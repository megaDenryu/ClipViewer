# 同時再生の設計

本文書は、同じ時刻に複数のクリップを並べて同時に再生する仕組み(issue #2)の、言葉の定義・利用者から見た振る舞いの案・層と依存の向き・データの形と保存形式・再生の仕組み・実装の段階を定める。続く issue #3(別々の動画のクリップを同時に再生する)を不可能にしない形を、本文書の各節で明示する。

クレートどうしの層の正本は `アーキテクチャ.md`、`clip_viewer` の内側の層の正本は `画面.md`、ライブラリの形式の正本は `ライブラリ.md` である。本文書はそれらに足す部分だけを扱う。実装と食い違ったときは、どちらが正しいかを決めて一致させる。本文書の内容を3つの正本へ写す段階は6節に書いた。

状態: 設計の案。7節のオーナーの決定(2026-10-03)を反映した。2節の振る舞いは、実装の各段階で `../使い方.md` へ写し、オーナーの承認を受ける(CLAUDE.md「利用者向けの説明書」)。

## 1. 定義

ここで定める言葉は、実装のときに `clip_domain` または `clip_viewer` の該当する型の文書コメントへ同じ定義文で写す(用語の正本は `clip_domain` の rustdoc である)。

- **同時再生**とは、1つのタイムラインの上に並べた複数のクリップを、同じ時刻に、それぞれの場所と大きさで映し、それぞれの音量で鳴らすことである。
- **重ね合わせ**とは、重ねる画面の縦横比と、使う動画の表と、タイムラインの行の並びの組のことである。重ね合わせは、同時再生で再生するものの全部であり、ライブラリへ1ファイルとして保存する単位である。今のスタック(1本の動画のクリップを上から順に並べたもの)とは別の型である。
- **重ねる画面**とは、重ね合わせの縦横比を持つ四角の画面であり、置いたクリップを好きな場所に好きな大きさで映す画面のことである。重ね合わせの作業場の出力は、重ねる画面をそのまま映す。
- **使う動画の表**とは、重ね合わせが使う動画のパスを、動画の番号(0から始まる整数)で指せる並びのことである。issue #2 の重ね合わせは表に動画を1本だけ持ち、issue #3 で2本以上を持つ。
- **動画の番号**とは、使う動画の表の中で、1本の動画を指す番号のことである。
- **置いたクリップ**とは、1本の動画の区間に、リピート回数・クロップ範囲・動画の番号・重ね合わせ上の始まりの時刻・映す矩形・置いたクリップの音の設定を付けたもののことである。置いたクリップはスタックのクリップ(`クリップ`)から受け継いだ値で作るが、別の型であり、トリガーと無限ループを持たない(7節の決定1)。
- **クリップから受け継いだ値**とは、置いたクリップが持つ値のうち、スタックのクリップから受け継ぐ名前・区間・リピート回数・クロップ範囲の組のことである。受け継ぐときに値を複製するため、元のクリップを後で直しても変わらない。無限ループは1回として受け継ぎ、トリガーは受け継がない。
- **タイムラインの行**とは、タイムラインの横1本の帯であり、時間の重ならない置いたクリップを始まりの時刻の順に並べたもののことである。手前の行の置いたクリップほど、重ねる画面の手前に映る。1つの行は、同時に高々1つの置いたクリップを映し、1つの音を鳴らす。
- **タイムラインの行の並び**とは、重ね合わせのタイムラインの行を奥から手前の順に並べたもののことである。行の数の上限と、行の中で時間が重ならないことを守る。
- **重ね合わせ上の時刻**とは、重ね合わせの始まりからの経過の秒のことである。今の `時刻<タイムライン上>`(スタックを並べた時間の中の秒)とは別の基準であり、`時刻<重ね合わせ上>`(別名 `重ね合わせ上の秒`)として型で分ける。
- **重ね合わせの再生位置**とは、重ね合わせの作業場が再生している重ね合わせ上の時刻のことであり、`clip_domain` の `重ね合わせの再生位置` が表す。スタックの作業場の `再生位置`(再生モードごとに意味の違う位置。シーケンス再生のタイムライン上の秒・単独クリップ再生の区間の中の経過・元動画再生の動画上の秒)とは別の型である。重ね合わせの作業場は再生モードを持たないため、1つの基準の時刻だけを持つ。
- **置いたクリップの占める長さ**とは、区間の長さにリピート回数を掛けた長さのことである。置いたクリップは、重ね合わせ上で始まりの時刻から占める長さの間だけ映る。
- **重ね合わせの長さ**とは、すべての置いたクリップの終わり(始まりの時刻に占める長さを足した時刻)のうち最も遅い時刻のことである。
- **映す矩形**とは、置いたクリップのクロップを掛けた絵を、重ねる画面のどこにどの大きさで映すかを表す矩形のことであり、重ねる画面の幅と高さに対する百分率(`百分率<重ねる画面に対する>`。クロップ範囲の `百分率<元の動画に対する>` とは基準の型で分ける)で左端・上端・幅・高さを持つ。
- **置いたクリップの音の設定**とは、置いたクリップごとの音量(0〜1。`clip_domain` の `音量` であり、`audio_pcm` が再公開してスタックの再生と同じ型を使う)と、消音しているかの組のことである。
- **同時に重ねられる行の数**とは、1つの重ね合わせが持てるタイムラインの行の数の上限のことであり、8とする(根拠は 5-4)。
- **作業場**とは、利用者が1つの目的で使う画面の全体であり、自分の状態・操作の適用・キーの表・画面の木・時計・音の送り方・閉じる前の確かめを持つもののことである。ClipViewer は、スタックの作業場と重ね合わせの作業場の2つを持ち、どちらか1つを前に出す。
- **スタックの作業場**とは、今の ClipViewer の画面の全体(編集・シアター・ライブラリの3つの構えと、その状態 `アプリの状態`)のことである。
- **重ね合わせの作業場**とは、重ね合わせを作り、直し、再生し、保存して開き直すための作業場のことである。
- **塊**とは、タイムラインの行の帯の上に、置いたクリップを始まりの時刻から占める長さの幅で描いた四角のことである。

## 2. 利用者から見た振る舞いの案

### 2-1. 2つの作業場

オーナーの決定(2026-10-03)により、1本の動画の今の操作感を変えず、同時再生は専用の UI に分ける。ClipViewer は、同時再生を今の画面の構え(編集・シアター・ライブラリ)の4つ目にせず、別の作業場にする。理由は3-2で述べる。

- 利用者は、スタックの作業場のヘッダーの「同時再生」を押して、重ね合わせの作業場へ移る。
- 利用者は、重ね合わせの作業場のヘッダーの「スタックへ戻る」を押して、スタックの作業場へ戻る。
- ClipViewer は、作業場を移るとき、後ろへ下げる作業場の再生を止める。後ろへ下げた作業場の状態(スタック・取り消しの履歴・再生の位置・選んでいるもの・重ね合わせ)は、そのまま残る。
- 利用者が重ね合わせの作業場からスタックの作業場へ戻ると、ClipViewer は移る前と同じ構え・同じスタック・同じ再生の位置を出す。利用者が再びスタックの作業場から重ね合わせの作業場へ移ると、ClipViewer は同じ重ね合わせを同じ再生の位置で出す。
- 重ね合わせの作業場の画面には、スタックの作業場の部品(サイドバーのカード・出力の帯・キーの一覧のダイアログ等)を出さない。スタックの作業場のキー(Space・Enter・I・O・Ctrl+Z 等)は、重ね合わせの作業場では効かない。

### 2-2. 重ね合わせを始める

- 重ね合わせを開いていないときに利用者が重ね合わせの作業場へ移ると、ClipViewer は「今のスタックから並べる」のボタンと、重ね合わせの一覧(2-7)を出す。重ね合わせを開いていない間は、再生のボタンを押せない。
- 開いている重ね合わせに置いたクリップが無い(長さが0秒の)ときも、映すものが無いため、再生のボタンを押せない。
- 「今のスタックから並べる」は、スタックの作業場で動画を開いていて、スタックに再生できるクリップ(有効で長さが0でないもの)が1つ以上あるときだけ押せる。
- 利用者が「今のスタックから並べる」を押すと、ClipViewer は次の規則で新しい重ね合わせを作る(4-3 の読み替え)。
  - 使う動画の表は、スタックの作業場で開いている動画1本である。
  - スタックの再生できるクリップを、スタックの順に1つずつ別の行へ、始まりの時刻0で置く。そのため、置いたクリップはすべて同時に始まる。
  - ClipViewer は、区間の終わりが動画の長さより後ろにあるクリップ(別の動画の JSON を読んだ後など)のように置く操作が拒むクリップを置かずに飛ばし、次のクリップへ進む。飛ばしたクリップの分の行は、後ろのクリップが使う。
  - 置いたクリップが8つになった後ろの再生できるクリップは、行が8つまでのため置かない。
  - ClipViewer は、置かなかったクリップがあれば、その名前と理由(行が8つまでのため・置けないため(置く操作が拒んだ理由))を知らせる。置けるクリップが1つも無いときは、重ね合わせを作らずに、置けなかったクリップの名前と理由を知らせる。知らせは3秒で消えるため、ClipViewer は並べた数と置かなかった数を知らせに出し、置かなかったクリップの名前と理由は出力の区画の上に次に並べるまで出し続ける。8つまでのため置かなかったクリップは、数と名前を1つの文(「並べられるのは8つまでのため置かなかったクリップ(<数>個): …」)にまとめる
  - 映す矩形は、置いたクリップの数で重ねる画面を縦横の格子に等分したます目である(列の数は個数の平方根を切り上げた数、行の数は個数を列の数で割って切り上げた数)。
    個数ごとの列と行の数は、1個が1列1行、2個が2列1行、3個と4個が2列2行、5個と6個が3列2行、7個と8個が3列3行である。ClipViewer は、スタックの順の置いたクリップを、左上のます目から、行ごとに左から右へ、上の行から下の行への順に入れる。最後の行のます目が余るときは、余ったます目に何も映さない。
    映す矩形は誤差を許さない(4-1)ため、各ます目の幅と高さは隣の境界との差で求め、最後の列と行の境界を100ちょうどにする。そのため、最後の列の幅と最後の行の高さは100から左端・上端を引いた値になり、右端と下端が丸めの誤差で100を超えない。
  - 重ねる画面の縦横比は、スタックの作業場の出力のアスペクト比が固定の比ならその比、「クロップ枠に合わせる」なら16:9である(2-5)。
- 重ね合わせを開いている間は、ヘッダーに「今のスタックから並べ直す」を置く。押すと、ClipViewer は開いている重ね合わせを捨てて、同じ規則で並べ直す。並べた後に利用者が置き方を手で直した(映す矩形を変えた・クリップを置いた・取り除いた・縦横比を変えた・置いたクリップの音量か消音を変えた)重ね合わせでは、ClipViewer は捨てる前に「この重ね合わせは置き方を直してある。今のスタックから並べ直すと、直した置き方は失われる」のダイアログを出し、「直した置き方を捨てて並べ直す」を押したときだけ並べ直す。「やめる」か、ダイアログの外を押すか Escape で閉じると、並べ直さない。手で直していない重ね合わせは確かめずに並べ直す(第13段階)。押せる条件は「今のスタックから並べる」と同じである。並べ直したときに置けるクリップが1つも無ければ、ClipViewer は開いている重ね合わせを変えずに残し、置かなかったクリップの報告だけを差し替える
- 置いたクリップは、スタックのクリップの写しである。利用者が後でスタックの作業場でクリップを直しても、置いたクリップは変わらない(7節の決定3)。

### 2-3. 画面の区画

| 区画 | 場所 | 中身 |
|---|---|---|
| ヘッダー | 上の端 | 「スタックへ戻る」、重ね合わせの名前とライブラリへの保存の様子と「ライブラリに保存」、「取り消す」「やり直す」、縦横比の選択 |
| 左のサイドバー | 左の端 | 置くクリップの一覧(スタックの作業場の今のスタックのクリップ)と、置いたクリップの一覧(手前の行から。押すと選ぶ)と、選んでいる置いたクリップの設定(名前・区間・繰り返しの回数・クロップのプレビュー・音量・消音・取り除く。第13段階ではクロップのプレビューのほかを作る) |
| 出力 | 真ん中 | 重ねる画面。今の時刻に映している置いたクリップと選んでいる置いたクリップの映す矩形に枠を重ねる。選んでいる枠は太い線と4隅のつまみで、選んでいない枠は細い線で描く |
| タイムライン | 下の端 | 再生の操作(再生と停止・全体ループ・音量のつまみ)と、行の操作(「行を足す」「選んだ空の行を消す」と選んでいる行の文)と、行ごとの帯に塊を並べたもの。行の並びの上の時間の軸が再生位置の帯を兼ねる(第15段階。第8段階から第14段階までは再生の操作の行に位置を見せるだけの棒を置いた) |

### 2-4. 置き方と大きさの変え方

- 置くクリップの一覧を押せるのは、スタックの作業場で今開いている動画のパスが、重ね合わせの使う動画の表の動画のパスと同じときだけである。2つのパスは、パス全体を `正規化した動画パス` の等しさで比べる。これは、スタックの作業場が登録済みのスタックと開く動画が同じかを決める今の比べ方(`アプリの状態::関係を保って開き直せるか`。`画面.md` 判断14)と同じである。違うとき、ClipViewer は一覧を押せなくし、一覧の上に「スタックの動画が、この重ね合わせの動画と違います」と出す。別々の動画のクリップを置けるようにするのは issue #3 である(5-5)。
- 利用者がサイドバーの置くクリップの一覧で「置く」を押すと、ClipViewer はそのクリップから受け継いだ値(区間・リピート回数(無限ループなら1回)・クロップ・名前)から置いたクリップを作り、今の再生の位置を始まりの時刻にして、始まりの時刻から占める長さの間が空いている最も手前の行へ置く。どの行も空いていなければ、ClipViewer は新しい行を最も手前に足す。行が8つあってどの行も空いていなければ、ClipViewer は置かずに「その時刻に空いている行が無い(行は8つまで)」と知らせる。区間の終わりが動画の長さより後ろにあるクリップ(別の動画の JSON を読んだ後など)は、置く操作が動画の長さで確かめて拒み(4-1)、ClipViewer は置かずに理由を知らせる。
- 新しく置いたクリップの映す矩形は、重ねる画面の全体である。行のテクスチャは行の中で置いたクリップが入れ替わっても作り直さないため、前の置いたクリップのコマが残る行へ置くと、そのままでは一瞬前の絵が出る。そこで ClipViewer は、置いたばかりの置いたクリップを、その行のテクスチャにそのコマが載るまで描かず、その間は描き直しを続ける(行のコマを待つ間は描き直しを続ける今の規則による)。そのコマが載ったとみなすのは、供給がその置いたクリップの求めで、その置いたクリップの区間の中のコマを実際に行のテクスチャへ載せたときだけである(`コマの載せ先::コマを載せる` が返す `コマを載せたか` の番号を `表示するコマの求め::区間の中のコマか` で確かめる。5-2 の7)。流し読みが出すコマの無いまま読み終えたか失敗したときは、コマを待っていなくても載ったとみなさない。置いたばかりの置いたクリップは、前の置いたクリップから続く行であっても、前の置いたクリップのコマを描き続けない(5-2 の7)。
- 利用者が「置く」で置いたとき、ClipViewer は新しく置いたクリップを選ぶ。スタックの作業場で動画を開いていないとき、ClipViewer は一覧を押せなくし、一覧の上に「スタックの作業場で動画を開いていないため、置けない」と出す。
- 利用者は、出力の重ねる画面の上で置いたクリップを押して選び、枠の内側をドラッグして映す矩形を動かし、四隅をドラッグして大きさを変える。大きさを変えるときは、ClipViewer はクロップの形の縦横比を保つ(利用者が Shift を押している間は保たない)。映す矩形は重ねる画面の外へ出ない。映す矩形の幅と高さは重ねる画面の5%より小さくならない(今のクロップ枠と同じ規則)。
  - クロップの形の縦横比とは、置いたクリップのクロップを掛けた絵を画素で測った幅÷高さのことであり、動画の元の寸法とクロップ範囲から求める。ClipViewer は、掴んだ隅の向かいの隅を動かさず、動かした隅が示す幅と高さのうちその比で大きい方へ合わせる。動画を開けず元の寸法が分からないときは、掴み始めの映す矩形の形を保つ。掴んだ隅の向かいの隅から、掴んだ隅の側の重ねる画面の端までの横と縦の空きが、その比のまま幅と高さを5%以上に保てないときは、縦横比を保たずに大きさを変える。保てるかは、比と向かいの隅の位置の両方で決まる(幅の下限は5%と5%×百分率の比の大きい方、上限は横の空きと縦の空き×百分率の比の小さい方であり、下限が上限を超えるとき)。絵の幅が0で比が有限で正でないときも保たない
  - ドラッグの間、ClipViewer は重ね合わせを変えずに動かしている枠と絵を仮の位置と大きさで描き、利用者が放したときに映す矩形を変える操作で1回だけ確定する。押しただけで動かさなかったときは確定しない。ドラッグの途中で掴んだ枠が重ねる画面から消えたとき(再生していて、その置いたクリップを映さなくなった等)は、確定せずにドラッグを終える
- 重ねる画面は、今の時刻に映している置いたクリップと、選んでいる置いたクリップの枠を出す。選んでいる置いたクリップは、今の時刻に映していなくても枠を出す。
- 枠を掴む順は、選んでいる枠の隅 → 選んでいる枠の内側 → ほかの枠の内側である。利用者が選んでいない置いたクリップどうしの重なっている場所を押すと、ClipViewer は手前の行の置いたクリップを選ぶ。全体の大きさで重なった奥の置いたクリップは画面の上では選べないため、利用者はサイドバーの置いたクリップの一覧(手前の行から並べる)を押して選ぶ。
- 利用者が重ねる画面の何も無い所(枠の外)を押すと、ClipViewer は選びを外す。

### 2-5. 重ねる画面の縦横比と出力の設定

- 重ねる画面の縦横比は、`clip_domain` の今の型 `アスペクト比設定` の固定の比(16:9・4:3・1:1・9:16)のどれかである。「クロップ枠に合わせる」(`クロップ連動`)は、置いたクリップごとにクロップが違うため重ね合わせでは意味を持たない。そのため、重ね合わせの作業場の縦横比の選択欄は「クロップ枠に合わせる」を出さず、重ね合わせの型とファイルの読み手は `クロップ連動` を型付きのエラーで拒む。
- 重ね合わせを開いている間、ヘッダーに「縦横比:」と選択欄(「16:9」「4:3」「1:1」「9:16」)を出す。名前はスタックの作業場の出力アスペクト比の選択欄と同じ文である。
- 利用者が縦横比を変えると、映す矩形は百分率のまま残るため、置いたクリップの形は新しい縦横比に合わせて伸びる。
- 重ね合わせの作業場の出力は、出力の区画の中に縦横比を保って収める(スタックの作業場の表示サイズの「大きめ」と同じ収め方)。スタックの作業場の表示サイズの設定は使わない。
- 左右反転(スタックの作業場の出力の帯の設定)は、重ね合わせの作業場では効かせない。映す矩形を動かす画面が反転していると、ドラッグの向きと置いた位置が逆になるためである(スタックの作業場のプレビューを反転しないのと同じ理由。`画面.md` 判断15)。

### 2-6. タイムラインと音量

- タイムラインは、上から行を並べ、行ごとに横の帯を持つ。帯の左端から右端までが、0秒から重ね合わせの長さ(10秒より短いときは10秒)までである。塊の中には周回の区切りが細い線で描かれる。
- 利用者が塊をドラッグすると、その置いたクリップの始まりの時刻が変わる。ドラッグしている塊は、同じ行のほかの塊と重ならず、ぶつかった所で止まる。利用者が塊を上下の行へ動かすと、その置いたクリップの行が変わり、重なりの順が変わる。
- ぶつかった所で止める規則は、`clip_domain` の `タイムラインの行の並び::ずらした行き先を求める` が持つ。行き先は、掴み始めの行と始まりの時刻に、時刻をずらす量と行の差を当てて毎回求め直す(ドラッグの間の途中の位置を覚えない)。行の差は0番から最も手前の行までへ収める。掴み始めの始まりが先の行で空いている範囲(前後の置いたクリップの間で、その長さが入る始まりの範囲)にあれば、望む始まりをその範囲へ収める。そのため、塊は動かした向きの最初の置いたクリップの手前で止まり、それを飛び越えない。また0秒より前へ行かない。掴み始めの始まりが先の行で塞がっていれば(別の行へ動かしたとき)、その行の空いている始まりのうち望む始まりに最も近いものを選ぶ。最後の置いたクリップの後ろの空きは限りが無いため、必ず見つかる
- 塊を行の並びの上の外(最も手前の行より上)へドラッグしても、新しい行を作らない(第15段階で決めた)。理由は次の3つである。(1)行の差は ClipViewer が行の数へ収める(issue #21 の決定)。(2)ドラッグの間は重ね合わせを変えない決まり(下の項目)があり、ドラッグの途中で行を足すと、仮の行を型に持ち込むことになる。(3)行を足す操作は、タイムラインの行の操作の「行を足す」で足りる(使い方.md 15.8節)。利用者は「行を足す」で空の行を最も手前に足してから、塊をその行へ動かす
- ClipViewer は、塊のドラッグの間、重ね合わせを変えずに塊を仮の位置で描き、利用者が放したときに1回だけ確定する。新しい始まりの時刻は、掴み始めの始まりの時刻に、部品が知らせる時間の差を足して求める(3-4 の項3)。利用者が動かさずに放したとき、ClipViewer は確定せず、置き方を手で直したとして扱わない。放したことを判定できずにドラッグが終わったとき(部品は塊の操作を何も知らせない)は、ClipViewer は塊のドラッグを安全網へ入れ、確定せずに捨てる。この安全網は、スタックの作業場の `command/band_commit.rs` の安全網(区間の帯とクロップ枠のためのもの。主ボタンを押していないのにドラッグが残っていたら捨てる)と同じ形のものであり、重ね合わせの作業場は `crate::command` を使えない(3-2)ため、`overlay/` の中に置く。
- 利用者が行の上の塊の無い所(置いたクリップの無い行を含む)を押すと、ClipViewer はその行を選ぶ。行の選びと置いたクリップの選びは1つの型(`選んでいるもの`: 無し / 置いたクリップ / 行)で持ち、同時には選ばない。利用者は、空の行を選んで「選んだ空の行を消す」を押して消す(`重ね合わせ::空の行を消す`。置いたクリップを持つ行は拒む)。「行を足す」は空の行を最も手前に足して選ぶ(`重ね合わせ::空の行を手前に足す`。行が8つあるときは拒む)。塊を選ぶことは、重ねる画面の枠とサイドバーの一覧と同じ選びである
- 再生位置の帯は、行の並びの上の時間の軸である(第15段階で、重ね合わせの作業場の `進捗バー` をやめた)。利用者は、時間の軸を押すかドラッグして、再生の位置を動かす。時間の軸と、行の帯の上の位置の線は同じ時刻を指す。重ね合わせの長さより後ろの時刻は長さで止める。位置を動かしても、再生しているかは変えない。時間の軸を押したままドラッグしている間は、スタックの作業場の再生位置の帯と同じく(`画面.md` 判断5・判断10)、位置だけを動かし、映像と音の流し読みを開き直さず(`流し読みの開き直し::控える`)、行ごとの再生の指示を止めている指示にして黙らせる。時計は進め続ける。放したら開き直し、鳴らし直す。位置の線を掴んでいることは、掴んでいるもの(`位置の線`)が持ち、放したを受け取れなかったときは安全網が捨てる。位置を動かしたら、全部の行の続く先を止まるにし、全部の行の位置を飛ばした回数を進める(5-2 の7)。末尾(重ね合わせの長さ)に達したとき、全体ループに印が付いていれば ClipViewer は0秒へ戻り、印が無ければ止まる。止まったとき、置いたクリップを持つ行は、その行の最後の置いたクリップの区間の終わりのコマを映す(スタックの作業場が末尾で最後のクリップの最後のコマを映すのと同じ)。全体の末尾より前に終わる行は、終わった後は何も映さず、止まった時点でその行の最後のコマが戻る。そのため、止まる前に空いていた行にもコマが出る。
- サイドバーは、選んでいる置いたクリップの音量のつまみ(0〜1。最初の値は1)と「消音」のチェックボックスを出す。音量は置いたクリップごとに別々の値であり、利用者は片方の置いたクリップを消音にすることも、両方を鳴らすこともできる。
- タイムラインの音量のつまみは、スタックの作業場と同じ見る側の設定の音量である。鳴らす大きさは、置いたクリップの音の設定の音量(置いたクリップの消音なら0)に、全体の鳴らす音量(音量のつまみの値。全体を消音していれば0)を掛けたものである。重ね合わせの作業場は速度のつまみを持たず、等倍で再生する。
- 消音は両方の作業場で共通にする(オーナーの決定 2026-10-03)。重ね合わせの作業場の再生の操作の行に、音量のつまみの隣に「全体を消音」のチェックボックスを置き、押すとスタックの作業場の今の操作(`再生の操作::消音を切り替える`)を当てる。スタックの作業場で M キーで消したら、重ね合わせの作業場の音も鳴らない。行の音量に掛けるのは、スタックの作業場の鳴らす音量(`音量の設定::鳴らす音量`。消音しているなら無音)であり、配線が今のスタックの値の `全体の音量`(つまみの値・消音しているか・鳴らす音量)として渡す。消音の規則はスタックの作業場の1か所に置いたままにする。重ね合わせの作業場でつまみを動かすと、スタックの作業場の今の操作(`再生の操作::音量を選ぶ`)を当てるため、消音もやめる(説明書 6.6節の規則)。「全体を消音」は置いたクリップごとの「消音」と別のものであり、画面の文字で分ける。
- 置いたクリップの音量のつまみと「消音」は、左のサイドバーの選んでいる置いたクリップの設定の中に、見出し「このクリップの音量:」の下に出す。置いたクリップを選んでいないときは出さない(第11段階では全部の置いたクリップを並べて出し、第13段階で選べるようになったため、選んでいる置いたクリップの設定へ移した)。置いたクリップの音量か消音を変えると、置き方を手で直したとして扱い、「今のスタックから並べ直す」の前に確かめる(2-2)。並べ直すと音の設定も失われるためである。音量のつまみは、下の再生の操作の行の全体ループの後ろに置く。
- 置いたクリップの音の設定を変える操作は `clip_domain` の `重ね合わせ::置いたクリップの音を変える` であり、変更(`置いたクリップの音の変更`: 音量を選ぶ / 消音を設定する)を当て、識別子が無いときだけ拒む(音量の範囲は `音量` の型が守る)。音量を選んでも消音しているかは変えず、消音を戻すと前の音量で鳴る。画面はつまみの値を境界で `音量` へ包んでから応答に載せる。第17段階で保存するまでは、並べ直すと音の設定は最初の値に戻る。

### 2-7. 保存と開き直し

- 利用者は、重ね合わせをライブラリへ名前を付けて登録する。ClipViewer は、登録した重ね合わせを、スタックと同じく編集のたびに自動で保存する(`ライブラリ.md` 判断5と同じ規則)。
- 重ね合わせの一覧は、重ね合わせの作業場の中に置く。スタックの作業場のライブラリの構えの一覧には、重ね合わせを出さない。一覧の操作は、開く・名前を変える・複製する・削除する・動画の場所を指定し直すである。
- 利用者が未登録の重ね合わせを捨てる操作(一覧から別の重ね合わせを開く・アプリを閉じる)をする前に、ClipViewer はスタックと同じく確かめるダイアログを出す(`画面.md` 判断14 と同じ文と選択肢)。
- ライブラリが読み取り専用のアプリ(`ライブラリ.md` 判断9)は、重ね合わせも読み取り専用で開く。重ね合わせの作業場のヘッダーは、重ね合わせのライブラリへ書けないとき、「重ね合わせのライブラリ: 読み取り専用(<理由>)」か、アプリのデータの置き場所が無ければ「重ね合わせのライブラリ: 使えない(アプリのデータの置き場所が無い)」を出す(第16段階)。
- 一覧のサムネイルは、最も早く始まる置いたクリップ(同じ時刻なら奥の行のもの)の開始のコマにそのクロップを掛けたものとする。今の撮り方(`サムネイルの撮り方`)をそのまま使える。

### 2-8. 重ね合わせの作業場でのそのほかの振る舞い

- 利用者が重ね合わせの作業場でウインドウへファイルを落とすと、ClipViewer はファイルを開かず、重ね合わせの作業場の知らせに「動画と JSON は、スタックへ戻ってから落とす」と出す(スタックの作業場の通知は重ね合わせが前の間は見えないため、重ね合わせの作業場が自分の知らせを持つ)。重ね合わせの作業場の操作がスタックの作業場の状態を変えないためである。
- 以前の版の ClipViewer から動画を開く頼み(`画面.md` 判断13)が届いたとき、ClipViewer はスタックの作業場を前に出してから、今と同じ経路で開く。
- 利用者がアプリを閉じようとしたとき、スタックの作業場の確かめがダイアログを出したら、ClipViewer はスタックの作業場を前に出してそのダイアログを見せる。スタックの作業場が書けると分かった後に重ね合わせの確かめがダイアログを出したら、ClipViewer は重ね合わせの作業場を前に出して見せる(3-2)。
- 利用者が作業場を移る前に頼んだスタックの保存が失敗したとき、ClipViewer はスタックの作業場の知らせに加えて、重ね合わせの作業場の知らせにも「スタックをライブラリへ保存できない: <理由>」を出す。スタックの作業場の知らせは、重ね合わせが前の間は見えないためである。
- 重ね合わせを開くときに FFmpeg が見つからない(スタックの作業場の動画の開き手が読み手を持たない)と、ClipViewer は重ね合わせを開いたうえで映像を映さず、重ね合わせの作業場の知らせに「FFmpeg が見つからないため重ね合わせの動画を開けない。「スタックへ戻る」を押し、画面の上部で FFmpeg の置き場所を設定する」と出す。スタックの作業場で動画を開いているときは読み手があるため、「今のスタックから並べる」を押せる間はこの知らせは出ない
- 重ね合わせの作業場でも、F11 で全画面を切り替えられる。全画面の様子は2つの作業場で共有し、作業場を移っても全画面のまま・普通のウインドウのままである。
- 重ね合わせの作業場のキーは、再生と停止(Space)・全画面(F11)・取り消し(Ctrl+Z)・やり直し(Ctrl+Y)だけであり、割り当ては変えられない(F11 は第8段階、ほかは第18段階。スタックの作業場のキーの割り当てと settings.json の keyBindings は使わない)。

## 3. 層と依存の向き

### 3-1. クレートの層

新しいクレートは作らない。今のクレートの層(`アーキテクチャ.md` 2節)と依存の向きを変えず、各クレートの中へ次を足す。

| 層(クレート) | 足すもの | 知ってよいもの(今と同じ) |
|---|---|---|
| `clip_domain` | `overlay/` モジュール: 重ね合わせ・使う動画の表・動画の番号・置いたクリップ・クリップから受け継いだ値・タイムラインの行・タイムラインの行の並び・映す矩形・置いたクリップの音の設定・重ね合わせ上の時刻の基準・重ねる画面に対する百分率の基準。重ね合わせの操作(置く・動かす・映す矩形を変える・取り除く)と不変条件、その時刻に映すものを求める処理、重ね合わせの時計の規則、スタックからの読み替え。`library/` へ: ライブラリの重ね合わせ・重ね合わせの識別子・重ね合わせのファイルの第1版の型と最新への変換 | 何も知らない |
| `video_source` | issue #2 では足さない。1本の動画の倉庫が複数の区間を溜め、流し読みは1本の動画に何本でも開けるため、今の口で足りる | `clip_domain` |
| `audio_pcm` | 左右の標本を −1〜1 へ収める演算(`ステレオの標本` のメソッド)。足し合わせる演算 `ステレオの標本::足す` は今あるものを使う | `clip_domain` |
| `audio_output` | 行ごとの音の再生器を固定の数だけ持ち音を混ぜる新しい型(`行の音を混ぜる係`)と、それを2本目の装置の流れとして開く口(`行を混ぜる音声出力`。5-3) | `clip_domain`・`audio_pcm`・cpal |
| `clip_library` | `overlays` フォルダを読み書きし走査する新しい型(`裏で動く重ね合わせのライブラリ`)と、`overlays` フォルダの錠。今の `裏で動くライブラリ` と一覧の項目の型は変えない | `clip_domain`・thiserror・std::fs |
| `thumbnail_cache` | 足さない | `clip_domain`・thiserror・std::fs |
| `clip_viewer` | 作業場を移すこと(3-2)と、重ね合わせの作業場の状態・操作・供給・画面 | すべて |

`clip_domain` の `overlay/` は egui も FFmpeg も知らないため、重ね合わせの規則から画面やデコードを呼ぶコードはコンパイルできない。`clip_domain` の `overlay/` は既存の `クリップスタック` を知ってよいが、その逆は無い。`クリップスタック` を知る理由は、スタックからの読み替え(4-3)とクリップの値の写しを作る口だけであり、`クリップスタック` の型と規則は変えない。

### 3-2. 作業場を分ける形

**同時再生を `画面の構え` の4つ目の選択肢にしない理由。** スタックの作業場のコードには、`画面の構え` による分岐と比較が約20か所ある(例: `view/mod.rs`、`command/output_ops.rs`、`view/output/` の各所、`state/library_thumbnail.rs`、`view/invisible.rs`)。そのうち `view/keys/rule.rs` の `構え != 画面の構え::ライブラリ` のような比較は、選択肢を足してもコンパイラが知らせず、4つ目の構えでも Space 等がスタックの作業場の再生を動かす。描き直しの予約・構えを移すときの規則・起動の頼み・閉じる前の確かめ・アプリを落とすときの保存・ライブラリの一覧・音の再生の共有も、同時再生のときに通る経路になる。これらすべてを確かめて直す形は、オーナーの決定「今の UI にバグを持ち込まない」に反する。

**形。** 配線(`app/`)の `クリップビューアー` が、前に出ている作業場を判別共用体で持ち替える。

```
クリップビューアー
  スタックの作業場       : アプリの状態 と 操作の適用係(今のまま。常に持つ)
  前に出ている作業場     : どちらが前 と 重ね合わせの側の作り方(画面描画の共有状態・2本目の流れを開く手立て)
    どちらが前           : スタックが前(控えた重ね合わせ: Option<重ね合わせの側>)
                        | 重ね合わせが前(重ね合わせの側)
    重ね合わせの側        : 重ね合わせの作業場 と 重ね合わせの音の送り手(2本目の流れ)
  共有するもの           : 音の送り手・起動の受け口・見る側の設定の保存係(今のまま)
                          と、overlays の錠・重ね合わせのライブラリ(新しく足す)
```

- 重ね合わせの作業場は、状態(`overlay/state/`)・操作の適用(`overlay/command/`)・キーの表・画面の木(`overlay/view/`)・時計・映像と音の供給(`overlay/feed/`)・閉じる前の確かめを、`アプリの状態` とは別の型として持つ。重ね合わせの作業場の型は `アプリの状態` を持たず借りもしない。共有するもののうち書き換えるもの(音量と全画面の頼み)は、重ね合わせの作業場が応答として発し、`クリップビューアー` が今の `アプリの状態` のメソッドを呼んで当てる
- `クリップビューアー::画面` は、前に出ている作業場の画面の木だけを組む。スタックの作業場の画面の木を組まないフレームでは、`画面の構え` の分岐もスタックのキーの表も通らない
- スタックの作業場の1フレームの手順(時計・供給・音の指示・ライブラリの書き込み・サムネイル・見る側の設定の保存)は、重ね合わせが前のときも今のまま毎フレーム呼ぶ。再生は止めてあるため時計は進まず、未保存の並びの保存と見る側の設定の保存は今どおり進む
- **設計の不変条件**: `アプリの状態` の型と、スタックの作業場が今通る経路の振る舞い(`画面の構え` の全分岐・キーの表・画面の木・閉じる前の確かめ・ライブラリの構えの一覧・音の再生の共有)を変えない。スタックの作業場と配線のコードに触れる所は、次の表のものに限る。どの行も、スタックの作業場だけを使っているときの振る舞いを変えない形にし、守る試験で確かめる

**依存の向きの検査。** `overlay/` のモジュールがスタックの作業場の `state/`・`command/`・`view/` を知らないという決まり(3-3)は、1つのクレートの中なので Cargo では強制できない。第4段階で、`clip_viewer/src/overlay/` の下のファイルに `use crate::state`・`use crate::command`・`use crate::view`(と `crate::state::` 等の完全な名前)が無いことを確かめる xtask のコマンド(`cargo xtask check-overlay-deps`)を足し、`cargo xtask verify` の工程に入れる。検査は、調べたファイルの数を出す。

**回帰試験。** 次の3つの試験を作り、作った後のすべての段階の完了条件に、通ることを入れる。

- (a) 作業場を行き来しても、スタック・取り消しの履歴・再生の位置・選んでいるクリップ・構え・キーの割り当て・見る側の設定が変わらない(再生しているかは止まるだけである)。第4段階で作る
- (b) 重ね合わせの作業場が前のとき、スタックの作業場のキー(Space・Enter・←→・Ctrl+Z 等)を押しても、`アプリの状態` が変わらない。第4段階で作る
- (c) スタックの作業場の音の標本が変わらない。`音を埋める係::装置の並びを埋める` は中で `Instant::now()` を読む(`device/callback.rs`)ため、通しで見本を固定すると値が決まらない。そこで、2つを別々に固定する。1つ目は、時刻を引数で受け取る `再生の共有::埋める(今, 出力)`(`device/shared.rs`)へ、決まった溜めた音と決まった指示の列と決まった時刻の列を渡して作った標本の並びを見本として固定する試験である。2つ目は、左右の標本を装置のチャンネルへ写す関数(`チャンネルへ写す`)について、1チャンネル・2チャンネル・3チャンネル以上と f32・i16 の組で、写した値を見本として固定する試験である。第5段階で作り(今はこの2つを通す試験が無い)、第10段階で装置を開く関数の形を変えた後も、同じ見本と1標本も違わないことを確かめる。見本を書き換えてよいのは、オーナーが音の変更を決めたときだけであり、書き出しは一時的な試験で行い、変わった標本の番号と値を PR に示す

**重ね合わせの一覧を専用にする理由。** 今のライブラリの構えの一覧(`clip_library` の一覧の項目と、それを使う `clip_viewer` の9つのモジュール)に重ね合わせを混ぜると、一覧の項目の型が判別共用体に変わり、9つのモジュールすべてに触れる。重ね合わせの作業場に専用の一覧を置けば、今の一覧に触れずに済む。足りない点は、スタックと重ね合わせを1つの一覧で見渡せないことである。これは2つの作業場を移れば見られるため、issue #2 では受け入れる。

### 3-4. SengenEgui に足す口

今の SengenEgui の重ねる容器(`重ね型`)は、子を下地の9つの寄せ先(左上・中央など)へ寄せて置くか、下地を覆って中央に置く(`覆って中央に置く`)だけであり、好きな場所と大きさへは置けない。範囲枠付き画像は1つの枠しか持たない。区間の帯は1本の帯に1つの区間しか持たない。CLAUDE.md の規約(利用側に素の egui の呼び出しを書いて回避しない)に従い、次の3つを SengenEgui へ足してから使う。

1. **割合の矩形へ置く容器**: 子を、容器の矩形に対する割合で表した矩形へ、書いた順に重ねて置く。重ねる画面の表示に使う
2. **複数の範囲枠を置く部品**: 下地の上に複数の枠を置き、押した枠を選び、内側のドラッグで動かし、四隅のドラッグで大きさを変える。縦横比を保つかの指定を持つ。発する値は割合の差であり、`clip_domain` の百分率への変換は、重ね合わせの画面の境界1箇所で行う(今の `view/conversion.rs` と同じ形。第13段階で `overlay/view/frame_conversion.rs` に置いた)。部品は枠を利用側の鍵(置いたクリップの識別子)で覚え、掴んだ枠が並びから消えたら消えたことを表す操作を発し、何も無い所を押したことを知らせる口を持つ(第12段階。第13段階で、消えたらドラッグを閉じ、何も無い所で選びを外す)
3. **時間の行の並び**(第14段階。SengenEgui の rev c684409): 複数の行に、それぞれ複数の塊(始まりと長さ)を描く。行は置いた順に下から上へ積む(最初に置いた行がいちばん下で、行の番号は0)。部品は塊を利用側の鍵(置いたクリップの識別子)で覚えるため、ドラッグの途中で塊を別の行へ置き直しても、掴んだ塊へ操作が届く。部品が掴む順は、選んでいる塊、それ以外の塊の順である。
   - 塊のドラッグについて、部品は塊の新しい始まりの値を知らせない。部品が知らせるのは、掴み始めてからの累積の時間の差と行の差である。新しい始まりは、利用側が「掴み始めの始まり + 時間の差」で求める。部品は、時間の差を、掴み始めた回の全体の範囲の目盛りで求める。部品は、行の差を、縦の移動量を行の高さで割って求めるので、行の差は行の数に左右されない。部品は行の差を行の数へ収めない
   - 部品は、掴んだ鍵の塊が置かれなくなったら、掴んだ塊が無くなったことを知らせてドラッグを終える。部品は、放したことを判定できずにドラッグが終わったときは、塊の操作を何も知らせない。部品は、動かさずに放したときは、差0の「放した」を知らせる
   - 部品は、何も無い所を押したことと、行の何も無い所を押したこと(押した行の番号を渡す)を知らせる
   - 部品は、時間の軸から行の並びの下端まで位置の線を描く。利用者は、位置の線を、時間の軸を押すかドラッグして動かす。部品は、押した位置の値を全体の範囲へ収めて知らせる
   - ぶつかった所で止める規則と、行の数へ収める規則は、利用側(ClipViewer)が持つ(4-1)
   - 部品は、`時間の行型::選んでいる行にする` を付けた行の背景をテーマの選択の色で描き分ける。どの行を選ぶかは利用側が決める(第15段階の検収で足した。SengenEgui の rev ae59b43)

## 4. データの形と保存形式

### 4-1. 型の形

```
重ね合わせ
  重ねる画面の縦横比     : アスペクト比設定(固定の比だけ。クロップ連動は拒む)
  使う動画の表          : [正規化した動画パス]   (issue #2 では1本。型は複数を許す)
  タイムラインの行の並び : タイムラインの行の並び  (0〜8行のタイムラインの行。先頭が奥、末尾が手前。画面のタイムラインは末尾の行をいちばん上に描く)

タイムラインの行
  置いたクリップの並び   : [置いたクリップ]      (始まりの時刻の順。時間が重ならない)

置いたクリップ
  識別子               : 置いたクリップの識別子(重ね合わせの中で重ならない)
  受け継いだ値           : クリップから受け継いだ値(名前・区間・リピート回数(1〜100。無限を持たない)・クロップ範囲)
  動画の番号            : 動画の番号(使う動画の表にある番号)
  始まりの時刻           : 時刻<重ね合わせ上>
  映す矩形              : 映す矩形(百分率<重ねる画面に対する>)
  音の設定              : 置いたクリップの音の設定(音量と消音しているか)
```

重ね合わせの不変条件は次のとおりである。重ね合わせの操作はどれも、満たさない値を返さずに型付きのエラー(`重ね合わせの操作エラー`)を返す。縦横比と映す矩形の条件はそれぞれの型が作るときに守り、行の数と行の中の時間の条件は `タイムラインの行の並び` が守り、動画の番号と識別子の条件は `重ね合わせ` が置く前に確かめる。

- 重ねる画面の縦横比は `クロップ連動` でない
- 行の数は同時に重ねられる行の数(8)以下である
- 同じ行の置いたクリップは、始まりの時刻の順に並び、占める時間が重ならない。前の終わりと次の始まりの食い込みが丸めの許容誤差(`時間の長さ::丸めの許容誤差`。1マイクロ秒)以下なら、重ならずに接しているとみなす。終わりの時刻は始まりの時刻と占める長さの足し算で求めるため、丸めで接する端が僅かに食い込むことがあるためである
- 置いたクリップの識別子は、重ね合わせの中で重ならない
- 置いたクリップの動画の番号は、使う動画の表にある
- 映す矩形は重ねる画面の内側にあり(左端+幅と上端+高さが100以下。誤差を許さない)、幅と高さは5%以上である

置く操作は、上の不変条件に加えて、置く動画の長さ(呼び手が開いた動画の情報から渡す)を受け取り、区間の終わりが動画の長さより後ろなら型付きのエラーで拒む。動画の長さは重ね合わせに保存しないため、これは保存した値の不変条件ではなく置く操作の確かめである。ファイルから読んだ置いたクリップの区間は、スタックと同じく読むときには動画の長さで確かめない。置く操作は、区間の長さが0のクリップ(占める長さが0で、重ね合わせ上で映らないもの)も型付きのエラーで拒む。

ファイルから読んだ全部の値から重ね合わせを作る手段は、規約のビルダーの形にする(第16段階)。`重ね合わせの部品一式`(縦横比・使う動画の表・行ごとの `置いたクリップの部品一式` の並び)が、不変条件を確かめる前の値を持ち、`重ね合わせの部品一式::重ね合わせへ組み立てる` だけが重ね合わせへ変える。組み立ては、行の数が同時に重ねられる行の数を超えるときに `行の数が上限を超える` で、置いたクリップの識別子が重なるとき・動画の番号が表に無いとき・区間の長さが0のとき・同じ行のほかの置いたクリップと時間が重なるときに、置けない置いたクリップの行と行の中の位置と理由(`重ね合わせの操作エラー`)を持つ `置いたクリップを置けない` で拒む(`重ね合わせを組み立てられない理由`)。行の中の並びは始まりの時刻の順に並べ直す。区間の終わりと動画の長さは確かめない(下の置く操作の段落)。逆向きの `重ね合わせ::部品一式を複製する` は、奥から手前の順の行ごとに、行の中は始まりの時刻の順に写しを返す。どちらの向きも `..` を使わずに分解・組み立てるため、置いたクリップに項目を足すと保存の形式との変換がコンパイルエラーになる。

重ね合わせの操作は、置く操作(`クリップから受け継いだ値を置く`)と取り除く操作(`置いたクリップを取り除く`)のほかに、最も手前に新しい行を足してそこへ置く操作(`手前に新しい行を足して置く`。ほかの行の空きを問わない。置く前の確かめは置く操作と同じであり、行が8つあるときは拒む。スタックからの読み替え(4-3)が使う)と、置いたクリップを先の行の始まりの時刻へ動かす操作(`置いたクリップを動かす`。同じ行の中で時刻だけを変えるときも同じ操作で、先の行に今の行を渡す)と、映す矩形を変える操作(`映す矩形を変える`)を持つ。動かす先の行で時間が重なるときは型付きのエラーで拒む。ぶつかった所で止める振る舞い(2-6)は、拒まれない行き先を求める口(`タイムラインの行の並び::ずらした行き先を求める`。時刻をずらす量 `時刻をずらす量` と行の差 `行の差` を受け取り、行き先 `置いたクリップの行き先` を返す。並びは変えない)が作り、画面の側はその行き先で `置いたクリップを動かす` を呼ぶ。取り除く操作は、置いたクリップが無くなった行も残す。ほかの行の番号と重なりの順を変えないためである。そのため、空の行を消す操作(`空の行を消す`。置いたクリップを持つ行は `行が空でない` で拒む。後ろの行の番号は1つずつ小さくなる)と、空の新しい行を最も手前に足す操作(`空の行を手前に足す`。行が8つあれば拒む)を持つ(第15段階)。

使う動画の表は、どの置いたクリップも使っていない動画を持ってよい。issue #3 で、動画を表に足してから置く順の操作を許すためである。

置いたクリップの動画の番号を置いたクリップごとに持つのは、issue #3 を不可能にしないためである。issue #2 の画面は表の動画が1本の重ね合わせだけを作るが、型とファイルの形は最初から複数の動画を表せる。そのため issue #3 は形式の版を上げない(issue #3 で変える範囲は 5-5)。

### 4-2. 保存形式(重ね合わせのファイルの第1版)

- 置き場所は `%APPDATA%\ClipViewer\library\overlays\<重ね合わせの識別子>.json` である。ライブラリのフォルダの直下に新しいデータを置かないという互換の約束(`ライブラリ.md` 8節)に従い、サブフォルダに置く。今の版のアプリは走査でサブフォルダを読まないため、重ね合わせのファイルを読めない行として出さず、触れもしない
- 重ね合わせの識別子は `overlay-<ミリ秒>-<0〜9999の乱数>` の形にする。スタックの識別子(`stack-…`)と別の型(`重ね合わせの識別子`)であり、取り違えても型が通らない
- 書き込み(一時ファイルへ書いてから置き換える)・走査・読めないファイルの扱いは、スタックのファイルと同じ規則(`ライブラリ.md` 判断2・3・6)を `overlays` フォルダに当てる。錠は `overlays\ClipViewer.lock` である(3-2)
- 形式は版を持つ新しい形式(`format` は `ClipViewer.overlay`、`version` は1)にする。第1版は欠けた項目も知らない項目も許さない(`deny_unknown_fields`)。理由はスタックの第1版と同じである(`ライブラリ.md` 判断4)
- 第1版の形は `clip_domain` の `library/overlay_v1.rs` がそのまま写す。読み込みでは、先に `format` と `version` だけを読み、版に合う型で読んでから最新の `ライブラリの重ね合わせ` へ変換する。版ごとの型と最新の型の変換は、両方向とも最新の型を `..` を使わずに分解・組み立てる
- 縦横比の表記は settings.json の `aspectRatio` と同じ(`16:9`・`4:3`・`1:1`・`9:16`)にし、`crop` を拒む
- 読み込みは、置いたクリップの値をそれぞれの型にしてから(成立しない値は、行の番号(rows の順番は組み立てた重ね合わせの行の番号と同じ)と items の中の位置(`部品の並びの中の位置`。組み立てると行の中は始まりの時刻の順へ並べ直すため、行の中の順番とは別のもの)を添えた `置いたクリップが不正`)、重ね合わせの部品一式を重ね合わせへ組み立てて重ね合わせの不変条件を全部確かめる(破れば `組み立てられない`。4-1)。クロップ範囲と映す矩形の各値は0〜100へ、音量は0〜1へ収めてから型にする(スタックのファイル第1版のクロップと同じ扱い。このアプリが書いた値は範囲の中にあるため変わらない)。映す矩形が重ねる画面の外へ出るか小さすぎれば拒む
- 名前は `重ね合わせの名前`(前後の空白を除いて空でない。スタックの名前とは別の型)、日時はスタックと同じ `ライブラリの日時` で持つ。見本は `clip_domain/tests/fixtures/overlay_v1.json` であり、読んだ結果を手で組んだ期待値と比べる試験と、書き出しが見本と1バイトも違わないことを比べる試験を置く(`ライブラリ.md` 7節)

### 4-3. 既存の形式の読み替え

- **スタックのファイルの版は上げない。** 複数の動画を持つのは重ね合わせだけであり、スタックは1本の動画のままである(7節の決定2)。今の版のアプリと新しい版のアプリは、同じスタックのファイルを今までどおり読み書きできる
- **スタックから重ね合わせへの読み替え**は、`clip_domain` の `重ね合わせ::スタックから並べる` が行う。この口は、スタック・スタックの作業場で開いている動画のパス・その動画の長さ・スタックの作業場の出力のアスペクト比・置いたクリップの識別子の発行元を受け取る。動画のパスは使う動画の表に入れ、動画の長さは置く操作と同じく区間の終わりを確かめるのに使う。規則は2-2の「今のスタックから並べる」のとおりである(再生できるクリップをスタックの順に、`手前に新しい行を足して置く` で1つずつ新しい行へ始まりの時刻0で置き、置いた数が8つになったら止め、映す矩形を格子のます目にする。回数指定はその回数、無限ループは1回にし、トリガーは写さない)。読み替えは写しを作るだけであり、元のスタックとそのファイルを変えない
- 読み替えの結果(`スタックから並べた結果`)は、重ね合わせと、再生できるのに置かなかったクリップの一覧(`置かなかったクリップ` の並び。スタックの順)を持つ。一覧の各項目は、クリップの名前と、置かなかった理由(`置かなかった理由`)を持つ。理由は次の2つの選択肢である。`行の数の上限を超える` は、置いたクリップが8つになった後ろのクリップである。`置く操作が拒んだ` は、置く操作が拒んだクリップであり、拒んだ理由(`重ね合わせの操作エラー`。区間の終わりが動画の長さより後ろにある等)を持つ。全部を置いたときは一覧が空である。画面は一覧で利用者に知らせ、置かなかったクリップが黙って抜けることはない
- 読み替えが重ね合わせを作らずに型付きのエラー(`スタックから並べるエラー`)を返すのは、置けるクリップが1つも無いときだけであり、エラーは次の2つの選択肢である。`再生できるクリップが無い` は、スタックに再生できるクリップが1つも無いときである(画面はこのときボタンを押せなくするが、読み替えの側でも拒む)。`置けるクリップが無い` は、再生できるクリップはあるが置く操作がどれも拒んだときであり、置かなかったクリップの一覧を持つ
- 出力のアスペクト比から重ねる画面の縦横比を決める規則(2-2)は、`重ねる画面の縦横比::スタックの出力のアスペクト比から決める` が持ち、読み替えはスタックの作業場の出力のアスペクト比をそのまま受け取る
- v4.0 の JSON は今までどおりスタックとして読む。重ね合わせは v4.0 の JSON を直接は読まない
- 重ね合わせの形式の版を上げるときは、`ライブラリ.md` 7節の手順に従う

### 4-4. 互換の約束に足すもの

- 重ね合わせのフォルダの名前は `overlays` であり、置き場所はライブラリのフォルダの直下である。名前と置き場所を変えない
- `overlays` フォルダの中の名前の規則は、スタックのファイルと同じく `<識別子>.json` と書きかけの `<識別子>.json.tmp` であり、錠のファイルは `ClipViewer.lock` である

## 5. 再生の仕組み

### 5-1. 何を複数にするか

今の再生は、1本の動画を1つの `読み込んだ動画`(コマの倉庫・流し読み1本・テクスチャ1枚・音の倉庫・音の流し読み1本)で映し、1つの再生の指示で鳴らす(`アーキテクチャ.md` 判断1・判断8)。重ね合わせの作業場は、次の3つの単位で持つものを分ける。

| 単位 | 持つもの | 理由 |
|---|---|---|
| 使う動画の表の動画ごとに1つ | 動画の情報・コマの倉庫・音の倉庫・依頼の台帳 | 倉庫は1本の動画に結び付く。同じ動画の複数の区間は1つの倉庫に溜められる。同じ区間を2つの置いたクリップが使えば、倉庫は1回だけ溜める(倉庫は、同じ区間の依頼が既にあればその札を返す) |
| タイムラインの行ごとに1つ | 映像の流し読み・音の流し読み・テクスチャ・音の再生器 | 1つの行は同時に高々1つの置いたクリップを映す。行の中の置いたクリップの継ぎ目は、今のスタックの継ぎ目と同じ形で扱える |
| 重ね合わせに1つ | 再生の状況(時計)・行ごとの再生の指示の並び | すべての行が同じ時刻で動く |

テクスチャと音の再生器を行ごとにするのは、置いたクリップが入れ替わる間も行の番号が変わらないためである。テクスチャを載せ直すかの比較の鍵(コマ番号と寸法)は、今の判断3と同じく行の供給の中に置く。

### 5-2. 映す

重ね合わせが前のとき、`クリップビューアー` は1フレームごとに重ね合わせの作業場の次の手順を呼ぶ。

1. 時計: 重ね合わせの状態は、再生の状況を実時間の経過で進める。末尾(重ね合わせの長さ)に達したとき、全体ループが有効なら0秒へ戻し、無効なら止める。この規則は `clip_domain` の重ね合わせの時計(`重ね合わせの再生位置`)が持つ。全体ループの有効と無効は、スタックの全体ループと同じ型 `末尾での振る舞い` で表す。末尾で止まった位置から再生を始めると、スタックの作業場と同じく0秒から再生し直す(`重ね合わせの再生位置::再生を始める位置`)。置いたクリップが無い重ね合わせは長さが0秒なので、時計は0秒に留まる
2. 映すものを求める: `重ね合わせ::重ね合わせ上の時刻に映すものを求める(時刻, 全体の末尾)` は、奥の行から手前の行の順に、行ごとの映し方(`行の映し方`)を返す。映し方は次の3つのどれかである
   - **置いたクリップを映す**: その時刻に当たる置いたクリップと、その置いたクリップの区間の中の動画上の時刻(区間の開始に、始まりの時刻からの経過を区間の長さで割った余りを足した時刻)と、周回と、区間の終わりの行き先(`置いたクリップの区間の終わりの行き先`)を返す
   - **末尾で最後のコマを映す**: 時刻が重ね合わせの長さ以降のとき(全体ループが無効で時計が末尾で止まったとき)、置いたクリップを持つ行は、その行の最後の(始まりの時刻が最も遅い)置いたクリップの区間の終わりのコマを映す。最も遅く終わる行でない行も、その行の最後の置いたクリップの終わりのコマを映す。スタックが末尾で最後の再生できるクリップの区間の終わりを映す(`クリップスタック::表示するコマを求める`)のと揃える
   - **何も映さない**: 行の置いたクリップの間の隙間・最初の置いたクリップの前・置いたクリップの無い行。ただし、前の置いたクリップの終わりから丸めの許容誤差(`時間の長さ::丸めの許容誤差`。1マイクロ秒)より短い隙間に当たった時刻は、隙間とみなさず、前の置いたクリップを映す(4 の境目の判定)
3. 区間の終わりの行き先: 行き先は「区間の開始へ戻る」「別の置いたクリップへ進む(置いたクリップ)」「止まる」のどれかであり、進む先を置いたクリップで持つため、issue #3 で動画の番号を落とさない。行き先は、スタックの行き先(`アーキテクチャ.md` 判断8)と同じく、重ね合わせの時計の規則そのもので求め、規則を二重に書かない。今の周回の終わりを丸めの許容誤差だけ越える時刻まで、受け取った全体の末尾での振る舞いで時計を等倍で進め、時計が末尾で止まれば「止まる」、進めた時刻にその行が映す置いたクリップが同じ動画の同じ区間なら「区間の開始へ戻る」(次の周回、または同じ区間が続くとき)、別の置いたクリップなら「別の置いたクリップへ進む」、何も映さないなら「止まる」とする。この結果、次のようになる
   - 最後の周回より前は「区間の開始へ戻る」
   - 最後の周回で、同じ行の次の置いたクリップが丸めの許容誤差の内で続くなら、その置いたクリップへ進む
   - 最も遅く終わる行(終わりが重ね合わせの長さに達する行)の最後の周回の終わりは、全体ループが有効なら、時計が0秒へ戻るため、その行の0秒に始まる置いたクリップへ進む(0秒に置いたクリップが無ければ止まる)。全体ループが無効なら止まる。スタックの全体ループの継ぎ目と同じく、音を重ねてつなげる
   - 最も遅く終わる行でない行の最後の置いたクリップの終わりは、全体の末尾より前に来るので、全体ループが有効でも止まる。その行は隙間の後、時計が0秒へ戻ったときに0秒の置いたクリップから始まり直す
4. 境目の判定は次の形にし、秒の足し算と割り算の丸めで判定が揺れないようにする
   - 置いたクリップは、始まりの時刻から終わりの時刻の手前までを映す(半開区間)。境目ちょうどの時刻は後ろの置いたクリップが映す。行の中で始まりの時刻がその時刻以前の置いたクリップのうち最も後ろのものを選ぶため、許容誤差の分だけ食い込んだ継ぎ目でも後ろの置いたクリップが映す
   - 置く操作は許容誤差以下の食い込みを接しているとみなし、区間の終わりの行き先も許容誤差の内なら続くとする。これと揃えるため、前の置いたクリップの終わりから許容誤差より短い隙間に当たった時刻は、前の置いたクリップの最後の周回の区間の終わり(区間の中の最後のコマ)を映し、行き先はその隙間の後ろの置いたクリップへ進む。供給はその行の流し読みを閉じない(`clip_domain` の `タイムラインの行::許容誤差の内で終わった置いたクリップ`)
   - 周回は、始まりからの経過を区間の長さで割った正確な余りを先に引いてから商を四捨五入して求め(`時間の長さ::周回番号を求める`。スタックと共通)、周回と区間の中の位置が同じ位置を指すようにする。丸めで最後の周回を越えた周回が出たときは、最後の周回の区間の終わりとみなす
5. 先読み: 重ね合わせの供給は、動画ごとに、溜める区間の並びを「今映している置いたクリップ → 次に始まる置いたクリップ → 残り」の順に作り、依頼の台帳へ渡す(今の判断4と同じ台帳)
6. 供給: 重ね合わせの供給は、行ごとに、その区間を溜め終えていれば倉庫から、そうでなければ行の流し読みから、その時刻のコマを取り出して行のテクスチャへ載せる
7. 画面: 重ね合わせの画面は、重ねる画面の中に、行の順(奥から手前)に、各テクスチャのクロップを映す矩形へ引き伸ばして描く(割合の矩形へ置く容器)
   - 行のテクスチャは行の中で置いたクリップが入れ替わっても作り直さないため、行が映す置いたクリップが変わった直後は、新しい置いたクリップのコマが届くまで前の置いたクリップのコマが残る(溜めていない区間は流し読みを開き直して待つ)。新しい置いたクリップの映す矩形とクロップでそのコマを描くと、前の絵が別の場所と切り抜きで一瞬出る。そこで供給は、行ごとの行の映像(`overlay/feed/row_video.rs`。行のコマの載せ先と載せたコマの置いたクリップの組)に、行のテクスチャに今載っているコマがどの置いたクリップのコマかと、その置いたクリップの続く先を覚える(`overlay/feed/loaded_rows.rs` の `載せたコマの置いたクリップ`)。続く先とは、その置いたクリップの今の周回の区間の終わりの行き先(3)を写したもの(同じ区間 / 別の置いたクリップ / 止まる)であり、行がその置いたクリップを映すフレームごとに今に合わせ、行が何も映さないフレームと末尾で最後のコマを映すフレームでは止まるにする(`overlay/feed/continuation.rs`)。別の置いたクリップのコマとして覚え直すのは、その置いたクリップの区間の中のコマを実際に行のテクスチャへ載せたとき(`コマを載せたか::載せた` の番号が区間の開始を含むコマ以上で、区間の終わりより前に始まるコマ)だけである。区間の外のコマは載せ先の範囲(下の `載せるコマの範囲::求めの区間の中だけ`)が先に弾くため、この確かめが偽になることは今は無いが、どの置いたクリップのコマかを覚える側の約束として残す。流し読みを開き直さずに続く継ぎ目(次の置いたクリップの区間の開始が、前の置いたクリップで最後に求めた位置から前向き2秒以内)では、流し読みがまだ前の置いたクリップの区間のコマを出し、番号と寸法が同じなら載せ直さずに載せたと返すため、区間を確かめないと前の置いたクリップのコマを新しい置いたクリップのコマとみなしてしまう
   - 画面は、行が映す置いたクリップのコマが載っていれば、その置いたクリップの映す矩形とクロップで描く。載っていなくても、載っている前の置いたクリップの続く先が映す置いたクリップ(または同じ区間)なら(再生中に同じ行の次の置いたクリップへ続けて進んだとき、全体ループで0秒の置いたクリップへ戻ったとき)、前の置いたクリップの最後のコマを、前の置いたクリップの映す矩形とクロップで描き続ける。続く先が止まる後(何も映さない時刻を挟んだ後と、末尾で止めた位置から「再生」で0秒へ飛んだ後)と、置いたばかりの置いたクリップ(2-4)と、前の置いたクリップがもう重ね合わせに無いときは、その行を描かない。重ね合わせの作業場で再生の位置が進み以外で変わるのは、末尾で止めた位置から再生し直すときの0秒へのジャンプと、時間の軸で位置を動かすとき(第15段階。使い方.md 15.8節)である。0秒へのジャンプでは、行は末尾で最後のコマを映していたため、続く先は止まるになっている。時間の軸で位置を動かすときは、動かした時点で全部の行の続く先を `止まる` にする(`開いている重ね合わせ::再生の位置を動かす`。`clip_domain` の `重ね合わせの再生位置::時刻から作成する` の注意)。塊のドラッグを確定したときは動かした置いたクリップの元の行と先の行だけ、空の行を消したときは番号が変わる行(消した行から、消す前の最も手前の行まで)だけ、同じく続く先を `止まる` にし、位置を飛ばした回数を進める。ほかの行は行の中身も番号も変わらないため、続けて映し、鳴らす。塊を確定して重ね合わせの長さが変わると、ほかの行の置いたクリップの区間の終わりの行き先(全体ループで0秒へ戻るか止まるか)も変わりうるが、断たなくてよい。供給は、行が映す置いたクリップと行のテクスチャに載っているコマの置いたクリップが同じ間は、毎フレーム続く先を今の行き先に合わせ直す(`載せたコマの置いたクリップ::載せた結果を覚える` が `今の続く先に合わせる` を呼ぶ)ためである。合わせ直さないのは、行が次の置いたクリップのコマを待って前の置いたクリップのコマを描いている間だけであり、そのとき覚えている続く先は、もう起きた切り替わり(前から次へ)を表すため、長さが変わっても古くならない(映像は `overlay/with_ffmpeg_continuation_tests.rs`、音は `overlay/timeline_continuation_sound_tests.rs` が固定する)。止まるにしないと、前の置いたクリップの最後のコマが、動かした先で前の映す矩形に描かれ続ける(`overlay/with_ffmpeg_seek_tests.rs` が固定する)
   - 重ね合わせの行のコマの載せ先は、流し読みの出したコマのうち、映す置いたクリップの区間の中のコマだけを行のテクスチャへ載せる(`video_feed/load_range.rs` の `載せるコマの範囲::求めの区間の中だけ`。スタックの作業場はどのコマも載せる)。流し読みを開き直さずに続く継ぎ目では、流し読みが2つの区間の間にあるどちらの区間にも入らないコマ(区間の間が2秒なら最大で約60コマ)を順に出すが、それを載せないため、前の置いたクリップの最後のコマがそのまま残り、それを描き続ける
   - 継ぎ目で前の置いたクリップの最後のコマを描き続ける方を選んだのは、ちらつきが少ないためである。新しい置いたクリップのコマが届くまで行を描かない形では、隙間なく続く継ぎ目のたびに、流し読みを開き直す間(数フレームから十数フレーム)その場所が空になり、奥の行か重ねる画面の背景が一瞬見える。描き続ける形では、前の置いたクリップが自分の場所で最後のコマのまま止まって見えるだけであり、溜めていない区間の繰り返しのつなぎ目で映像が詰まる今の振る舞い(使い方.md 15.5節)と同じ見え方になる

### 5-3. 鳴らす(音を混ぜる)

- `audio_output` に、行ごとの音の再生器を固定の数(同時に重ねられる行の数と同じ8)だけ配列で持ち、行ごとの再生の指示の並びに従って標本を作る新しい型(`行の音を混ぜる係`)を足す。配列の大きさは `clip_domain` の定数から決め、2つの値を別々に書かない
- 重ね合わせの音は、同じ既定の音声出力装置に開く2本目の流れで鳴らす。スタックの作業場の音は今の1本目の流れのまま鳴らし、今の `再生の共有` と `音を埋める係` の中身を変えない。作業場を移るときは後ろへ下げた作業場の再生を止めるため、2本の流れが同時に音を出すことは無い。止めた側の流れは、今の止めた指示のとおり黙った標本を出し続ける
- 行の音を混ぜる係は、行ごとの再生器にそれぞれの指示で下書きを埋めさせ、`ステレオの標本::足す` で足し合わせ、−1〜1 へ収めて装置の並びへ写す。下書きは、今の下書き(4096標本)と同じ大きさのものを1つだけ、作るときに1回だけ確保し、行ごとに順に貸して使い回す。音声のスレッドでメモリを確保しないという制約(`アーキテクチャ.md` 判断8-4)を保つためである。1標本は16バイト(左右の f64)なので、下書きは 4096 × 16バイト = 約64KB である。音を埋める係が装置の並びを下書きの標本数ずつに分けて渡すため、行の音を混ぜる係は自分では分けず、長い出力が届いたら到達したらバグとして止める
- 行の指示の音量は、置いたクリップの音の設定の音量(置いたクリップの消音なら0)に、全体の鳴らす音量(音量のつまみの値。全体を消音していれば0)を掛けたものである。行の再生器が音量を標本に掛ける扱いは、今の1本の再生器と同じにする
- その時刻に置いたクリップが無い行について、重ね合わせの状態は「止めている」の指示を組み立てる。行が隙間の後に置いたクリップを映し始めると(前のフレームでその行が何も映していなかったとき)、その行の指示の区間が変わり、その行の位置を飛ばした回数が進むため、行の再生器は今の規則(5ミリ秒で上げる)で鳴り始める。隙間なく続く継ぎ目(前のフレームも置いたクリップを映していた行。行き先が次の置いたクリップへ進む継ぎ目と、全体ループで0秒へ戻る最も遅く終わる行)では進めない。進めると、行き先に従って音を重ねる処理(クロスフェード)が、跳ぶ先の処理に打ち消されるためである(PR #28 の検収からの申し送り。第11段階で `overlay/state/sound/jump_count.rs` に置いた)。末尾で止まった行(末尾で最後のコマを映す行)は映しているとみなし、止めている指示に区間と区間の終わりの位置を持たせる(スタックの作業場が末尾で区間を持ったまま止める指示と同じ)
- 行の再生器が手放す出どころ(`Arc`)は、今と同じく退いた出どころの置き場へ移す。行の音を混ぜる係は、行ごとに今の型の置き場を1つずつ(32枠を8つ)持つ。1つの行が1フレームに手放す数は今の1本の再生器と同じなので、置き場の型と枠の数は変えない
- 行の再生器は、映像との同期を行ごとに今の規則(ずれが40ミリ秒を超えたときだけ合わせる)で行い、区間の終わりでは今の規則で行き先の音と重ねる(クロスフェード)。8行の再生器が1秒にする計算は今の8倍であり、48kHz で毎秒384,000回の読み出しと補間である
- 2本目の流れが使えなくなったとき(装置を抜いたとき等)は、重ね合わせの作業場が自分の音の出力の状況と通知で知らせる。スタックの作業場の音の出力の状況は変えない。知らせると同時に、行ごとの音の流し読みを閉じ、動画ごとの音の倉庫を捨てて読み込みを止める(音が出ないのに ffmpeg と倉庫の裏のスレッドが CPU を使い続けないため)
- 第11段階で決めたこと(PR #35 と PR #28 の検収からの申し送り)は次の5つである
  - 重ね合わせの作業場を離れている間の置き場: 2本目の流れを開いたら、スタックの作業場が前の間も毎フレーム、どの行も黙る指示(`行ごとの再生の指示::黙る`)を渡し続ける。指示を渡すたびに、`行を混ぜる音声出力::指示を渡す` が行ごとの置き場の中身を引き取って画面のスレッドで捨てる。離れる時点で1回だけ渡す形にしないのは、音声のスレッドがその指示を取り込んで手放した出どころ(溜めた音と流れてくる音の `Arc`)が、次に指示を渡すまで(重ね合わせの作業場へ戻るまで)置き場に残るためである。錠を取る回数は1フレームに1回であり、スタックの作業場の1本目と同じである。控えるときは、行ごとの映像と音の流し読みを閉じて ffmpeg を止め、控える時点でも黙る指示を1回渡す(次の描き直しまで前の指示で鳴り続けないため)
  - 装置を開く時間: 2本目の流れは画面のスレッドで開く。開発機(Windows 11・WASAPI・48kHz)で1本目を開いたまま2本目を5回開いて測ると、1回あたり約5ミリ秒(4.9〜5.8ミリ秒)であり、描き直しの間隔(16ミリ秒)より短い。開くのは初めて重ね合わせの作業場へ移るときの1回だけであり、1本目も起動のときに画面のスレッドで開いている。裏のスレッドで開くと、開いている間に重ね合わせを開いたときの音の倉庫の周波数が決まらない状態が生まれ、型に「開いている途中」を足すことになる。そのため裏のスレッドでは開かない。遅い装置(Bluetooth 等)で開く時間が長いことが分かったら、そのとき裏のスレッドへ移す
  - 2本目の周波数: 重ね合わせの音の倉庫は、2本目の流れの周波数(`行を混ぜる音声出力::周波数`)で FFmpeg に音を出させる。2本目の流れは重ね合わせを開く前(作業場を作るとき)に開くため、重ね合わせを開くときには周波数が決まっている。重ね合わせの作業場の状態が音の出力の状況(`重ね合わせの音の出力の状況`)として周波数を持ち、使えなければ音の倉庫を開かない(どの動画も鳴らせない)
  - Windows の途切れの確かめ: cpal の出力の関数が受け取る時刻(`OutputCallbackInfo` の再生の時刻と呼ばれた時刻の差)が小さくなったことから下書きが空になったことを捕まえる方法を検討した。この差は WASAPI では装置の待ち時間であり、差が小さくなったことは途切れの兆しであって途切れそのものではないため、閾値の決め方に実機の測定が要る。測定には実機で音を鳴らす確認が要り、オーナーの許可が要るため、第11段階では作らない。Windows で短い途切れを機械で確かめられないことは第10段階のまま変わらない(`アーキテクチャ.md` 判断8-9)
  - 隙間の後に始まるときだけ位置を飛ばした回数を進める規則: 上の項目に書いた
- 2本目の流れを開けることは、第10段階で `audio_output` の例(`examples/device_check/`)を2本の流れを開く形に広げて確かめた。開けない環境があると分かった場合の代わりの案は、今の1本の流れの共有の中に「1本で鳴らす」と「重ねて鳴らす」の判別共用体を置く形であり、そのときも回帰試験(c)で今の音を守る。第10段階で決めたことは次の4つである(`アーキテクチャ.md` 判断8-9)
  - `音声出力` の型の形: `音声出力` に型の引数を足さず、2本目は別の型 `行を混ぜる音声出力` にした。`音声出力` の公開の口と、それを使う `clip_viewer` のコードを変えないためである。型の引数は、内側の音を埋める係が持つ(時刻を渡して埋めさせる共有)
  - 2本目の流れを開く時期: 起動のときでなく、重ね合わせの作業場へ初めて移ったときに開く(第11段階で配線する)。重ね合わせを使わない利用者に起動の時間と2本目の音声のスレッドの負荷をかけないためであり、開けないことは利用者が重ね合わせの作業場へ移った時点で分かり、その作業場の知らせにすぐ出せる。一度開いたら、スタックの作業場へ戻っても閉じず、止めている指示で黙った標本を出し続ける
  - 開けないときの知らせ方: `行を混ぜる音声出力::既定の装置を開く` が `音声出力のエラー` を返し、途中で使えなくなったときは `使えなくなった理由` が返す。第11段階で、重ね合わせの作業場がこの値を自分の音の様子と知らせに出す。スタックの作業場の音の出力の状況は変えない
  - 2本が同時に開いている間の途切れの確かめ方: `device_check` は、2本目で8行に符号を反転した波を交互に音量1で鳴らし(混ぜるとちょうど0になり、装置から音は出ない)、2本目を開いている0.5秒の間に、cpal が1本目の途切れ(`ErrorKind::Xrun`)を1回も知らせないことと、1本目の毎秒の埋めた標本数が1本だけのときの9割を下回らないことを確かめる。2本目が音を求めないとき・2本目を開けないときも失敗にする。注意: cpal 0.18 の WASAPI(Windows)は出力の流れで途切れを知らせず、WASAPI は遅れた分をまとめて求めるため、Windows では短い途切れを機械で確かめられていない(`アーキテクチャ.md` 判断8-9)

### 5-4. デコードの負荷の見積もり

**溜めた区間を映すときのデコードは0である。** 倉庫に溜め終えた区間を映すとき、ClipViewer は FFmpeg を起動しない。同時再生で負荷が増えるのは、(a)区間を溜めるとき と (b)溜め終える前か溜められない区間を流し読みで映すとき の2つである。

**RAM。** 溜めるコマは1280×720のとき1コマ約3.7MB(3,686,400バイト)であり、今のRAMの上限の既定値2GBには約540コマ、30コマ/秒で約18秒分が収まる(`アーキテクチャ.md` 1-2)。同じ動画の置いたクリップは1つの倉庫の予算を分け合うため、溜められる区間の長さの合計が約18秒である。例えば、5秒の区間を2つ置くと約1.1GB(300コマ)を使い、4つ置くと約2.2GBで上限を超え、優先順の低い区間が溜められずに流し読みになる。

**デコードの速さ(測った値)。** 第9段階で、開発機(論理 CPU 20個、ffmpeg 4.4.1)の上で `cargo xtask decode-load`(下の「測る道具」)を使い、次の4つの動画を測った。どの表も、動画の先頭30秒を、アプリの流し読みと同じ形(fps フィルタでコマの速さをそろえ、1280×720 へ縮め、RGBA で標準出力へ出す)で、n 本の ffmpeg を同時に起動して読み切った時間である。倍率は、1本あたりの速さをその動画の再生の速さで割ったものであり、1倍を下回ると流し読みが再生に間に合わない。測るたびに、計算機のそのときの他の負荷で1割ほど揺れる。

| 1 | 10.9秒 | 約82コマ/秒 | 約82コマ/秒 | 約2.7倍 |
| 2 | 14.9秒 | 約121コマ/秒 | 約60コマ/秒 | 約2.0倍 |
| 4 | 34.2秒 | 約105コマ/秒 | 約26コマ/秒 | 約0.9倍 |
| 8 | 65.5秒 | 約110コマ/秒 | 約14コマ/秒 | 約0.5倍 |

この4つの表から次のことが言える。

- 溜める: 1920×1080 の動画なら、5秒(150コマ)の区間を1本で溜めると約0.6秒で終わる。3840×2160・60コマ/秒の動画では、5秒(300コマ)の区間を溜めるのに約4.4秒かかり、再生の速さとほぼ同じである
- 流し読み: 1920×1080・30コマ/秒の実写の動画では、8行が同時に流し読みになると1本あたり約1.2倍しか余裕が無く、4行までなら約3.0倍の余裕がある。3840×2160・30コマ/秒の動画は2行まで(約2.0倍)間に合い、4行で間に合わなくなる(約0.9倍)。3840×2160・60コマ/秒の実写の動画では、1行の流し読みが約1.1倍で間に合うのがやっとであり、2行以上は間に合わない
- 同じ実写の中身でも、3840×2160・60コマ/秒(約100Mbps)を1920×1080・30コマ/秒(約9.7Mbps)へ符号化し直すと、1本あたりの速さは約3.6倍になり、再生に必要なコマの数は半分になる。ただし、この2つは寸法・コマの速さ・ビットレート・符号化の設定が同時に違い、どれがどれだけ効いているかは分けて測っていない

**同時に重ねられる行の数の見直し(第9段階)。** 8のまま変えない。理由は次の2つである。

1. 流し読みが再生に間に合う行の数は、測った動画で、1行(3840×2160・60コマ/秒)・2行(3840×2160・30コマ/秒)・8行(1920×1080・30コマ/秒)のように変わる。行の数の上限を4へ下げても、3840×2160・60コマ/秒の動画は2行で間に合わないため救えず、1920×1080 の動画で8行を使う利用者の役に立たない。行の数の上限は、デコードの負荷を抑える値として働かない
2. 行の音を混ぜる係の配列の大きさを、決まった数にする必要がある(5-3)

8行が同時に流し読みになる状態は、溜め終える前の一時的な状態に限らない。上の「RAM」の段落のとおり、同じ動画の倉庫に溜められる区間の長さの合計は約18秒(1280×720)であり、例えば8行に5秒ずつの区間を置くと、約半分の行は倉庫の上限で溜められず、ずっと流し読みを続ける。そのため、流し読みの余裕(1920×1080・30コマ/秒の実写で、8行なら約1.2倍、4行なら約3.0倍)は、溜められない行が残る間ずっと必要な余裕である。間に合わないときの扱いは、上の方針の(1)(今映している区間から溜める)と(4)(行ごとに「溜めたコマ / 流し読み」を見せる)で受け持つ。

ただし、この表は ffmpeg が読み出すところだけの速さであり、アプリはこのほかに、コマを GPU へ載せる仕事と音の仕事を同じ計算機でする。1920×1080・30コマ/秒で8行が同時に流し読みになると、約1.2倍の余裕はそれらの仕事で消えうる。

行の数を見直すときは、`clip_domain` の `overlay/arrange/grid.rs` の格子の前提も確かめる。スタックから並べるときの格子は、列の数を個数の平方根を切り上げた数にし、ます目の大きさを100%を列(行)の数で等分した大きさにする。映す矩形の幅と高さは5%以上でなければならないため、列の数が21以上(個数が401以上)になると、ます目を映す矩形にできず、到達したらバグの panic に届く。また、grid.rs のコメントは「分割数は3以下」と書いており、これは個数が9以下(3×3)のときだけ正しい。行の数を10以上へ上げるときは、このコメントも直す。今の8では、格子は3×3であり、どちらの前提も崩れない。

**方針。** (1)重ね合わせの供給は、先読みの順を「今映している置いたクリップを先にする」にし、映している区間から溜める。(2)倉庫の裏のスレッドは、今と同じく溜める依頼を1本ずつ処理するため、溜めることが流し読みと CPU を取り合う本数は1本で済む。(3)重ね合わせの供給は、流し読みの開き直しの規則(最短0.25秒の間隔等。`画面.md` 判断5)を、スタックの作業場と同じコマの載せ先を行ごとに1つ持つことで行ごとに当て、8行が同時に ffmpeg を起動し直し続けることを防ぐ。(4)重ね合わせの画面は、行ごとに「溜めたコマ / 流し読み」を出し、継ぎ目が詰まる理由を利用者に見せる。

**測る道具。** 上の表の測り方は `cargo xtask decode-load [<動画のパス>] [--streams <本数,...>] [--seconds <秒数>]` である(実装は `xtask/src/decode_load/`、使い方は README の「デコードの負荷の測定」)。本数の既定は 1,2,4,8、読む長さの既定は先頭から30秒であり、出力の表は上の表と同じ列である。動画のパスを渡さなければ (1) の合成画像を一時フォルダに作って測り、終わったら消す。FFmpeg は verify と同じ順(環境変数 `CLIPVIEWER_FFMPEG_DIR` → PATH)に探す。1本の ffmpeg の引数はアプリの流し読み(`video_source` の `デコードの指定::引数を並べる`)と同じ形にしてあり、映像の流れの選び方(添付の画像を除いた最初の映像の流れ)・コマの速さの選び方(平均が読めないか240コマ/秒を超えるときは r_frame_rate)・回転の扱い(90度・270度なら幅と高さを入れ替える)も `video_source` の `probe/stream_shape.rs` と同じ規則にしてある。アプリと違うのは、先頭から読むため -ss を置かず -t で読む長さを限ることと、fps フィルタの前の時刻の補正(setpts)を置かないことである。xtask は `video_source` に依存しないため、同じ形に保つことは機械で確かめていない。アプリの流し読みの引数か流れの選び方を変えたときは、`xtask/src/decode_load/one_stream.rs` と `probed_stream.rs` も合わせて直す。上の4つの動画はどれも、最初の流れが映像で、回転の情報が無く、平均のコマの速さが240コマ/秒以下であるため、選び方を合わせる前に測った値がそのまま使える。時間がかかり結果が揺れるため、verify には入れない。登録しないまま測るスクリプトを置かない。

**GPU へ載せる量(見積もり。測っていない)。** 行ごとにコマが変わるたびに1コマ約3.7MBを載せる。4行が30コマ/秒で動くと毎秒約440MB、8行なら毎秒約880MBである。8行を映したときの1フレームの時間は、第18段階で測る。`decode-load` は ffmpeg だけを起動する道具であり、アプリの1フレームの時間を数えるには、アプリの中に時間を数える口が要るためである。

**既知の制約: 2つの作業場の RAM。** 重ね合わせの作業場へ移っても、スタックの作業場の `読み込んだ動画` は捨てない(3-2 の不変条件)。そのため、スタックの作業場の倉庫(上限2GB)と重ね合わせの作業場の倉庫(上限2GB)の両方が溜めると、映像だけで最大約4GBを使う。音の倉庫(上限256MB)も2つになる。

**既知の制約: 控えた重ね合わせの倉庫。** 重ね合わせの作業場を控える(スタックの作業場を前に出す)とき、重ね合わせの作業場は再生を止め、行ごとの流し読みを閉じて ffmpeg を止める(行のテクスチャには前に載せたコマが残る)。倉庫は捨てないため、控える前に依頼した区間の溜め残しを、控えた後も裏のスレッドが溜め続ける。量は最大で倉庫の上限の2GB分(1280×720 で約540コマ)であり、1本の読み出しの速さ(約280コマ/秒。上の表)で約2秒のデコードである。控えた間は先読みの並びが変わらないため、溜め終えれば止まる。

**既知の制約: デコードの二重。** 重ね合わせが前の間も、`クリップビューアー` はスタックの作業場の1フレームの手順を今のまま呼ぶ(3-2)。そのため、スタックの作業場の倉庫は、作業場を移る前に頼まれた先読みの区間を溜め続け、その間は重ね合わせの供給と CPU を取り合う。スタックの作業場の先読みの依頼は、並びが変わったときにしか増えず、重ね合わせが前の間はスタックの並びが変わらないため、取り合いは作業場を移った直後の、溜め残した区間の分に限られる。止めないのは、止めるとスタックの作業場の経路を変えることになるためである。

### 5-5. issue #3 で変える範囲

issue #3 で使う動画の表が2本以上になると、次を変える。

- **倉庫の予算**: 動画ごとの倉庫がそれぞれ2GBの上限を持つと、合計の上限が動画の本数に比例して増える。`video_source` に、複数の倉庫で1つの上限を分け合う予算の型を足し、重ね合わせの作業場の倉庫どうしで分け合う(スタックの作業場の倉庫とは分け合わない)
- **テクスチャの鍵**: 今の載せ直しの鍵(`video_feed/texture_key.rs` の `載せたコマの番号と寸法`)はコマ番号と寸法だけを持ち、動画を読み込み直したことを `読み込んだ動画` を作り直すことで区別している。行のテクスチャは、行の中で置いたクリップの動画が変わっても作り直さないため、行の鍵に動画の番号を足す
- **音の区間の比較**: 音の再生器は、指示との関係を区間の範囲(`小数の標本の範囲`)だけで比べる(`audio_output/src/player/relation.rs`)。別々の動画の同じ数値の区間を同じ区間とみなさないよう、比較に出どころの動画を含める
- **行の中で動画が変わるときの流し読み**: 行の流し読みは1本の動画に結び付くため、行の中で次の置いたクリップの動画が変わったら、行の流し読みを新しい動画で開き直す。音の行き先の「別の区間へ進む」は、次の区間の出どころが溜めた音のときだけ渡す(今の規則と同じ)
- **置くこと**: issue #2 では、スタックの作業場の今の動画が使う動画の表の動画と同じときだけクリップを置ける(2-4)。issue #3 では、違う動画のクリップを置くと、その動画を使う動画の表に足し、足した動画の番号で置く形へ広げる。置く操作の動画の長さの確かめ(4-1)は、足した動画の長さで行う
- **画面**: 使う動画の表の動画の一覧と、動画ごとの映像の様子

重ね合わせのファイルの形式は第1版のまま変えない(4-1)。

## 7. オーナーの決定と主要な設計判断

### 決定1: 置いたクリップはトリガーと無限ループを持たない(オーナーの決定 2026-10-03)

置いたクリップは回数指定の繰り返しだけを持ち、重ね合わせ全体の繰り返しは全体ループで行う。今のクリップのトリガー(Enter待ち等)は「最後の周回を繰り返しながら待つ」規則(`アーキテクチャ.md` 判断6)であり、1本のタイムラインに1つのクリップしか映らないことを前提にしている。複数の行が同時に動くとき、1つの行が待つと、ほかの行を止めるのか動かし続けるのかが決まらない。無限ループの置いたクリップは占める長さが決まらず、塊の幅と重ね合わせの長さを決められない。スタックのクリップを置くときは、無限ループを1回に読み替え、トリガーを写さない。

### 決定2: 複数の動画を持つのは重ね合わせだけであり、スタックは1本の動画のままにする(オーナーの決定 2026-10-03)

スタックのファイルの版を上げず、スタックの作業場の動画の欄と先読みを変えない。issue #3 は、重ね合わせの使う動画の表に動画を足す形で行う(5-5)。

### 決定3: スタックのクリップを置くときは写しを作り、以後は別々に直す(オーナーの決定 2026-10-03)

参照にすると、スタックの作業場でクリップを直したときに重ね合わせが黙って変わり、スタックをライブラリから削除すると重ね合わせが壊れる。写しにすれば、重ね合わせのファイルは1つで完結し、スタックの作業場の操作とファイルを変えない。

### 判断4: 同時再生を画面の構えの選択肢にせず、別の作業場にする

理由と形は 3-2 に書いた。スタックの作業場と配線のコードに触れる所は 3-2 の「触れる所」の表に挙げたものに限り、どれもスタックの作業場だけを使っているときの振る舞いを変えない形にして、表の守る試験と回帰試験で確かめる。

### 判断5: 行ごとに1つの音の再生器と1つのテクスチャを持つ

置いたクリップごとに持つと、置いたクリップの数(上限なし)だけ再生器が要り、音声のスレッドの配列を決まった大きさにできない。行は同時に1つの置いたクリップしか映さないため、行ごとに持てば数は行の数(8以下)で決まる。行の中の置いたクリップの継ぎ目は、今のスタックのクリップの継ぎ目と同じく、行き先の音と重ねて鳴らせる。

### 判断6: 重ね合わせはスタックの版を上げずに、別の形式と別のフォルダで保存する

重ね合わせは別の型なので、別の形式(`ClipViewer.overlay`)にすれば、スタックのファイルは今の版のまま互換を保つ。フォルダを `overlays` にするのは、互換の約束(ライブラリのフォルダの直下に新しいデータを置かない)を守り、今の版のアプリの一覧に読めない行を出さないためである。`overlays` に別の錠を置くのは、今の `裏で動くライブラリ` と錠の型を変えずに、重ね合わせの書き込みを別の係に任せるためである。

### 判断7: 重ねる画面の縦横比は既存の `アスペクト比設定` の固定の比で持ち、重ね合わせが保存する

オーナーの決定の「出力と同じ縦横比の画面」は、重ね合わせの作業場の出力が重ねる画面そのものであることで満たす。縦横比の型は新しく作らず `アスペクト比設定` を使い、意味を持たない `クロップ連動` は重ね合わせの不変条件で拒む(2-5)。スタックの作業場の出力のアスペクト比は見る人の好み(見る側の設定)だが、重ね合わせの映す矩形は重ねる画面に対する百分率なので、縦横比が変わると置いたクリップの形が変わる。そのため縦横比は重ね合わせの値として保存する。
