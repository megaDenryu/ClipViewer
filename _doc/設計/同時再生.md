# 同時再生の設計

本文書は、同じ時刻に複数のクリップを並べて同時に再生する仕組み(issue #2)の、言葉の定義・利用者から見た振る舞いの案・層と依存の向き・データの形と保存形式・再生の仕組み・実装の段階を定める。続く issue #3(別々の動画のクリップを同時に再生する)を不可能にしない形を、本文書の各節で明示する。

クレートどうしの層の正本は `アーキテクチャ.md`、`clip_viewer` の内側の層の正本は `画面.md`、ライブラリの形式の正本は `ライブラリ.md` である。本文書はそれらに足す部分だけを扱う。実装と食い違ったときは、どちらが正しいかを決めて一致させる。

状態: 設計の案(オーナー未承認)。2節の振る舞いは、実装の各段階で `../使い方.md` へ写し、オーナーの承認を受ける(CLAUDE.md「利用者向けの説明書」)。

## 1. 定義

ここで定める言葉は、実装のときに `clip_domain` の該当する型の文書コメントへ同じ定義文で写す(用語の正本は `clip_domain` の rustdoc である)。

- **同時再生**とは、1つのタイムラインの上に並べた複数のクリップを、同じ時刻に、それぞれの場所と大きさで映し、それぞれの音量で鳴らすことである。
- **重ね合わせ**とは、重ねる画面の縦横比と、使う動画の表と、タイムラインの行の並びの組のことである。重ね合わせは、同時再生で再生するものの全部であり、ライブラリへ1ファイルとして保存する単位である。今のスタック(クリップを上から順に並べたもの)とは別の型である。
- **重ねる画面**とは、重ね合わせの縦横比を持つ四角の画面であり、置いたクリップを好きな場所に好きな大きさで映す台のことである。同時再生の構えの出力は、重ねる画面をそのまま映す。
- **使う動画の表**とは、重ね合わせが使う動画のパスを、動画の番号(0から始まる整数)で指せる並びのことである。issue #2 の重ね合わせは表に動画を1本だけ持ち、issue #3 で2本以上を持つ。
- **動画の番号**とは、使う動画の表の中で、1本の動画を指す番号のことである。
- **置いたクリップ**とは、1本の動画の区間に、繰り返しの回数・クロップ範囲・動画の番号・タイムラインの上の始まりの時刻・映す矩形・置いたクリップの音量を付けたもののことである。置いたクリップは今のクリップ(`クリップ`)の値の写しから作るが、別の型であり、トリガーを持たない(7節の判断1)。
- **タイムラインの行**とは、タイムラインの横1本の帯であり、時間の重ならない置いたクリップを始まりの時刻の順に並べたもののことである。上の行の置いたクリップほど、重ねる画面の手前に映る。1つの行は、同時に高々1つの置いたクリップを映し、1つの音を鳴らす。
- **重ね合わせの上の時刻**とは、重ね合わせの始まりからの経過の秒のことである。今の `時刻<タイムライン上>`(スタックを並べた時間の中の秒)とは別の基準であり、`時刻<重ね合わせの上>` として型で分ける。
- **置いたクリップの占める長さ**とは、区間の長さに繰り返しの回数を掛けた長さのことである。置いたクリップは、タイムラインの上で始まりの時刻から占める長さの間だけ映る。
- **重ね合わせの長さ**とは、すべての置いたクリップの終わり(始まりの時刻に占める長さを足した時刻)のうち最も遅い時刻のことである。
- **映す矩形**とは、置いたクリップのクロップを掛けた絵を、重ねる画面のどこにどの大きさで映すかを表す矩形のことであり、重ねる画面の幅と高さに対する百分率で左端・上端・幅・高さを持つ。
- **置いたクリップの音量**とは、置いたクリップごとの音の大きさ(0〜1)と、消音しているかの組のことである。鳴らす大きさは、置いたクリップの音量に、今の音量のつまみの値(見る側の設定の音量)を掛けたものである。
- **同時に重ねられる行の数**とは、1つの重ね合わせが持てるタイムラインの行の数の上限のことであり、8とする(根拠は5節の 5-4)。
- **同時再生の構え**とは、重ね合わせを作り、直し、再生するための画面の構えのことである。今の編集・シアター・ライブラリの3つの構えに並ぶ4つ目の構えである。

## 2. 利用者から見た振る舞いの案

### 2-1. 今の UI と分ける境界

オーナーの決定(2026-10-03)により、1本の動画の今の操作感を変えず、同時再生は専用の UI に分ける。分ける境界は次のとおりである。

| 項目 | 今の構え(編集・シアター・ライブラリ) | 同時再生の構え |
|---|---|---|
| 再生するもの | スタック(1本の動画のクリップの並び) | 重ね合わせ |
| 時計 | 今の `再生の状況` | 同時再生の構えの再生の状況(別の値) |
| 映像の供給 | 今の `読み込んだ動画`(1つ) | 重ね合わせの動画の供給(使う動画の表の動画ごとに1つ) |
| 音 | 今の1本の再生の指示 | 行ごとの再生の指示を混ぜる指示(5節) |
| 取り消しの履歴 | 今の編集の履歴 | 重ね合わせの編集の履歴(別の値) |
| ライブラリのファイル | スタックのファイル | 重ね合わせのファイル(4節) |

同時再生の構えから今の構えへ戻っても、今の構えのスタック・動画・再生の位置・取り消しの履歴は、同時再生の構えへ入る前のままである。同時再生の構えで行う操作は、今の構えの状態を書き換えない。逆も同じである。

今の構えのコードで変えるのは次の7つだけである。どれも、同時再生の構えの分を足すだけであり、今の構えのときに通る処理を変えない。

1. ヘッダーの構えのボタンに「同時再生」を足す
2. `アプリの状態::構えを移す` に同時再生の構えを足す。同時再生の構えへ移るときは、ライブラリの構えへ移るときと同じく今の構えの再生を止める。同時再生の構えから出るときは、重ね合わせの再生を止める
3. 1フレームの手順で、同時再生の構えのときだけ重ね合わせの時計・供給・音を進める。ほかの構えのときは今の手順のまま進める
4. 音の送り手が `audio_output` へ渡す値を、「1本で鳴らす」と「重ねて鳴らす」の判別共用体にする(5-3)。今の構えは「1本で鳴らす」に今の再生の指示を入れて渡す
5. 応答の束(`command::応答`)に、同時再生の構えの応答の列挙を足す
6. ウインドウへ落としたファイルの扱いに、同時再生の構えのときの行き先を足す(2-2)
7. ライブラリの一覧に、重ね合わせの行と、スタックの行の「同時再生で並べる」を足す(2-7・2-8)

### 2-2. 入り方と出方

- 利用者は、ヘッダーの「同時再生」を押して同時再生の構えへ入る。
- 重ね合わせを開いていないときに入ると、同時再生の構えは「今の動画で同時再生を始める」のボタンと、ライブラリから重ね合わせを開く案内を出す。ボタンは、編集の構えで動画を開いているときだけ押せる。押すと、ClipViewer はその動画を使う動画の表に入れた空の重ね合わせを作る。
- 利用者が重ね合わせを開いたまま構えを出て、また入ると、ClipViewer は同じ重ね合わせを同じ再生の位置で出す。
- 利用者は、ヘッダーの「編集」「シアター」「ライブラリ」で同時再生の構えを出る。
- 同時再生の構えでウインドウへ動画を落とすと、ClipViewer は動画を編集の構えで開き、編集の構えへ移る(ライブラリの構えで動画を落としたときと同じ)。JSON を落とすと、「JSON読込」と同じく読み、編集の構えへ移る。どちらも重ね合わせを変えない。

### 2-3. 画面の区画

| 区画 | 場所 | 中身 |
|---|---|---|
| ヘッダー | 上の端 | 構えのボタン、「キー設定」、重ね合わせのライブラリへの保存の様子と「ライブラリに保存」、「取り消す」「やり直す」(重ね合わせの履歴) |
| 左のサイドバー | 左の端 | 置くクリップの一覧(今の構えのスタックのクリップ)と、選んでいる置いたクリップの設定(名前・区間・繰り返しの回数・クロップのプレビュー・音量・消音・削除) |
| 出力 | 真ん中 | 重ねる画面。選んでいる置いたクリップの映す矩形に枠を重ねる |
| タイムライン | 下の端 | 再生の操作(再生と停止・再生位置の帯・全体ループ・音量のつまみ)と、行ごとの帯に置いたクリップを並べたもの |

### 2-4. 置き方と大きさの変え方

- 利用者がサイドバーの置くクリップの一覧で「置く」を押すと、ClipViewer はそのクリップの区間・繰り返しの回数・クロップ・名前の写しから置いたクリップを作り、今の再生の位置を始まりの時刻にして、空いている最も上の行へ置く。どの行もその時刻に空いていなければ新しい行を足す。行が同時に重ねられる行の数(8)に達していれば置かずに理由を知らせる。
- 写しであるため、置いた後に今の構えでスタックのクリップを直しても、置いたクリップは変わらない(7節の判断3)。
- 新しく置いたクリップの映す矩形は、重ねる画面の全体である。
- 利用者は、出力の重ねる画面の上で置いたクリップを押して選び、枠の内側をドラッグして映す矩形を動かし、四隅をドラッグして大きさを変える。大きさを変えるときは、ClipViewer はクロップの形の縦横比を保つ(利用者が Shift を押している間は保たない)。映す矩形は重ねる画面の外へ出ない。映す矩形の幅と高さは重ねる画面の5%より小さくならない(今のクロップ枠と同じ規則)。
- 利用者が置いたクリップの重なっている場所を押すと、ClipViewer は手前(上の行)の置いたクリップを選ぶ。

### 2-5. タイムラインの形

- タイムラインは、上から行を並べ、行ごとに横の帯を持つ。帯の左端から右端までが、0秒から重ね合わせの長さ(短すぎるときは10秒)までである。
- 塊とは、行の帯の上に、置いたクリップを始まりの時刻から占める長さの幅で描いた四角のことである。塊の中には周回の区切りが細い線で描かれる。
- 利用者が塊をドラッグすると、その置いたクリップの始まりの時刻が変わる。ドラッグしている塊は、同じ行のほかの塊と重ならず、ぶつかった所で止まる。利用者が塊を上下の行へ動かすと、その置いたクリップの行が変わり、重なりの順が変わる。
- 再生位置の帯と、行の帯の上の位置の線は同じ時刻を指す。

### 2-6. 音量

- サイドバーは、選んでいる置いたクリップの音量のつまみ(0〜1。最初の値は1)と「消音」のチェックボックスを出す。音量は置いたクリップごとに別々の値であり、利用者は片方の置いたクリップを消音にすることも、両方を鳴らすこともできる。
- タイムラインの音量のつまみは、今の構えと同じ見る側の設定の音量であり、すべての置いたクリップに掛かる。

### 2-7. 保存と開き直し

- 重ね合わせは、スタックと同じライブラリへ、名前を付けて登録する。登録した重ね合わせは、スタックと同じく編集のたびに自動で保存する(`ライブラリ.md` 判断5と同じ規則)。
- ライブラリの一覧は、スタックの行と重ね合わせの行を同じ一覧に並べ、重ね合わせの行に「同時再生」の印を付ける。一覧の操作(開く・名前を変える・複製する・削除する・動画の場所を指定し直す)は重ね合わせにも効く。重ね合わせの行で「開く」を押すと、ClipViewer は重ね合わせを開いて同時再生の構えへ移る。
- 未登録の重ね合わせを捨てる操作(別の重ね合わせを開く・アプリを閉じる)の前には、スタックと同じく確かめるダイアログを出す(`画面.md` 判断14)。
- 一覧のサムネイルは、最も早く始まる置いたクリップ(同じ時刻なら下の行のもの)の開始のコマにそのクロップを掛けたものとする。今の撮り方(`サムネイルの撮り方`)をそのまま使えるため、`thumbnail_cache` を変えない。

### 2-8. 既存のスタック・ライブラリとの関係

- 重ね合わせは、スタックを参照しない。置くクリップの一覧は今の構えのスタックを見せるだけであり、置いた後は写しが重ね合わせに属する。
- 一覧のスタックの行に「同時再生で並べる」を足す。押すと、ClipViewer はそのスタックの再生できるクリップを1つの行に順に並べた新しい重ね合わせを作る(4-3 の読み替え)。並べた後は、塊を別の行へ動かして同時に鳴らせる。
- 既存のスタックのファイル・v4.0 の JSON・settings.json の形式は変えない。

## 3. 層と依存の向き

### 3-1. クレートの層

新しいクレートは作らない。今のクレートの層(`アーキテクチャ.md` 2節)と依存の向きを変えず、各クレートの中へ次を足す。

| 層(クレート) | 足すもの | 知ってよいもの(今と同じ) |
|---|---|---|
| `clip_domain` | `overlay/` モジュール: 重ね合わせ・使う動画の表・動画の番号・置いたクリップ・タイムラインの行・映す矩形・置いたクリップの音量・重ね合わせの上の時刻の基準。重ね合わせの操作(置く・動かす・大きさを変える・行を変える・取り除く)と不変条件、その時刻に映すものを求める処理、重ね合わせの時計の規則、スタックからの読み替え。`library/` へ: ライブラリの重ね合わせ・重ね合わせの識別子・重ね合わせのファイルの第1版の型と最新への変換 | 何も知らない |
| `video_source` | issue #2 では足さない。1本の動画の倉庫が複数の区間を溜め、流し読みは1本の動画に何本でも開けるため、今の口で足りる(5-2) | `clip_domain` |
| `audio_pcm` | 左右の標本を足し合わせる演算と、−1〜1へ収める演算(`ステレオの標本` のメソッド) | `clip_domain` |
| `audio_output` | 行ごとの音の再生器を固定の数だけ持ち、音を混ぜる係(5-3)。重ねて鳴らす指示の型 | `clip_domain`・`audio_pcm`・cpal |
| `clip_library` | ライブラリのフォルダの下の `overlays` フォルダの読み書きと走査。一覧の項目を「スタック」か「重ね合わせ」の判別共用体にする | `clip_domain`・thiserror・std::fs |
| `thumbnail_cache` | 足さない(2-7) | `clip_domain`・thiserror・std::fs |
| `clip_viewer` | 同時再生の構えの状態・操作・供給・画面(3-2) | すべて |

依存の向きの強制は今と同じく Cargo の依存で行う。`clip_domain` の `overlay/` は egui も FFmpeg も知らないため、重ね合わせの規則から画面やデコードを呼ぶコードはコンパイルできない。

`clip_domain` の `overlay/` は、既存の `クリップスタック` を知ってよいが、その逆は無い。`クリップスタック` を知る理由は、スタックからの読み替え(4-3)と、クリップの値の写しを作る口だけである。`クリップスタック` の型と規則は変えない。

### 3-2. `clip_viewer` の内側の層

`画面.md` 2節の層の表に、同時再生の構えの部分を次の形で足す。どれも、今の構えのモジュールの横に別のモジュールとして置き、今のモジュールの中に同時再生の分岐を書かない。

| 層(モジュール) | 何を持つか | 何を知ってよいか |
|---|---|---|
| 型契約(`state/overlay/`) | 同時再生の構えの状態: 開いている重ね合わせ(ライブラリとの関係を含む)・再生の状況・選んでいる置いたクリップ・映す矩形と塊のドラッグ・重ね合わせの編集の履歴。状態から重ねて鳴らす指示を組み立てること | `clip_domain`・`clip_library`・`audio_pcm`・`audio_output`(指示の型)・`overlay_feed`・`viewer_settings` |
| 重ね合わせの供給(`overlay_feed/`) | 使う動画の表の動画ごとの供給(コマの倉庫・音の倉庫・依頼の台帳)と、行ごとの流し読み・音の流し読み・テクスチャ | `clip_domain`・`video_source`・`audio_feed`(動画の音の型)・`video_feed`(依頼の台帳と載せ直しの判断の純粋な部分)・`stream_rules`・SengenEgui のテクスチャ |
| 操作コマンド(`command/overlay/`) | 同時再生の構えの応答(`重ね合わせの操作`)の列挙と適用。応答の束(`command::応答`)に9つ目の列挙として足す | `state`・`overlay_feed`・`clip_library`・`persistence` |
| UI(`view/overlay/`) | 重ねる画面・タイムライン・サイドバー | `state`・`command` の応答・`overlay_feed`(読むだけ)・`clip_domain`・`viewer_settings`(読むだけ) |

`overlay_feed` が `video_feed` から使うのは、依頼の台帳(`画面.md` 判断4。毎フレームの並びから捨てる区間と依頼する区間を決める純粋な判断)と、テクスチャを載せ直すかの判断(判断3)だけである。2つとも1本の動画に結び付いた純粋な判断であり、動画ごとに1つずつ持てば重ね合わせでもそのまま使える。`video_feed` の `読み込んだ動画` は今の構えだけが持ち、`overlay_feed` は使わない。`video_feed` が `overlay_feed` を知ることは無い。

### 3-3. SengenEgui に足す口

今の SengenEgui の重ねる容器(`重ね型`)は、子を下地の9つの寄せ先(左上・中央など)へ置くだけであり、好きな場所と大きさへは置けない。範囲枠付き画像は1つの枠しか持たない。区間の帯は1本の帯に1つの区間しか持たない。CLAUDE.md の規約(利用側に素の egui の呼び出しを書いて回避しない)に従い、次の3つを SengenEgui へ足してから使う。

1. **割合の矩形へ置く容器**: 子を、容器の矩形に対する割合で表した矩形へ、書いた順に重ねて置く。重ねる画面の表示に使う
2. **複数の枠を置く台**: 下地の上に複数の枠を置き、押した枠を選び、内側のドラッグで動かし、四隅のドラッグで大きさを変える。縦横比を保つかの指定を持つ。発する値は割合の差であり、`clip_domain` の百分率への変換は `view/conversion.rs` と同じく境界1箇所で行う
3. **時間の行の並び**: 複数の行に、それぞれ複数の塊(始まりと長さ)を描き、塊のドラッグを始まりの値と行の差で発する。位置の線を持つ

## 4. データの形と保存形式

### 4-1. 型の形

```
重ね合わせ
  重ねる画面の縦横比     : 縦横比の選択(16:9・4:3・1:1・9:16。最初は16:9)
  使う動画の表          : [正規化した動画パス]   (issue #2 では1本。型は複数を許す)
  タイムラインの行の並び : [タイムラインの行]      (0〜8行。先頭が奥、末尾が手前。タイムラインは末尾の行をいちばん上に描く)

タイムラインの行
  置いたクリップの並び   : [置いたクリップ]      (始まりの時刻の順。時間が重ならない)

置いたクリップ
  識別子               : 置いたクリップの識別子(重ね合わせの中で重ならない)
  名前                 : クリップ名
  動画の番号            : 動画の番号(使う動画の表にある番号)
  区間                 : 動画上の区間
  繰り返しの回数         : リピート回数(1〜100。無限を持たない)
  クロップ範囲           : クロップ範囲
  始まりの時刻           : 時刻<重ね合わせの上>
  映す矩形              : 映す矩形(重ねる画面に対する百分率)
  音量                 : 置いたクリップの音量(音量と消音しているか)
```

重ね合わせの不変条件は次のとおりであり、重ね合わせの操作はどれも、満たさない値を返さずに型付きのエラー(`重ね合わせの操作エラー`)を返す。

- 行の数は同時に重ねられる行の数(8)以下である
- 同じ行の置いたクリップは、始まりの時刻の順に並び、占める時間が重ならない
- 置いたクリップの識別子は、重ね合わせの中で重ならない
- 置いたクリップの動画の番号は、使う動画の表にある
- 映す矩形は重ねる画面の内側にあり、幅と高さは5%以上である

使う動画の表は、どの置いたクリップも使っていない動画を持ってよい。issue #3 で、動画を表に足してから置く操作の順を許すためである。

置いたクリップの動画の番号を、置いたクリップごとに持つのは、issue #3 を不可能にしないためである。issue #2 の画面は、表の動画が1本の重ね合わせだけを作るが、型とファイルの形は最初から複数の動画を表せる。そのため issue #3 は、表に動画を足す画面と、動画ごとの供給を複数持つ配線を足すだけで済み、形式の版を上げない。

### 4-2. 保存形式(重ね合わせのファイルの第1版)

- 置き場所は `%APPDATA%\ClipViewer\library\overlays\<重ね合わせの識別子>.json` である。ライブラリのフォルダの直下に新しいデータを置かないという互換の約束(`ライブラリ.md` 8節)に従い、サブフォルダに置く。今の版のアプリは走査でサブフォルダを読まないため、重ね合わせのファイルを読めない行として出さず、触れもしない
- 重ね合わせの識別子は `overlay-<ミリ秒>-<0〜9999の乱数>` の形にする。スタックの識別子(`stack-…`)と別の型(`重ね合わせの識別子`)であり、取り違えても型が通らない
- 書き込み・走査・錠・読めないファイルの扱いは、スタックのファイルと同じ規則(`ライブラリ.md` 判断2・3・6・9)を `overlays` フォルダに当てる。錠はライブラリのフォルダの錠を共有する
- 形式は版を持つ新しい形式(`format` は `ClipViewer.overlay`、`version` は1)にする。第1版は欠けた項目も知らない項目も許さない(`deny_unknown_fields`)。理由はスタックの第1版と同じである(`ライブラリ.md` 判断4)
- 第1版の形は `clip_domain` の `library/overlay_v1.rs` がそのまま写し、読み込みは先に `format` と `version` だけを読み、版に合う型で読んでから最新の `ライブラリの重ね合わせ` へ変換する。版ごとの型と最新の型の変換は、両方向とも最新の型を `..` を使わずに分解・組み立てる

### 4-3. 既存の形式の読み替え

- **スタックのファイルの版は、issue #2 では上げない。** 同時再生はスタックの形を変えずに、別の型と別のファイルで表すためである。今の版のアプリと新しい版のアプリは、同じスタックのファイルを今までどおり読み書きできる
- **スタックから重ね合わせへの読み替え**は、`clip_domain` の `重ね合わせ::スタックから並べる` が行う。スタックの再生できるクリップ(有効で長さが0でないもの)を、スタックの順に1つの行へ隙間なく並べる。各クリップの区間・クロップ・名前を写し、繰り返しの回数は回数指定ならその回数、無限ループなら1回にする。トリガーは写さない。映す矩形は重ねる画面の全体である。読み替えは写しを作るだけであり、元のスタックのファイルを変えない
- v4.0 の JSON は今までどおりスタックとして読む。v4.0 の JSON から重ね合わせを作るときは、スタックとして読んでから上の読み替えを通す
- 重ね合わせの形式の版を上げるときは、`ライブラリ.md` 7節の手順に従う(版ごとの型を足し、最新の型へ互換の都合を持ち込まない。古い版の読み手と見本は永久に残す)

### 4-4. 互換の約束に足すもの

`ライブラリ.md` 8節に次を足す。

- 重ね合わせのフォルダの名前は `overlays` であり、置き場所はライブラリのフォルダの直下である。名前と置き場所を変えない
- `overlays` フォルダの中の名前の規則(`<識別子>.json` と書きかけの `<識別子>.json.tmp`)は、ライブラリのフォルダの直下のスタックのファイルと同じである

## 5. 再生の仕組み

### 5-1. 何を複数にするか

今の再生は、1本の動画を1つの `読み込んだ動画`(コマの倉庫・流し読み1本・テクスチャ1枚・音の倉庫・音の流し読み1本)で映し、1つの再生の指示で鳴らす(`アーキテクチャ.md` 判断1・判断8)。同時再生では、次の3つの単位で持つものを分ける。

| 単位 | 持つもの | 理由 |
|---|---|---|
| 使う動画の表の動画ごとに1つ | 動画の情報・コマの倉庫・音の倉庫・依頼の台帳 | 倉庫は1本の動画に結び付く。同じ動画の複数の区間は1つの倉庫に溜められ、同じ区間を2つの置いたクリップが使えば、倉庫は1回だけ溜める(倉庫の「同じ区間の依頼が既にあればその札を返す」規則) |
| タイムラインの行ごとに1つ | 映像の流し読み・音の流し読み・テクスチャ・音の再生器 | 1つの行は同時に高々1つの置いたクリップを映し、行の中の置いたクリップの継ぎ目は今のスタックの継ぎ目と同じ形で扱える |
| 重ね合わせに1つ | 再生の状況(時計)・重ねて鳴らす指示 | すべての行が同じ時刻で動く |

テクスチャと音の再生器を行ごとにするのは、行の番号が置いたクリップの入れ替わりの間も変わらない識別になるためである。テクスチャを載せ直すかの比較の鍵(コマ番号・寸法・読み込み直し)は、今の判断3と同じく行の供給の中に置く。

### 5-2. 映す

1フレームの手順は、同時再生の構えのとき次のとおりである。

1. 時計: 重ね合わせの再生の状況を、実時間の経過と速度で進める。末尾(重ね合わせの長さ)に着いたら、全体ループが有効なら0秒へ戻り、無効なら止まる。規則は `clip_domain` の重ね合わせの時計(`重ね合わせの再生位置`)が持つ
2. 映すものを求める: `重ね合わせ::その時刻に映すもの(時刻)` が、行ごとに、その時刻に当たる置いたクリップと、その置いたクリップの区間の中の動画上の時刻(区間の開始に、始まりの時刻からの経過を区間の長さで割った余りを足した時刻)と、周回と、区間の終わりの行き先を返す。行き先は、最後の周回より前なら「開始へ戻る」、最後の周回で同じ行の次の置いたクリップが隙間なく続くなら「別の区間へ進む」、それ以外は「止まる」である
3. 先読み: 動画ごとに、溜める区間の並びを「今映している置いたクリップ → 次に始まる置いたクリップ → 残り」の順に作り、依頼の台帳へ渡す(今の判断4と同じ台帳)
4. 供給: 行ごとに、その区間を溜め終えていれば倉庫から、そうでなければ行の流し読みから、その時刻のコマを取り出し、行のテクスチャへ載せる
5. 画面: 重ねる画面の中に、行の順(奥から手前)に、各テクスチャのクロップを映す矩形へ引き伸ばして描く(割合の矩形へ置く容器)

### 5-3. 鳴らす(音を混ぜる)

- `audio_output` の再生の共有は、行ごとの音の再生器を固定の数(同時に重ねられる行の数と同じ8)だけ配列で持つ。配列の大きさは `clip_domain` の定数から決め、2つの値を別々に書かない
- 画面のスレッドが渡す鳴らし方は、判別共用体で表す。「1本で鳴らす(再生の指示)」は今の構えが渡し、今と同じく再生器を1つだけ使う。「重ねて鳴らす(行ごとの再生の指示の固定長の並び)」は同時再生の構えが渡す。今の構えの音は、混ぜる処理を通らないため、今と1標本も変わらない
- 重ねて鳴らすとき、音を混ぜる係は、行ごとの再生器にそれぞれの指示で下書きを埋めさせ、下書きを足し合わせ、−1〜1へ収めて装置の並びへ写す。行の下書きは、今の下書き(4096標本)と同じ大きさのものを、行の数だけ作るときに1回だけ確保する。音声のスレッドでメモリを確保しないという制約(`アーキテクチャ.md` 判断8-4)を保つためである。8行分の下書きは 8 × 4096 × 16バイト = 約0.5MB である
- 行の指示の音量は、置いたクリップの音量(消音なら0)に音量のつまみの値を掛けたものである。行の再生器が音量を標本に掛ける扱いは、今の1本の再生器と同じにする
- 鳴っていない行(その時刻に置いたクリップが無い行)の指示は「止めている」にする。行に新しい置いたクリップが始まると、その行の指示の区間が変わり、位置を飛ばした回数が進むため、再生器は今の規則(5ミリ秒で上げる)で鳴り始める
- 行の再生器が手放す出どころ(`Arc`)は、今と同じく退いた出どころの置き場へ移す。行が8つになると1フレームに手放す数が増えるため、置き場の枠の数を今の32から64へ増やす
- 映像との同期は行ごとに今の規則(ずれが40ミリ秒を超えたときだけ合わせる)で行う。8行の再生器が1標本あたりにする計算は今の8倍であり、48kHz で毎秒 384,000 回の読み出しと補間である

### 5-4. デコードの負荷の見積もり

**溜めた区間を映すときのデコードは0である。** 倉庫に溜め終えた区間は、再生中に FFmpeg を起動しない。同時再生で負荷が増えるのは、(a)区間を溜めるとき と (b)溜め終える前か溜められない区間を流し読みで映すとき の2つである。

**RAM。** 溜めるコマは1280×720のとき1コマ約3.7MB(3,686,400バイト)であり、今のRAMの上限の既定値2GBには約540コマ、30コマ/秒で約18秒分が収まる(`アーキテクチャ.md` 1-2)。同じ動画の置いたクリップは1つの倉庫の予算を分け合うため、溜められる区間の長さの合計が約18秒である。例えば、5秒の区間を2つ置くと約1.1GB(300コマ)を使い、4つ置くと約2.2GBで上限を超え、優先順の低い区間が溜められずに流し読みになる。

**デコードの速さ(測った値)。** 本文書を書いた開発機(論理 CPU 20個、ffmpeg 4.4.1)で、1920×1080・30コマ/秒・30秒(900コマ)の H.264 の動画(ffmpeg の合成画像 `testsrc2` を libx264 の既定の設定・キーフレームの間隔60コマで符号化したもの)を、アプリと同じ形(fps フィルタ、1280×720 へ縮め、RGBA で標準出力へ出す)で、n 本の ffmpeg を同時に起動して読み切る時間を測った。

| 同時に読む本数 | 読み切る時間 | 合計の速さ | 1本あたりの速さ | 再生の速さ(30コマ/秒)に対する倍率 |
|---|---|---|---|---|
| 1 | 3.2秒 | 約280コマ/秒 | 約280コマ/秒 | 約9.3倍 |
| 2 | 3.9秒 | 約470コマ/秒 | 約230コマ/秒 | 約7.8倍 |
| 4 | 8.3秒 | 約430コマ/秒 | 約110コマ/秒 | 約3.6倍 |
| 8 | 20.6秒 | 約350コマ/秒 | 約44コマ/秒 | 約1.5倍 |

この値から次のことが言える。合成画像は実写の動画と符号化の中身が違うため、実写の動画での速さは測っておらず、この表と違いうる。

- 溜める: 5秒(150コマ)の区間を1本で溜めると約0.5秒で終わる。8行に置いた区間をすべて溜める時間は、合計のコマ数を約280〜470コマ/秒で割った時間である
- 流し読み: 8行が同時に流し読みになると、1本あたりは再生の速さの約1.5倍しか余裕が無い。4行までなら約3.6倍の余裕がある
- 同時に重ねられる行の数を8にした根拠は、この開発機で8本の流し読みが再生の速さを上回ったことと、音を混ぜる係の配列の大きさを決まった数にする必要があることの2つである。8本の流し読みは CPU をほぼ使い切るため、実写の動画や遅い計算機では間に合わない見込みがある。この値は `clip_domain` の定数1つであり、同時再生の第2段階で実写の動画を測って見直す

**方針。** (1)先読みの順を「今映している置いたクリップを先にする」にし、映している区間から溜める。(2)溜める依頼は今の倉庫と同じく裏のスレッドが1本ずつ処理し、溜めることと流し読みが CPU を取り合う本数を増やさない。(3)流し読みの開き直しの規則(最短0.25秒の間隔等。`画面.md` 判断5)を行ごとに当て、8行が同時に ffmpeg を起動し直し続けることを防ぐ。(4)同時再生の構えの映像の様子の行に、行ごとの「溜めたコマ / 流し読み」を出し、継ぎ目が詰まる理由を利用者が見られるようにする。

**GPU へ載せる量(見積もり。測っていない)。** 行ごとにコマが変わるたびに1コマ約3.7MBを載せる。4行が30コマ/秒で動くと毎秒約440MB、8行なら毎秒約880MBである。同時再生の第2段階で、8行を映したときのフレームの時間を測る。

**同じ動画を2つの構えで開いたときの RAM。** 同時再生の構えへ移っても、編集の構えの `読み込んだ動画` は捨てない(2-1 の境界)。そのため、編集の構えの倉庫(上限2GB)と重ね合わせの倉庫(上限2GB)の両方が溜めると、映像だけで最大約4GBを使う。音の倉庫(上限 256MB)も同じく2つになる。これは既知の制約として受け入れ、同時再生の第2段階で、重ね合わせの倉庫の上限を設定値にするかを測って決める。

### 5-5. issue #3 への備え

issue #3 で動画が2本以上になると、動画ごとの倉庫がそれぞれ2GBの上限を持ち、合計の上限が動画の本数に比例して増える。issue #3 では、`video_source` に複数の倉庫で分け合う予算(1つの上限を複数の倉庫が借りる型)を足す。issue #2 の重ね合わせの供給は、使う動画の表の動画ごとに供給を持つ形にしておき、動画が1本のときも同じ形で動かす。そのため issue #3 で変えるのは、予算の型と、表に動画を足す画面だけである。

## 6. 実装の段階

各段階は単独でマージでき、`cargo xtask verify` を通す大きさにする。各段階を子 issue にする。振る舞いが利用者に見える段階は、同じ PR で `../使い方.md` に同時再生の節を足す(説明書が草案の間は、今のコードの写しとして足す)。

| 段階 | 内容 | 依存 | 利用者に見えるもの |
|---|---|---|---|
| 第1段階 | `clip_domain` の `overlay/`: 型・不変条件・その時刻に映すものを求める処理・時計の規則・スタックからの読み替えと、単体試験 | 無し | 無し |
| 第2段階 | 同時再生の構え(映像だけ): ヘッダーの「同時再生」、「今の動画で同時再生を始める」、スタックの再生できるクリップを1つずつ別の行に始まりの時刻0で置き、重ねる画面を縦横の格子に区切って映す矩形を決める。再生と停止・再生位置の帯・全体ループ。SengenEgui の割合の矩形へ置く容器を先に足す。8行の映像の負荷と RAM を測り、5-4 の値を見直す | 第1段階 | 同じ動画の複数のクリップが同時に映る(音は出ない。保存しない) |
| 第3段階 | 音: `audio_pcm` の足し合わせ、`audio_output` の音を混ぜる係と重ねて鳴らす指示、行ごとの音の供給、置いたクリップの音量と消音のつまみ | 第2段階 | クリップごとの音量で同時に鳴る |
| 第4段階 | 置き方の編集: SengenEgui の複数の枠を置く台を足し、映す矩形の選択・移動・大きさの変更。サイドバーの「置く」と、選んだ置いたクリップの設定(名前・区間・回数・クロップ・削除) | 第2段階 | 好きな場所と大きさに置ける |
| 第5段階 | タイムラインの編集: SengenEgui の時間の行の並びを足し、塊のドラッグで始まりの時刻と行を変える | 第4段階 | 時刻をずらして並べられる |
| 第6段階 | 保存: 重ね合わせのファイルの第1版、`clip_library` の `overlays` フォルダ、一覧の行の種類・開く・自動保存・確かめるダイアログ、スタックの行の「同時再生で並べる」 | 第1段階(画面の部分は第2段階) | ライブラリへ保存して開き直せる |
| 第7段階 | 仕上げ: 重ね合わせの取り消しとやり直し、同時再生の構えのキー操作(再生と停止等)、重ねる画面を全体に広げるシアターの形 | 第5段階・第6段階 | 取り消し・キー・シアター |

推奨順: 第1段階 → 第2段階 → 第3段階 → 第4段階 → 第5段階 → 第6段階 → 第7段階。第3段階・第4段階・第6段階は第2段階の後で互いに独立しており、並行してよい。

第1段階と第2段階を分けるのは、第1段階の不変条件(行の中で時間が重ならない・行の数の上限)と、映すものを求める処理の試験を、画面より先に固めるためである。第2段階は、置き方の編集も音も保存も持たないが、同じ動画の複数のクリップが同時に映ることを確かめられる最小の形である。

## 7. 主要な設計判断

### 判断1: 置いたクリップはトリガーと無限ループを持たない(オーナーの決定待ち。8節の1)

今のクリップのトリガー(Enter待ち等)は「最後の周回を繰り返しながら待つ」規則(`アーキテクチャ.md` 判断6)であり、1本のタイムラインに1つのクリップしか映らないことを前提にしている。複数の行が同時に動くとき、1つの行が待つと、ほかの行を止めるのか動かし続けるのかが決まらない。無限ループの置いたクリップは占める長さが決まらず、タイムラインの塊の幅と重ね合わせの長さを決められない。そのため、置いたクリップは回数指定の繰り返しだけを持ち、重ね合わせ全体の繰り返しは全体ループで行う。

### 判断2: 行ごとに1つの音の再生器と1つのテクスチャを持つ

置いたクリップごとに持つと、置いたクリップの数(上限なし)だけ再生器が要り、音声のスレッドの配列を決まった大きさにできない。行は同時に1つの置いたクリップしか映さないため、行ごとに持てば数は行の数(8以下)で決まる。行の中の置いたクリップの継ぎ目は、今のスタックのクリップの継ぎ目と同じく「別の区間へ進む」で交差させられる。

### 判断3: 置いたクリップは、スタックのクリップを参照せず写しを持つ(オーナーの決定待ち。8節の3)

参照にすると、編集の構えでスタックのクリップを直したときに重ね合わせが黙って変わり、スタックをライブラリから削除すると重ね合わせが壊れる。ファイルどうしの参照の整合を保つ仕組み(参照の検査・削除の連鎖)も要る。写しにすれば、重ね合わせのファイルは1つで完結し、今のスタックの操作感とファイルを一切変えない。

### 判断4: 重ね合わせはスタックの版を上げずに、別の形式と別のフォルダで保存する

スタックのファイルへ重ね合わせを入れる(スタックの第2版にする)と、新しい版のアプリが一度書いたスタックのファイルを、今の版のアプリが読めなくなる。重ね合わせは別の型なので、別の形式(`ClipViewer.overlay`)にすれば、スタックのファイルは今の版のまま互換を保つ。フォルダを `overlays` にするのは、互換の約束(ライブラリのフォルダの直下に新しいデータを置かない)を守り、今の版のアプリの一覧に読めない行を出さないためである。

### 判断5: 重ねる画面の縦横比は重ね合わせが持つ

今の出力のアスペクト比(見る側の設定)は見る人の好みであり、スタックのファイルに書かない(`画面.md` 判断17)。重ね合わせの映す矩形は重ねる画面に対する百分率なので、縦横比が変わると置いたクリップの形が変わる。そのため縦横比は重ね合わせの値として保存する。オーナーの決定の「出力と同じ縦横比の画面」は、同時再生の構えの出力が重ね合わせの縦横比で出ることで満たす。

## 8. オーナーに決めてもらうこと

1. **置いたクリップのトリガーと無限ループ。** 案A(推奨): 置いたクリップは回数指定の繰り返しだけを持ち、トリガーと無限ループを持たない。重ね合わせ全体の繰り返しは全体ループで行う。理由は、同時に動く複数の行の1つが待つときに、ほかの行の動き方が決まらないためである(判断1)。案B: 重ね合わせ全体に「待つ時刻」を置き、全部の行がその時刻で最後の周回を繰り返しながら Enter を待つ。案Bは後から足せる(案Aの形を壊さない)。
2. **issue #3 の「1つのスタックが複数の動画を持てる」の意味。** 案A(推奨): 複数の動画を持つのは重ね合わせだけにし、今のスタックは1本の動画のままにする。issue #3 の完了条件を「1つの重ね合わせが複数の動画を持てる(重ね合わせの形式は第1版で既に表せる)」に書き直す。理由は、今のスタックの操作感とファイルを変えないためである。案B: 今のスタック(順に並べる再生)のクリップも別々の動画を持てるようにする。案Bはスタックのファイルの版を上げ、編集の構えの動画の欄と先読みを作り直すため、今の UI に手を入れる。
3. **置いたクリップとスタックのクリップの関係。** 案A(推奨): 置くときに写しを作り、以後は別々に直す(判断3)。案B: スタックのクリップを参照し、編集の構えで直すと重ね合わせにも映る。案Bは、スタックの削除と重ね合わせの整合を保つ仕組みが要り、ファイルが2つにまたがる。
