# clip_viewer(アプリ本体)の設計

本文書は、`crates/clip_viewer` の中の層と依存の向き、主要な設計判断、移植元との操作の対応表を定める。
クレートどうしの層(`clip_domain` ← `audio_pcm` ← `video_source`・`audio_output` ← `clip_viewer`)は `アーキテクチャ.md` が正本であり、本文書はその内側だけを扱う。
利用者から見た振る舞いは `../使い方.md` が決める(オーナーが承認するまでは、使い方.md は今のコードの写しである。CLAUDE.md「利用者向けの説明書」)。本文書は作り方を書く。

## 1. 目的

`clip_viewer` は、クリップスタックを編集し、再生の時計を毎フレーム進め、表示するコマを溜めたコマか流し読みから取り出して画面へ出す。
このクレートが成立させることは次の3つである。

1. 短い区間の繰り返しを、溜めたコマから継ぎ目で途切れずに再生する(溜め終えるまでは流し読みで代わる)
2. クリップの区間・繰り返し・クロップ・トリガーを、プレビューを見ながら編集する
3. 設定ファイル(v4.0 形式)を読み書きし、FFmpeg の置き場所を画面から設定する
4. 作ったスタックをライブラリへ保存し、一覧から開き直す(設計は `ライブラリ.md`)

## 3. 主要な設計判断

### 判断1: 応答はモジュールごとの列挙に分け、適用は操作ごとの名前のある処理にする

応答(`command::応答`)は、ファイル・動画の手がかり・クリップ・クロップ枠・出力・再生・FFmpeg・ライブラリの8つの列挙を束ねる。
最上位の `操作の適用係::適用する` は束ねた列挙を振り分けるだけにし、状態だけで決まる操作は `アプリの状態` の
メソッド、外界(ファイルダイアログ・ファイル・FFmpeg)に触る操作は依存をコンストラクタで保持した係のメソッドで適用する。
状態は処理の対象であって依存ではないため、係のメソッドへ毎回 `&mut アプリの状態` として渡す。

### 判断2: 同時に生まれて同時に消えるものは `読み込んだ動画` 1つにまとめる

動画の情報(倉庫が保持する)・コマの倉庫・流し読み・テクスチャ・依頼の台帳・載せたコマの番号と寸法・動画の音(音の倉庫と音の流し読み)は、動画を開いたときに
一緒に作り、動画を解除したとき・別の動画を開いたときに一緒に捨てる。状態は `Option<読み込んだ動画>` 1つで持つ。

### 判断3: テクスチャを載せ直すかは、載せたコマの番号と寸法で決め、読み込み直しは型の寿命で区別する

`アーキテクチャ.md` 判断1-4の申し送りは、載せ直すかを決める比較に「動画を読み込み直したこと」の区別を含めることを求めている。
本アプリは載せたコマの番号と寸法を `読み込んだ動画` の中に置き、動画を読み込み直すとそれごと作り直す。そのため新しい動画の
最初のコマは必ず載せ直され、別の動画の同じ番号のコマを同じとみなすことは構造的に起きない。溜めたコマと流し読みは
同じ `読み込んだ動画` の同じ長辺の上限で読むため、出どころが変わっても番号と寸法が同じなら同じ画像である。

### 判断4: 先読みの依頼は台帳が決め、失敗と断られた区間を覚える

依頼の台帳は、毎フレーム渡される先読みの並び(再生中のクリップ → 次 → 残りの順の区間)と自分の行を比べ、
捨てる区間・依頼する区間・渡し直す保持の優先順を決める(純粋な判断。倉庫への呼び出しは `読み込んだ動画` が行う)。

- 並びから消えた区間(編集で区間が変わった等)は、すぐに破棄を依頼する
- 新しい区間の依頼は、区間の集まりが変わってから 0.4 秒たつまで出さない。区間の数値を続けて変えている間に
  ffmpeg の起動と停止を毎フレーム繰り返さないためである。並びの順だけが変わったときは待たない。
  カードの区間の帯のドラッグの間は区間を仮の値で持ち、クリップスタックを変えないため、並びも変わらない(判断11)
- 失敗した区間と、区間にコマが無い・上限の全体を超える区間は、並びに残る限り依頼し直さない
- 優先順の高い区間で埋まっていた区間・倉庫が捨てた区間・取り消された区間・倉庫が覚えていない(知らない札の)区間は、並びの順が変わったとき(再生中のクリップが変わったとき等)に依頼し直す
- 落ち着くのを待っている間も、画面は入力が無くても描き直す。止めた状態で区間を編集したり設定ファイルを読み込んだりした後も、待ち終えた時点で依頼が出る
- 表示するコマは、区間を溜め終えていれば倉庫から、そうでなければ流し読みから取り出す

### 判断5: 流し読みは、求める位置が戻ったか2秒より先へ飛んだときに開き直す

流し読みは前へしか読めない(`アーキテクチャ.md` 判断1-3)。求める位置が最後に求めた位置より前へ戻ったとき(区間の繰り返し・
シーク)と、2秒より先へ飛んだとき(読み進めるより開き直す方が早い)に開き直す。開けなかったときも同じ規則で扱い、
毎フレーム開き直さない。

- 再生位置の帯(シークバー)をドラッグしている間(`位置を動かしている`)は、
  再生位置だけを動かし、流し読みは開き直さない。開き直しを控えている間は、流し読みに位置を覚えさせない。
  覚えさせると、放した次のフレームで「戻っていない」と判定され、後ろへのシークで古いコマのまま止まるためである。
  開き直しは放したとき(`位置を決めた`)の次のフレームで行う
- カードの区間の帯をドラッグしている間は、逆に映像の流し読みを開き直してよい(掴んだものの位置のコマを映すため。判断11)。
  開き直しの最短の間隔と、前へ2秒以内なら読み進める規則はそのまま効くため、ffmpeg をフレームの頻度で起動し直さない。
  音の流し読みは区間の帯のドラッグの間は開き直さない(音は黙っているため)
- 開き直しの間隔は最短 0.25 秒とする。求める位置が毎フレーム戻っても、ffmpeg をフレームの頻度で起動し直さないためである。
  間隔を待つ間は流し読みのコマを待っているとして描き直しを続ける
- 左右キーのコマ送りは1回ごとの確定した操作として扱う
- 区間の終わりちょうどやそれより後ろ(末尾で止めたとき)は、流し読みに区間の中の最後のコマの真ん中の時刻を求める。
  終わりの時刻をそのまま求めると、終わりの時刻から表示が始まる区間の外のコマが出るためである

### 判断6: 割合(0〜1)と百分率(0〜100)の受け渡しは `view/conversion.rs` の1箇所で行う

クロップ範囲(百分率)から描く部分(割合で表した矩形)への変換と、範囲枠の移動量(割合の差)からクロップの移動量
(百分率の差分)への変換を、同じファイルに置く。百分率を100で割って0〜1の f64 にするのは `clip_domain` の `百分率::割合()` である。
`view/conversion.rs` は割った後の値を SengenEgui の `割合::倍精度の小数から範囲へ丸めて生成する` へ渡して割合にする。SengenEgui の口が
受け取るのは0〜1の値であり、f64 から f32 への丸めもこの口が行う(lint が `as` を禁じるため)。逆向きは、`割合の差` の値を f64 へ広げて
100を掛け、`百分率の差分::作成する` へ渡す。出力とプレビューの寸法は、ドメインの `縦横比` と
同じ f64 で計算し、結果だけを `論理画素::倍精度の小数から生成する` で論理画素へ包む。縦横比を保って収める・覆う計算は両方が使うため
`view/aspect_fit.rs` に置き、出力に固有の式(縁の余白・最小の寸法・表示サイズごとの選び方)は `view/output/size.rs` に、
プレビューに固有の式(負の最大を0へ揃える・論理画素の整数へ切り捨てる)は `view/sidebar/preview.rs` に置く。

### 判断7: 時刻は配線の1箇所で読み、FFmpeg の置き場所は環境変数か保存した設定のどちらか1つを探してから PATH を探す

`Instant::now` はフレームの手順の最初に1回だけ読み、時計・台帳へ渡す。FFmpeg の置き場所は、環境変数
`CLIPVIEWER_FFMPEG_DIR` があればそれを、無ければ `%APPDATA%\ClipViewer\settings.json` に保存したフォルダを
`video_source` の「設定の場所」として渡し、その後に PATH を探す(`アーキテクチャ.md` 判断2)。環境変数があるときは、保存したフォルダを探さない。見つからなければ画面の上部に
理由と手順を出し、フォルダを入力して保存し探し直せる。

### 判断8: 出力の寸法は移植元の計算を写し、表示の途中で黙って縮めない

出力の幅と高さは、使える大きさ・縦横比・表示サイズから移植元と同じ式で求める純粋な関数で決める。描く部分の切り出しと
引き伸ばしは GPU の描画で行い、溜めたコマそのものは縮め直さない。

### 判断9: 区画の地は移植元の配色を写し、プレビューはサイドバーの幅に合わせる

ヘッダー・左サイドバー・出力の帯・出力・再生コントロールの各パネルへ、SengenEgui の `パネル(…).装飾(スタイル)` で移植元の地の色を付ける
(値は `view/styles/palette.rs`、区画ごとの装飾は `view/styles/area.rs`)。出力の帯を区画の幅いっぱいに塗るため、出力の区画の中を
上のパネル(出力の帯)と中央のパネル(出力の画面)に分ける。シアターでは出力の地を黒にし、出力に重ねる操作の欄の地を半透明の黒にする(判断12)。
プレビューは `使える大きさから組む` の中で、サイドバーの使える幅から範囲枠の周りの余白を除いた幅と、移植元の枠の内側の高さ(264論理画素)の
中へ、動画の元の寸法の縦横比で収める。
琥珀色の地のボタン(ヘッダーの選ばれている構えのボタンと「JSON保存」、再生ボタン、「新規Clipを追加」などの `styles::強調ボタン`)は、
移植元の強調ボタンとモードボタンと同じく、地を #d97706 に、文字を #020617 にする。ヘッダーの構え(編集・シアター・ライブラリ)の切り替えは SengenEgui の
選択ボタンを使わず、ボタンに今の構えに応じて `styles::強調ボタン` を付ける。選択ボタンは選ばれた面を強調色(琥珀色)で塗り、
文字をテーマの文字色から導いた明るい色で描くため、文字が読めないからである(SengenEgui の版 68d5953 から、選択ボタンと選択欄の一覧の選ばれた項目の文字は
テーマの `強調色の上の文字色` で描かれる。本アプリはテーマにこれを #020617 と指定し、トリガー等の選択欄の選ばれた項目を読めるようにしている)。削除と解除の `styles::危険ボタン` は移植元どおり
部品の面の色(#1e293b)の地に淡い赤(#fda4af)の文字である。ヘッダーには移植元にあった版の札(「v4.0 Professional」)と
機能の紹介文を出さない。本アプリの版でも機能の説明でもないためである。移植元のアプリ名の文字(「Smart Clip Stack Player」)も、オーナーの裁定により出さない。

### 判断10: 音は映像と同じ先読みの並びで溜め、毎フレーム状態から再生の指示を組み立てて渡す

音の層と同期の方式は `アーキテクチャ.md` 判断8が正本であり、本節は `clip_viewer` の内側の配置だけを定める。

- 起動時に `app/` の音の送り手が既定の音声出力装置を開く。開けなければ通知と再生コントロールの「音: 鳴らせない(理由)」で知らせ、
  音の送り手は何もしない送り手になる(映像だけで再生を続ける)。動画の開き手は開いた装置の周波数を持ち、動画を開くときに調べた動画の情報の
  音の有無(映像と一緒に ffprobe の1回の呼び出しで調べる)を見て音の倉庫を開く。音が無い動画は「音: この動画には音が無い」を出す
- 動画の音は `読み込んだ動画` の中に置き、動画と一緒に作って一緒に捨てる(判断2と同じ)
- 1フレームの手順では、映像の先読みの後に、映像の依頼の台帳が落ち着いていれば(判断4の0.4秒)同じ並びを音の倉庫へ渡し、
  今の区間を溜め終えていなければ映像と同じ規則(判断5)で音の流し読みを開き直す。その後、配線が状態から再生の指示を組み立てて渡す
- 再生の指示の区間は表示するコマの求めの区間(元動画再生は動画の全体)であり、出どころは溜めた音、無ければ開いている流し読みである。
  区間の終わりの行き先は `clip_domain` の `再生位置::区間の終わりの行き先` で求め、次の区間の出どころは溜めた音だけを渡す
- 再生位置の帯をドラッグしている間は止めている指示にして黙らせる。位置を移す操作は `再生の状況::位置を移す` を通り、
  位置を飛ばした回数を進める
- 出力の途中で装置が使えなくなったら、音の送り手が状態の音の出力の状況を「使えない」にして通知を出す

### 判断11: クリップカードは区間の帯を主役にし、区間の帯のドラッグの間は掴んだものの位置のコマを映す

オーナーの試用で、開始と終了を別々のスライダーで決める形では、クリップが動画のどこからどこまでかを把握できないと判定された。
カードは SengenEgui の `区間の帯`(1本の帯に区間と開始・終了のつまみと位置の印を重ねる部品)を2本置き、区間を帯で決める。
開始と終了の2本のスライダーは置かない。

**区間の帯の2本。** カードの区間の帯は次の2本である。どちらも値の単位は動画上の秒であり、同じ規則で操作を状態へ当てる。

| 帯 | 全体の範囲(帯の左端〜右端) | 置く理由 |
|---|---|---|
| 全体の帯 | 0秒〜区間の上限(動画があれば動画の長さ。判断4の上限と同じ) | 動画全体の中でクリップがどこにあるかを見せる |
| 拡大の帯 | 区間の前後に余白(区間の長さの半分と2秒の大きい方)を足し、0秒〜区間の上限へ収めた範囲 | 長い動画の短いクリップ(30分の動画の1秒は全体の帯の幅の0.05%)を細かく動かす |

- 拡大の帯の範囲が全体の帯の範囲と同じになるとき(短い動画)は、拡大の帯を出さない。同じ帯が2本並ぶだけだからである
- 拡大の帯の範囲は掴み始めに決めて、放すまで変えない。ドラッグの間に範囲が動くと、つまみがポインタから逃げるためである。放すと、決めた区間から求め直す
- 拡大の帯の上に、範囲の秒数を「拡大 12.30〜18.40秒」の形で出す。範囲が区間に合わせて変わることを、人が見て分かるようにするためである

**区間が動画の外にあるとき。** 別の動画の設定ファイルを読み込んだ等で区間の終了が動画の終わりより後ろにあるときは、全体の帯の上に
「区間(…秒)が動画の終わり(…秒)より後ろまである」の注意を出し、拡大の帯は出さない。SengenEgui は範囲の外の値を区間の帯の端に外を指す三角で描くため、
全体の帯の上でも区間が範囲の外へはみ出していることが見える。

**位置の印。** 選ばれているカードの2本の帯に、再生の今の動画上の位置(表示するコマの求めの動画上の位置。区間の帯のドラッグのプレビューに
置き換える前の位置)を描く。拡大の帯には、位置が範囲の内側にあるときだけ描く。部品は範囲の外の値を区間の帯の端に描くため、
範囲の外の位置を渡すと、その位置が範囲の端にあるように見えてしまう。選ばれていないカードには位置の印を描かない。

**区間の帯のドラッグ。** 状態は、区間の帯を掴んでから放すまでの間だけ `区間の帯のドラッグ`(掴んだクリップ・掴んだ帯(全体の帯か拡大の帯か)・掴んだもの・
掴んだときの値と仮の値(それぞれ区間と位置の組)・拡大の帯の範囲・区間を動かす決まり・掴む前に再生していたか)を持つ。
拡大の帯の範囲と区間を動かす決まりは、掴み始めに決めて放すまで変えない。動かしていると放したは、今のドラッグと同じクリップの同じ区間の帯のものだけを当てる。ドラッグの間は区間を仮の値で持ち、クリップスタックを書き換えない。書き換えると
先読みの並びから元の区間が消え、溜めたコマをすぐに捨てるためである(判断4)。区間の端を動かす規則(0秒から上限へ収める・開始と終了の
間を0.05秒以上に保つ・長さを保って動かす)は `clip_domain` の `区間の編集の決まり` が持ち、カードの数値入力とずらすボタンも同じ決まりを使う。
区間の帯から受け取る秒は0.01秒の倍数へ丸め、丸めた秒が上限を超えるときは上限以下で最大の0.01秒の倍数にする
(`区間の編集の決まり::刻みへ丸めて上限の内側へ収める`)。数値入力が小数点以下2桁で出すため、丸めないと数値の表示と区間の値が食い違う。
丸めるのは区間の帯から受け取った秒だけであり、決まりの上限そのものは丸めない。そのため、区間の帯で動かさなかった端は変えない
(数値入力で終了を動画の長さ 10.047秒に合わせた後に開始のつまみを動かしても、終了は 10.047秒のままである)。
終了のつまみを右端まで動かすと、終了は上限以下で最大の0.01秒の倍数(この例では 10.04秒)になる。
区間の終了が上限を超えたかの判定は 1e-6秒の超過を許す。小数の計算で終了が上限を1ulp超えても、動画の外とみなさないためである。
秒の数値入力に打ち込んだ値と ±0.5s・±1コマのボタンで決めた値は、状態の側では丸めない。1コマ(30コマ/秒なら約0.0333秒)は0.01秒の倍数でないため、丸めるとコマ送りがずれる。
そのため ±1コマで決めた値は、数値入力の表示と最大0.005秒食い違う。秒の数値入力をドラッグか ↑・↓ キーで変えた値は、egui の数値入力が表示の桁(小数点以下2桁)へ丸めて渡すため、0.01秒の倍数になる。
区間の内側のドラッグは開始だけを0.01秒の倍数へ丸め、終了は開始に掴んだときの長さを足した位置にするため、終了は丸めない。
SengenEgui の区間の帯は、発する値を全体の範囲と掴み始めの値を合わせた範囲に収めるだけであり、全体の範囲の内側とは限らない。
0秒から上限の間へ収めるのは `区間の編集の決まり` である。

**操作契約。** 区間の帯の操作と、画面に返るものは次のとおりである。部品は掴み始め・動かしている(値が変わったときだけ)・放した(必ず)の3段階で
掴んだものと値を発する。

| 掴んだもの | 動かしている間に帯へ描く値 | 動かしている間にプレビューと出力へ映すコマ | 放したときに決めるもの |
|---|---|---|---|
| 開始のつまみ | 開始 = 値(0〜上限へ収め、終了より0.05秒以上前) | 新しい開始の位置のコマ | 区間 |
| 終了のつまみ | 終了 = 値(上限以下へ収め、開始より0.05秒以上後ろ) | 新しい区間の中の最後のコマ(終了の直前のコマ) | 区間 |
| 区間の内側 | 開始 = 値、終了 = 値 + 掴んだときの区間の長さ(終了が上限を超えるなら上限で止める) | 新しい開始の位置のコマ | 区間 |
| 位置の印(区間の外を押したときも) | 位置 = 値を今の再生モードの写し方で収めた位置 | 収めた位置のコマ | 再生位置 |

- 掴み始めたとき: まず再生していたかを覚える。次にそのカードのクリップを選ぶ。選ぶクリップが変わるときは、カードを押したときと
  同じ規則(4節の操作の対応表の「カードを押す」)で再生位置を合わせる。止めているシーケンス再生なら再生位置をそのクリップの開始へ移し、
  プレビューの絵と枠を同じクリップにする。再生中のシーケンス再生では再生位置を動かさない(時計を止める前に選ぶのはこのためである)。
  選ばれているカードなら選び直さないので、単独クリップ再生の経過も0へ戻らない。最後に再生の時計を止める
- 区間の帯で開始だけを動かしたときは終了を変えず、終了だけを動かしたときは開始を変えない
- 動かしている間: 時計が止まっているので音は黙る(再生位置の帯のドラッグと同じ)。映像は判断5のとおり流し読みを開き直してよい。
  映すコマのクロップは、シーケンス再生と単独クリップ再生ではそのクリップのクロップであり、元動画再生では全体である(元動画再生はクロップを掛けない)。
  位置の印を動かしている間は、シーケンス再生と単独クリップ再生では位置をクリップの区間の中に収めてあるため、そのクリップの区間のコマとして求める。
  映像と音の様子の行は、そのクリップの区間の様子を出し、元動画再生の文(「元動画を流し読みで再生中」)を出さない。元動画再生では区間を持たずに求める
- 放したとき: 区間を決めたなら、区間が変わった場合だけ再生位置をそのクリップの開始へ移す(カードの「先頭へ」と同じ移し方)。
  変わった区間は判断4の規則で溜め直し、溜め終えるまで流し読みで映す。位置の印なら再生位置を下の写し方で移す。
  どちらも、掴む前に再生していたなら再生を再開する。部品は掴んだだけで放したときも今の値を発するが、状態は放したときの値を使わず、
  最後に動かした値で決め、掴んだときから変わっていなければ何も決めない
- 安全網: 応答を適用した後に主ボタンを押していないのに区間の帯のドラッグが残っていたら(放したを受け取る前に帯が描かれなくなった等)、
  仮の値を決めずに捨て、掴む前に再生していたなら再生を戻す。時計が止まったまま・プレビューが固定されたままになるのを防ぐ

**位置の写し方。** 位置の印が指した動画上の位置から、今の再生モードの再生位置への写し方は次のとおりである。

| 再生モード | 収め方 | 写した再生位置 |
|---|---|---|
| シーケンス再生 | 区間の開始から、区間の中の最後のコマの始まり(終了 − 1コマ)までへ収める | そのクリップのタイムライン上の開始位置 + (位置 − 区間の開始)。最初の周回を指す。クリップが再生できない(無効か長さ0)なら移さずに通知を出す |
| 単独クリップ再生 | シーケンス再生と同じ | 区間の開始からの経過 = 位置 − 区間の開始 |
| 元動画再生 | 収めない | 元の動画の位置そのもの |

区間の中の最後のコマまでで止めるのは、区間の終了ちょうどが、シーケンス再生では次のクリップの先頭、単独クリップ再生では区間の先頭を指すためである。

**1つのクリップのプレビュー。** カードの「このクリップを再生」は、再生モードを単独クリップ再生にし、そのクリップを選び、区間の開始から再生を始める。
単独クリップ再生でそのクリップを再生している間は、ボタンを琥珀色の地の「単独再生を止める」にし、押すと再生を止める(モードと位置は変えない)。
動画が無いときは再生せず、通知で動画のロードを促す。複数のクリップを積んで通して見るときは、出力の帯の再生モードをシーケンス再生へ戻す。

**カードの並び。** カードは上から、見出しの行(有効・名前・「このクリップを再生」・「先頭へ」・削除)、全体の帯、拡大の範囲の文字と拡大の帯、
開始の行と終了の行(どちらも 端の名前・-0.5s・< F・秒の数値入力・F >・+0.5s)、繰り返しとトリガーの行の順に並べる。
開始と終了のそれぞれに前へと後ろへの両方のずらすボタンを置き、区間を縮められるようにする(オーナーの決定)。8つのボタンと2つの数値入力を1行に並べると、
サイドバーの最小の幅(480論理画素)に収まらないため、端ごとに1行へ分ける。
1行の幅は、日本語フォントとテーマを当てた試験の描画で約282論理画素である。
見出しの行の有効のチェックボックスには文字「有効」を付ける(オーナーの決定)。名前の欄は、見出しの行の残りの幅いっぱいに広げ、ただし枠の内側を120論理画素より狭くしない(オーナーの決定)。
残りの幅を名前の欄へ渡すため、見出しの行は SengenEgui の横並びの `残りの幅を渡す` で、名前の欄に後ろの3つのボタンを置いた残りの幅を渡す。
名前の欄は SengenEgui の一行テキスト入力の `幅いっぱい` と `最小幅` で広げる。子を左から右へ描くため、Tab キーでフォーカスが移る順は見えている並び(有効 → 名前 → 再生 → 先頭へ → 削除)と同じである(オーナーの決定。右寄せの横並びで残りの幅を作ると、描く順が逆になり Tab の順も逆になる)。
`view/sidebar/clip_card/card_width_tests.rs` が、サイドバーの中身に使える幅(サイドバーの幅から内余白を引いた幅)の中にカードを描き、サイドバーが最小の幅(480論理画素)のとき
カードが456論理画素に収まり、見出しの行の部品が重ならず、名前の欄の枠の内側が120論理画素以上あること(今は約123論理画素)と、最大の幅(610論理画素)へ広げると名前の欄が広げた幅の分だけ広がることを確かめる。
パネルは中身がはみ出した幅を覚えて広がるため、`view/sidebar/clip_card/sidebar_width_tests.rs` が画面と同じ左サイドバーのパネルにカードを並べて描き、
最初の回・カードを足した回・1枚だけ単独再生にした回のどれでもパネルの幅が480論理画素のままであることを確かめる。
SengenEgui の `残りの幅を渡す` は、後ろの子の幅を同じ回の中で見えない Ui へ描いて測るため、どの回でも行がサイドバーの幅を超えない。帯の地は最も濃い地(#020617)、

### 判断12: シアターでは出力をウインドウ全体に広げ、操作の欄を出力の下端に重ねて、マウスを操作したときだけ出す

オーナーの要望(2026-09-26)は、シアターで下に操作の部品が残るせいで動画がウインドウ全体にならないので、操作の部品を映像の上に重ねて出すことである。
本アプリは、シアターでは再生コントロールを下のパネルに置かない。出力だけをウインドウ全体に置き、再生コントロールの中身(時刻とステータスの行・
再生位置の帯・再生の操作と速度・音量・全体ループの行・供給の様子・音の様子)を、出力の画面の下端に幅いっぱいで重ねる(`view/output/theater_controls.rs`)。

- **出力の寸法。** シアターの出力は、縁の余白を置かず、ウインドウ全体の使える大きさへ縦横比を保って収める。移植元の「シアター高さ基準」
  (使える高さいっぱいにし、幅は高さから求める)は写さない。高さ基準では、ウインドウの縦横比より横長の動画の左右がウインドウからはみ出して切れるためである。
  ウインドウ全体に広げる目的は動画の全体を大きく見せることであり、切れる形はその目的に反する
- **操作の欄の地。** 半透明の黒(不透明度190/255)の単色で塗る。移植元は下端0.88から上端0へ薄くなる黒の濃淡だが、SengenEgui のスタイルは
  濃淡を描けない。単色の濃さは濃淡の中ほどにした
- **出し入れ。** 移植元の操作の欄は常に出ている。本アプリは動画サイト(YouTube 等)の再生画面に揃え、欄を出すのはマウスを操作したときだけにする。
  オーナーの要望(2026-09-27)は、欄がずっと重なって出ているのが不満なので、マウスを操作したときだけにし、普通の動画サイトを見習うことである。規則は次のとおりである。
  - 欄を出すのは、出力の上でマウスを実際に動かしたとき(最後に動いたと数えた位置から3論理画素以上。同じ位置への移動の知らせは数えない)と、
    出力の上で押したときと、左右キーを押している間である。出力を押したこと(トリガーのクリック待ちの操作)もマウスの操作として数えるため、押すと欄が出る
  - マウスが止まってから2.5秒で隠す。一時停止している間も隠す。欄の上にマウスがあっても、止まれば隠す。
    欄の中で押し始めたドラッグ(再生位置の帯・速度・音量のつまみ)の間だけは隠さない
  - マウスがウインドウの外へ出たら、時間を待たずに隠す
  - 規則は SengenEgui の `ポインタが止まると隠して上に置く`(`ポインタが止まると隠す指定`)が持ち、本アプリは隠すまでの時間と、欄を出すキー(左右)と、
    カーソルも隠すことと、組だけを渡す。`出したままにする` の指定は使わない

  変更前の規則(2026-09-26)は、欄の上にマウスがある間と一時停止している間は出したままにしていた。欄がずっと出ていた原因はこの2つである。
  シアターの下端は欄が占めるため、欄の再生ボタン等を押した後はマウスが欄の上に止まったままになり、再生していても欄が消えなかった。
  止めている間は、マウスをどこに置いても欄が消えなかった。egui の入力を合成した試験では、マウスを欄の外で止めて時間だけ進めると、変更前の規則でも欄は隠れた。
  Windows で動かしていないのに同じ位置への移動の知らせが届く経路は、winit(0.30.13)が同じ位置の WM_MOUSEMOVE を捨てているため、原因ではない。
  ただし他の環境やタッチパッドでの小さな揺れに備え、3論理画素未満の移動を数えない規則を SengenEgui に置いた。

  揃えた動画サイトの挙動と、その判断の確かさは次のとおりである(ウェブで調べておらず、記憶に基づく推測を含む)。
  - YouTube は、マウスを動かすと操作の欄を出し、止めて数秒で隠し、マウスがプレーヤーの外へ出るとすぐ隠す。隠すまでの時間は約2.5〜3秒である(推測)
  - YouTube は左右キーで位置を移すと操作の欄を一瞬出す。本アプリの左右キーはコマ送りであり、送った先の再生位置を欄の帯で見せるため、押している間は出す。
    Enter(次のクリップへ進める)と Space(再生と停止)は見ている最中に繰り返し押すため、押しても欄を出さない(出すと押すたびに映像が欄に隠れる)
  - 一時停止中の YouTube は操作の欄を出したままにする場合がある(推測)。本アプリはオーナーの要望「マウス操作したときだけ」に従い、一時停止中も隠す
  - 欄の上にマウスを止めたときに YouTube が隠すかは確かめていない(出したままにする可能性がある。推測)。本アプリは隠す。シアターでは欄を押した後に
    マウスが欄の上に残りやすく、欄の上を例外にすると要望の不満がそのまま残るためである
- **カーソル。** 欄を隠している間は、出力の上のマウスのカーソルも隠す。動画を見ている間にカーソルが映像の上に残らないようにするためである。
  マウスを動かせば欄とカーソルが同時に戻る
- **キー操作。** キー操作(判断14「キーの割り当て」)は画面の木の最初の見えない部品にあり、欄の出し入れと関係なく効く。T キーはシアターから編集の構えへ戻す(編集の構えではシアターへ入る)。Space・Enter と同じく、押しても欄を出さない。左右キーは(Shift を押していても)押している間だけ欄も出す
- **Next Clip とトリガー待ちの札。** 編集の構えでは Next Clip を出力の右下、トリガー待ちの札を下の辺に置くが、シアターでは下端を操作の欄が占める。
  Next Clip は操作の欄の最上段の右端へ移し、欄と一緒に出し入れする。トリガー待ちの札(札の中にも Next Clip がある)は上の辺へ置き、欄を隠しても出したままにする
- **編集へ戻る。** 右上に出し、操作の欄と同じ組(SengenEgui の `ポインタが止まると隠す組`)で出し入れする(操作の欄と同じ規則で出し、止めて2.5秒で隠す)。移植元は出力の上にマウスを
  乗せている間だけ出すが、シアターでは出力がウインドウ全体なので、その規則ではマウスがウインドウの中にある限り出たままになり、欄とカーソルを隠しても右上に残るためである。
  操作の欄と編集へ戻るは同じ組で出し入れする。組にした子は出し入れの記憶を1つ共有し、「子の上で押し始めたか」を組の全ての子の矩形の和で判定するため、
  欄のつまみをドラッグしている間は編集へ戻るも出たままになり、隠すときは欄と編集へ戻るとカーソルが一緒に隠れる。
  組の出し入れはその回に組の中で最初に描く子の指定で決まるため、指定は出力の区画が1つ作って両方へ渡す(`view/output/mod.rs`)
- **動画が無いとき。** 動画が無いシアターでは、出力の画面の代わりに動画の無い案内を出すため、右上の編集へ戻るも操作の欄も出ない。
  案内に、戻り方の文(「編集へ戻る」か Escape キー)と「編集へ戻る」のボタンを足し、出し入れせずに出したままにする(`view/output/placeholder.rs`。オーナーの決定)
  サイドバーが見えないため、動画の開き方の文は編集の構えの「左の「動画を開く」か、…」でなく、見えている部品だけを指す文(ウインドウへ落とせば開ける)にする。編集へ戻る話は、その下の戻り方の文だけで伝え、2回書かない(オーナーの決定)

### 判断13: 各起動で独立したウインドウを作り、複数の動画を別々に再生する

エクスプローラーで動画を開くと、OS は `clip_viewer.exe "<動画のパス>"` を起動する。各アプリは自分のウインドウを作って引数の動画を開き、既に起動しているアプリへ頼みを送らない。引数の無い起動も、新しいウインドウを作る。配線の `起動の手順::決める` は必ず `起動の準備` を返し、起動の部分はその準備でウインドウを作る。

起動の手順は、共有データを守るため、ウインドウを作る前にライブラリの錠を試す(`clip_library` の `錠を試したライブラリ`)。錠を持つアプリだけがライブラリと見る側の設定と警告の記録を書き、ほかのアプリはライブラリを読み取り専用で開く(`ライブラリ.md` 判断9)。各アプリは、自分の動画・スタック・再生位置・音量を持ち、動画再生と編集と JSON保存を独立して行える。錠を取れなくても、起動の手順は受け渡しの期限を待たず、引数の動画をほかのアプリへ渡さない。

| 起動したときの様子 | 起動の手順が行うこと |
|---|---|
| 錠を取れた | ライブラリを書ける状態で起動し、引数の動画を自分で開く。以前の版からの受け渡しを受け取る口を開く |
| 錠を取れない(ほかのアプリが持っている・錠を作れない等) | ライブラリを読み取り専用で開いて起動し、引数の動画を自分で開く。受け取る口は開かない |
| ライブラリの置き場所が無い | ライブラリを使わずに起動し、引数の動画を自分で開く |
| 錠を持つアプリが終わった後 | 次に起動したアプリが錠を取り、ライブラリを書ける状態で起動する。既に読み取り専用で起動していたアプリは、そのままである |

**以前の版との互換。** 以前の版のアプリは、後から起動したときに動画を錠を持つアプリへ渡す。`ライブラリ.md` 8節の互換の規則を保つため、錠を持つアプリは受け口と `%APPDATA%\ClipViewer\launch.json` の案内を維持する。現在の版は案内を読んで送らず、送り手は以前の版との通信を確かめる試験だけに含める。環境変数 APPDATA を別のフォルダにしたアプリは別のライブラリと受け口を使う。

**受け渡しの方式。** 受け口は、この計算機の中だけ(127.0.0.1)の TCP のポートで待つ。ポートは OS が空いているものを選び、案内のファイルへポートと
合言葉(OS の乱数から作った128ビットの文字の並び)を書く。以前の版の送り手は案内を読んでつなぎ、合言葉と頼みを1行の JSON で送り、1つ目は合言葉が合えば
「received」の1行を返す。比べた方式と選ばなかった理由は次のとおりである。

- 名前付きパイプ: Windows の標準の方式だが、Rust の標準ライブラリにはパイプを待つ側の口が無い。unsafe を全面禁止しているため OS の関数を直接呼べず、
  依存(tokio や interprocess 等)を足すことになる。Windows 以外では別の実装(Unix ドメインソケット)が要る
- ファイルの見張り: 2つ目が頼みのファイルを置き、1つ目が一定の間隔で見る方式は標準ライブラリだけで書けるが、1つ目が受け取ったかを2つ目が知るには
  返事のファイルを別に置いて見張ることになり、期限の判定と書きかけのファイルの扱いが複雑になる。見る間隔の分だけ遅れる
- この計算機の中だけの TCP: 標準ライブラリ(`std::net`)だけで書け、unsafe も依存の追加も要らず、Windows 以外でも同じコードで動く。つなぐ・読む・書くの
  それぞれに期限を置けるため、「受け取った」の返事で届いたことを確かめられる。127.0.0.1 だけで待つため、Windows のファイアウォールの許可を求めるメッセージボックスは出ない。
  この計算機のほかの利用者やプログラムもポートへはつなげるため、利用者ごとのフォルダにある案内のファイルの合言葉で受け付ける相手を限る

**受け取った頼みの当て方。** 受け口の裏のスレッドは、頼みを通り道(`mpsc`)へ入れて egui へ描き直しを頼むだけにし、状態に触らない。画面のスレッドは
1フレームの手順の応答の適用の後に頼みを取り出し、動画を開く頼みはウインドウへ落とした動画と同じく `操作の適用係::確かめてから動画を開く` で開く。そのため、
開いているスタックとの関係を終える前の確かめ(未登録の並びを捨てるかのダイアログ。判断14)も同じに通り、ライブラリの構えなら編集の構えへ移る。
「複数の動画が渡されたため、最初の1つだけを開いた」は、動画を開いたときだけ書き足す。確かめるダイアログを経て「変更を捨てて続ける」「並びを捨てて続ける」で開いたときも書き足すため、
確かめるダイアログが持つ続ける操作(`関係を終える操作::動画を開く`)がこの添え書きを持つ。確かめるダイアログでやめたときと開けなかったときは何も開いていないため書き足さない。
頼みが届いたときにダイアログ(ライブラリのダイアログ(確かめるダイアログ・名前を付けて登録するダイアログなど)とキーの一覧のダイアログ)を開いていれば、開いているダイアログを上書きしないよう動画を開かず、
「開いているダイアログを閉じてから、もう一度開いてください」と知らせてウインドウを前に出すだけにする。頼みが届いたフレームでは、ウインドウへの指示の並びに「前に出す」を入れ、
起動の部分が最小化を戻してウインドウを前に出す(`ViewportCommand::Minimized(false)` と `Focus`)。閉じる・閉じるのを取り消すの指示は前に出すより先にする。

**引数の扱い。** 引数はすべて動画のパスとして扱う。複数あれば最初の1つだけを開き、「複数の動画が渡されたため、最初の1つだけを開いた(ほかのN個は開いていない)」を
開いた結果の通知へ書き足す。パスが無い・読めない・動画でないときは、既存の動画を開く経路が理由を通知に出し、アプリは普通に起動したままである。
エクスプローラーで複数の動画を選んで開くと、OS は動画ごとにアプリを起動し、各アプリは別々のウインドウでその動画を開く。

### 判断14: 編集の操作は、並びの変化を毎フレーム1箇所で見て取り消せるようにし、並びを捨てる前に登録していない変更を確かめる

v0.1.0 の公開前のレビューとオーナーの決定(2026-09-27)から、編集の操作を次のとおり定める。どの操作も、クリップスタックの規則は `clip_domain` が持ち、
状態の組み合わせは `state/` が、操作の振り分けは `command/` が持つ。

**並びの置き換え。** 動画を開く(並びを残さないとき)・動画を解除する・設定ファイルを読み込む(JSON読込と落とした JSON)・ライブラリから開くは、クリップの並びを丸ごと置き換える。
置き換えは `アプリの状態::並びを置き換える`(`state/stack_replace.rs`)の1つだけを通し、開いているスタックとの関係を終える・クロップ枠と区間の帯のドラッグを捨てる・
編集の履歴を新しい並びから始め直す・再生位置を今の再生モードの先頭へ戻す、の4つを必ず揃えて行う。それぞれの呼び出し元に同じ手順を書き写さないためである
(以前は3箇所に書き写してあり、ドラッグの捨て方がずれていた)。置き換えるときは、新しい並びをこの場で作ったか、ファイル(設定ファイルかライブラリ)から読んだか
(並びの出どころ)も起点として覚える。

**動画を開いたときの並び。** 動画を開くと、今の並びを残すか、最初のクリップ1つ(先頭から10秒。動画がそれより短ければ動画の長さ)の新しい並びで始めるかを決める。
並びを残すのは、並びが空でなく、並びを作った動画(設定ファイルが期待する動画か、最後に開いた動画)のファイル名が開く動画と同じとき(大文字と小文字は区別しない)と、
期待する動画が分からないとき(動画の名前を持たない設定ファイルを読んだ後)である。別の動画の区間を新しい動画のパスでライブラリへ登録しないためである。
並びを残すときは並びを置き換えない。並び・編集の履歴と起点を引き継ぎ、動画だけを開き直して先頭のクリップを選び、取り消しのまとめを区切り、
ドラッグを捨てて再生位置を先頭へ戻す(`並びを残して動画を開き直す`)。起点を編集した後の並びへ置き換えると、その後に閉じる・解除する・JSON読込をしたときに
確かめるダイアログが出ずに編集が消えるためである。開いているスタックとの関係は、未登録なら関係が無いので確かめない。登録済みなら、スタックの動画のパス全体が
開く動画のパスと同じときだけ保ち、関係を終える前の確かめもしない(関係を終えるのは別の並びで上書きしてしまうからであり、同じ動画ならその理由は当たらない)。
ファイル名が同じでもフォルダが違えば(IMG_0001.MOV のように同じ名前の別の動画がありうる)、関係を終える前の確かめ(保存を確かめ、書けなければダイアログを出す)を通し、
並びは残して関係を終え、起点を今の並び(ライブラリのファイルに書けた並び)に置き直す。そのまま関係を保つと、別の動画に合わせて直した区間が古いパスのスタックへ
自動で上書き保存されるためである。スタックのパスを書き換えないのは、別の動画だったときにスタックを壊すためである。開いた後は、ライブラリの構えなら編集の構えへ移る
(見えないまま再生して音が鳴らないため)。

**登録していない変更の確かめ。** ライブラリに登録していない並びは自動保存の対象でないため、並びを捨てる操作の前に確かめる。確かめるのは、並びが空でなく、
続ける操作が並びを捨て、次のどちらかに当たるときである。動画を開いたときは並びを残すなら捨てない。

- 並びを置き換えたときからクリップを変えている(選択だけの変化は変更に数えない)。動画を開いただけで作られる最初のクリップは変更ではないため、
  動画を開いて何もせずに別の動画を開いても確かめない
- 起点の並びをファイル(JSON読込・落とした JSON・読み取り専用のライブラリから開いた並び)から読んでいて、続ける操作が名前の違う動画を開く。
  読み込んだ並びを使うつもりで動画を開くことが多く、変えていなくても「Clip Mod 1」へ黙って置き換わると驚くためである。ほかの操作では、
  並びはファイルに残っているため確かめない

開いているスタックをライブラリから削除した後の並びは、ファイルにも残っていない。そのため、削除したときに起点を空の並び(新しく作った並び)に置き直し、
並びが空でなければ、登録していない並びと同じく、捨てる前に確かめるダイアログを出す(`削除したスタックとの関係を終える`)。

| 続ける操作 | 並びを捨てるか | 確かめる理由 |
|---|---|---|
| 動画を開く(ボタン・落とす・起動の引数) | 並びを残せないときだけ捨てる | 変えている、または読み込んだ並びを捨てる |
| 動画を解除する・JSON読込・落とした JSON・一覧から開く・アプリを閉じる | 捨てる | 変えている |

確かめるダイアログは、変えているときは「ライブラリに保存していない変更がある。続けると失われる」と [ライブラリに保存する] [変更を捨てて続ける] [やめる] を出す。
読み込んだ並びを捨てるときは「読み込んだ並びは、名前の違う動画を開くと捨てて、最初のクリップだけの並びで始める。続けると今の並びは失われる」と
[ライブラリに保存する] [並びを捨てて続ける] [やめる] を出す。

| 押したもの | 結果 |
|---|---|
| ライブラリに保存する | 名前を付けて登録するダイアログを開く。登録したら、登録の書き込みを終えるのを待ってから元の操作を続ける(アプリを閉じるならウインドウを閉じる)。書けてから関係を終えるため、登録した並びは失われない。ライブラリへ書けないか動画を開いていなければ押せない |
| 変更を捨てて続ける・並びを捨てて続ける | 確かめずに元の操作を行う |
| やめる(ダイアログの外を押す・Escape を含む) | 何もしない |

ファイルを選ぶダイアログ(動画を開く・JSON読込)は確かめる前に済ませ、確かめるダイアログは選んだ動画か読んだ設定を持つ。ダイアログを取り消したときや、読めない JSON を選んだときに確かめるダイアログを出さないためである。
登録済みのスタックの保存の確かめ(`ライブラリ.md` 判断5)は変えない。

**ウインドウへ落としたファイル。** 拡張子で見分ける。json(大文字と小文字は区別しない)なら設定ファイルとして扱い、編集とシアターの構えでは「JSON読込」と同じく読んで並びを置き換え、
ライブラリの構えでは一覧の「v4.0 JSON を取り込む」と同じくライブラリへ取り込む(一覧に落としたものは一覧へ入れるのが自然なためである)。それ以外は動画として開き、
ライブラリの構えなら編集の構えへ移る。起動の引数は動画だけを渡す(`app/launch_requests.rs` は `確かめてから動画を開く` を使う)ため、JSON を起動の引数で渡しても設定ファイルとしては扱わない。
1回に落としたファイルは SengenEgui の `落とされたファイルをまとめて受け取る` で1つの応答(`一度に落としたファイル`)として受け取り、順に扱う。
ファイルごとに、扱う前にダイアログを開いているか(`アプリの状態::ダイアログを開いているか`。ライブラリのダイアログかキーの一覧のダイアログを開いていれば真。起動の受け口に届いた頼みと同じ判定)を見て、
開いていれば残りのファイルを扱わず「開いているダイアログを閉じてから、もう一度ドラッグ＆ドロップしてください」を1件だけ知らせる。
落とす前から開いていたダイアログも、前のファイルで出た確かめるダイアログも、後のファイルで上書きしないためである(上書きすると、そのダイアログで選ぶはずだった続ける操作や登録の後にすることが消える)。

**取り消しとやり直し。** 取り消しの単位はクリップスタックの値(10クリップで約2KB)であり、編集の履歴(`state/history/`)が、並びを置き換えたときの並び・最後に見た並び・
取り消せる並び(上限100)・やり直せる並びを持つ。

- 並びの変化を見るのは毎フレームの最初の1箇所(`フレームを進める` の最初)であり、操作ごとに積む呼び出しを足さない。自動保存が並びを毎フレーム比べるのと同じ理由である
- 選択の変化は積まない。取り消しとやり直しで並びを戻すときも、選択は今のままにする(今選んでいるクリップが戻した並びに無ければ、戻した並びの選択を使う)。戻した後は、カードを押したときと同じ規則で再生位置を合わせる
- クロップ枠のドラッグの間は積まず、放した時点で1つの変化として積む。区間の帯のドラッグはクリップスタックを変えない(判断11)ため、放した時点で1つの変化になる
- 数値入力のドラッグは、同じクリップの同じ端の値を1フレームごとに変える。同じ値の変化は、操作の区切り(ドラッグを放したとき)まで1つの変化にまとめる。区切りは SengenEgui の数値入力の
  `操作を終えたら発する` が発する応答で知り、区切りと同じフレームに届いた最後の変化までをまとめる。クロップ枠を放した時点で1つにするのと同じ方針である。数値入力の直接入力と
  クリップの名前の入力は、確定したとき(Enter・欄を離れたとき)だけ値を変えるため、1つの変化になる
- 取り消した後に並びを変えると、やり直せる変化を捨てる
- 取り消しで並びが変わると、登録済みのスタックなら自動保存が働く(並びが保存した並びと違うため)
- ドラッグの途中は取り消しもやり直しもしない
- 並びを置き換えると履歴を空にする。同じ動画を開き直して並びを残すときは履歴を引き継ぐ

**今の位置から区間を作る。** 今の位置とは、再生位置のコマの動画上の位置(元動画再生・単独クリップ再生・シーケンス再生のどれでも、今映している動画上の位置。区間の帯のドラッグのプレビューに
置き換える前の位置)のことであり、再生位置に当たるクリップが無ければ動画の先頭である。規則は `clip_domain` の `区間の編集の決まり`(`span_place.rs`)が持つ。

| 操作 | 結果 |
|---|---|
| 新規Clipを追加 | 今の位置から5秒の区間のクリップを末尾へ足して選ぶ。終了が上限(動画の長さ)を超えるなら上限で止める(長さが縮む)。開始は今の位置であり、上限ちょうどでは最小の長さ(0.05秒)を空けるため開始を前へ寄せる |
| カードの「開始を今の位置に」・I キー(選択中のクリップ) | 今の位置が終了より前なら開始だけを動かす。終了以降なら長さを保って開始を今の位置へ動かす |
| カードの「終了を今の位置に」・O キー(選択中のクリップ) | 今の位置が開始より後ろなら終了だけを動かす。開始以前なら長さを保って終了を今の位置へ動かす |

区間が変わったときは、区間の帯を放したときと同じく再生位置をそのクリップの開始へ移し、そのクリップを選ぶ。選ぶクリップが変わるため、
単独クリップ再生の対象もそのクリップへ変わる(選ばれていないカードのボタンを押したときも同じである)。

**並べ替えと複製。** カードに「↑」(1つ前へ)と「↓」(1つ後ろへ)と「複製」を置く。先頭の ↑ と末尾の ↓ は押せない。動かしたクリップを選び、カードを押したときと同じ規則で再生位置を合わせる。
複製は新しい識別子で名前に「のコピー」(空白を入れない。ライブラリのスタックの複製と同じ言葉を `clip_domain` の1か所で持つ)を足した写しを元の直後へ差し込んで選ぶ。ドラッグでの並べ替えは入れていない(6節)。

**前のクリップへ戻る。** Next Clip の隣に「前へ」を置く(シーケンス再生のときだけ出す)。前の再生できるクリップの開始へ戻して選ぶ。先頭のクリップにいるときはそのクリップの開始へ戻す。
末尾で止めたとき(タイムラインの末尾以降)は、最後の再生できるクリップを今のクリップとみなし、その前へ戻す。トリガーは見ない。再生しているか止めているかは変えない。

**キーの割り当て。** キーの割り当ては、操作ごとの既定のキー(`viewer_settings/keys/default_keys.rs`)に利用者の変更を重ねた今の割り当て(状態の `キーの割り当て`)であり、操作ごとの効く範囲と発する応答は `view/keys/table.rs` の表が持つ。
キー操作の部品と、F1 で開くキーの一覧のダイアログ(`view/keys/help.rs`)の両方が、今の割り当てとこの表から作る。表とダイアログの中身が食い違わないためである。下の表のキーは既定のキーであり、利用者はダイアログで変えられる(判断18)。キーが効く範囲は次の5つであり、ダイアログとは画面を覆うライブラリのダイアログとキーの一覧のダイアログのことである。
ダイアログを開いている間は、Escape はダイアログが受け取ってダイアログを閉じる(以前は Escape のキー操作が先に押下を消費し、確かめるダイアログを Escape で閉じられなかった)。

| 効く範囲 | 意味 |
|---|---|
| いつでも | 構えにもダイアログにも関わらず効く |
| 編集・シアター | 編集かシアターの構えで、ダイアログを開いていない間。ライブラリの構えは再生を止めて映像を見せないため、見えないところで再生や位置を変えない |
| 編集 | 編集の構えで、ダイアログを開いていない間。シアターでも並びを変えない |
| どの構えでも(ダイアログを開いている間は効かない) | ダイアログを開いていない間はどの構えでも効く。ダイアログを開いている間はダイアログがキーを受け取る |
| どの構えでも(キーの一覧のダイアログを開いている間も効く) | ライブラリのダイアログを開いていない間はどの構えでも効く(キーの一覧のダイアログを開いている間も効く。この範囲の操作はキーの一覧を開け閉めする操作だけなので、効けばダイアログを閉じる) |

効く範囲の名前はダイアログの「効く構え」の列にそのまま出す(`view/keys/rule.rs` の `説明`)。名前は範囲だけを述べ、割り当てたキーで決まること(Escape でダイアログが閉じる等)を書かない。
以前は全画面かシアターを抜ける操作の範囲を「どの構えでも(ダイアログを開いている間はダイアログを閉じる)」と書いていたが、ダイアログを閉じるのは Escape のキーであって操作ではないため、
その操作を別のキーへ変えると嘘になった。

| キー | 操作 | 効く範囲 |
|---|---|---|
| Space・K | 再生と停止 | 編集・シアター |
| Enter | 次のクリップへ進む(Next Clip と同じ。トリガーを待たない。シーケンス再生のときだけ進み、ほかのモードでは進まずに知らせる) | 編集・シアター |
| PageUp | 前のクリップへ戻る(Next Clip の隣の「前へ」と同じ。シーケンス再生のときだけ効く) | 編集・シアター |
| PageDown | 次のクリップへ進む(Next Clip と同じ。トリガーを待たない。シーケンス再生のときだけ効く) | 編集・シアター |
| ← / → | 1コマ戻す / 進める | 編集・シアター |
| Shift+← / Shift+→ | 5秒戻す / 進める(-5s・+5s のボタンと同じ) | 編集・シアター |
| [ / ] | 速度を1段下げる / 上げる | 編集・シアター |
| M | 音を消す・戻す | 編集・シアター |
| Ctrl+S | 未登録ならライブラリへ名前を付けて登録するダイアログを開き、登録済みなら落ち着くのを待たずに今の並びの保存を頼む(保存を待っている変更が無ければ「保存済み」と知らせる) | 編集・シアター |
| T | 編集の構えならシアターへ、シアターなら編集の構えへ切り替える(オーナーの決定 2026-10-03。Escape でシアターから編集へ戻る規則は残す) | 編集・シアター |
| Escape | 全画面なら全画面を抜け、全画面でなくシアターなら編集へ戻る(判断16) | どの構えでも(ダイアログを開いている間は効かない) |
| F11 | 全画面にする・抜ける(判断16) | いつでも |
| F1 | キーの一覧のダイアログを開く・閉じる | どの構えでも(キーの一覧のダイアログを開いている間も効く) |
| Ctrl+Z | 取り消す | 編集 |
| Ctrl+Y・Ctrl+Shift+Z | やり直す | 編集 |
| I | 選択中のクリップの開始を今の位置に | 編集 |
| O | 選択中のクリップの終了を今の位置に | 編集 |

- **入力欄。** 入力欄(一行・複数行のテキスト入力と数値入力の直接入力)にフォーカスがある間は、修飾キーの無いキーを入力欄に任せる(SengenEgui のキー操作の規則)。
  入力欄の編集を Escape でやめた回の Escape も入力欄に任せ、全画面やシアターを抜けない。egui はフレームの始めに Escape で入力欄のフォーカスを外すため、
  SengenEgui は前のフレームに入力欄がフォーカスを持っていた回を、入力欄に文字を打っている間とみなす。
  Ctrl+Z・Ctrl+Y・Ctrl+Shift+Z も入力欄に任せる(入力欄の文字の取り消しになる。SengenEgui の `キー操作(…).入力欄にフォーカスがある間は発しない()`)。
  Ctrl+S だけは入力欄のフォーカスを外させてから保存する。外した回に入力欄が確定の応答を出すため、打ちかけのクリップの名前も保存に入る
- **フォーカスを持つボタン。** egui は Space と Enter を、フォーカスを持つボタンの押下として扱う(Tab や矢印キーでボタンにフォーカスが移る)。
  以前の SengenEgui は、フォーカスを持つ部品があれば(ボタンでも)修飾キーの無いキーを見張らなかったため、Space を押すとフォーカスを持つボタンが押された。
  SengenEgui の版 128fad8 から、修飾キーの無いキーを入力欄に任せるのは文字を打つ部品にフォーカスがあるときだけになった。版 6b067b2 から、文字を打つ部品かは、
  一行・複数行のテキスト入力と数値入力が描いたフレームごとに識別子を知らせる集まり(前のフレームとこのフレームの分)で見分ける。egui のテキスト編集の状態は部品が消えても残るため、
  それで見分けると、描かれなくなった入力欄と識別子が重なるボタンを入力欄とみなし、そのボタンが Space で押されていた。ボタンにフォーカスがあるときは、
  キー操作が押下を消費してボタンのフォーカスを外させ、次の回に応答を発する。キー操作は画面の木の最初(見えない部品)に置き、ボタンより先に押下を消費する
- **Enter。** Enter は、シーケンス再生のとき、トリガーを待たずに Next Clip・PageDown と同じく次のクリップへ進める(オーナーの決定 2026-10-03)。
  以前の Enter はトリガーが Enter待ちか Space待ちのときだけ進め、既定の自動進行のクリップでは知らせも出さずに何もしなかった。
  キーの表は Enter を `出力の操作::Enterキーで次へ進める` へ写し、適用(`command/next_clip.rs`)は `clip_domain` の進める操作の `次へボタン` で進める。
  `clip_domain` は Enter を知らず、Enter 専用の進める操作を持たない。ドメインの規則が「シーケンス再生でない」と返したとき(単独クリップ再生と元動画再生)は、
  進めずに「Enter で次へ進めるのはシーケンス再生のときだけです」と知らせる(「Enter」の所は、この操作の今のキーの表記)。再生位置にクリップが無いとき(待機中)は、Next Clip と同じく何もしない
- **Space待ち。** 移植元のトリガー「Space待ち」は、Space を再生と停止に使うため、Enter で進む形に読み替える(オーナーの決定)。Enter はどのトリガーでも次へ進めるため、
  Space待ちと Enter待ちは同じく Enter で進む。2つのトリガーが「待つ」意味(最後の周回を繰り返しながら待つ。`アーキテクチャ.md` 判断6)は変えない。データとしては Space待ちのまま読み書きし、移植元の設定ファイルと
  ライブラリのファイルの互換を保つ。画面では、カードの選択欄を「Space待ち(Enterで進む)」、再生コントロールのステータスを「Spaceキー待ち(Enterで進む)」にし、
  トリガー待ちの札に「Space待ちは Enterキーで進む」と出す(「Enter」の所は、Enter の操作の今のキーの表記。「(Space は再生と停止に使う)」の補足は、再生と停止の操作が今 Space を持つときだけ出す。`view/text.rs` の `トリガー待ちの案内`)。選択欄とステータスの「(Enterで進む)」は移植元の選択肢の名前の一部として残し、キーを変えても変えない
- **PageUp・PageDown。** egui 0.32.3 のスクロールの区画はPageUp と PageDown を扱わない(egui のソースにこの2つのキーの処理が無いことを確かめた)ため、
  ページ送りとぶつからない。どちらもスクロールより先にキー操作が押下を消費する。前へ戻す・次へ進める規則はシーケンス再生のときだけ働くため、
  単独クリップ再生と元動画再生では押しても何も起きない(Next Clip と「前へ」のボタンもシーケンス再生のときだけ出す)
- **速度の選択肢。** 速度の選択肢とは、速度のつまみの範囲(0.25〜2倍)を0.25倍ごとに区切った倍率(0.25・0.5・…・2)のことである(`state/speed_steps.rs`)。
  [ と ] は速度を1つ隣の選択肢へ変える。つまみは0.05倍刻みで選べるため、選択肢の間の倍率(1.1倍等)からは、その向きで最も近い選択肢へ移る。最も遅い選択肢と最も速い選択肢より外へは動かない
- **消音。** M は、つまみの音量を覚えたまま音を消し、もう一度押すとその音量に戻す(`state/volume.rs` の `音量の設定`)。音量のつまみを動かすと消音を解く。
  再生コントロールの音量のつまみの隣に「消音」のチェックボックスを置く
- **ボタンの説明。** 再生の操作の行のボタンとつまみ、ヘッダーの取り消すとやり直す、出力の帯のシアターで見ると全画面の説明に、同じ操作の今の割り当てのキーを出す(再生は既定で「Space・K」等)。動画の無いシアターの案内の文も、全画面かシアターを抜ける操作の今のキー(既定は Escape)を出す。トリガー待ちの札の案内と、シーケンス再生でないときの Enter の知らせも、今のキーで書く。カードの「開始を今の位置に」「終了を今の位置に」の説明は、キーの名前を出さずにキーの一覧を指す(カードの様子へ割り当てを渡さないため)

ヘッダーには、構えに関わらず(シアターにはヘッダーが無い)キーの一覧のダイアログを開く「キー設定」のボタンを置き(判断18「閉じ込めの防止」)、編集の構えのときだけ「取り消す」「やり直す」のボタンを置き、取り消せる・やり直せる変化が無ければ押せなくする。記号の「↶」「↷」は日本語のフォントに字形が無いおそれがあるため、文字にした。

**ドラッグの後始末。** 再生位置の帯をドラッグしたまま構えを変える(シアターを Escape で抜ける等)と、帯は別の部品に描き直されて放したを受け取れない。
構えを変える経路(利用者の選択・シアターを抜ける・動画を開いたとき・ライブラリから開いたとき)はすべて `アプリの状態::構えを移す`(`state/view_stance.rs`)を通し、
そこでドラッグの様子を終える。残ると、ドラッグの間は音を黙らせるため、音が黙ったままになる。クロップ枠のドラッグは、区間の帯と同じく応答を適用した後の安全網
(`取り残されたドラッグを捨てる`)が、主ボタンを押していないのに残っていれば掴み始めを忘れる。残ると編集の履歴へ積めず、取り消しも止まるためである。
同じ安全網は、主ボタンを押していないフレームごとに取り消しのまとめも区切る。数値入力の区切りの応答が届かなかったときに、次の操作の変化を前の操作とまとめないためである
(数値入力のドラッグの間は主ボタンを押しているので区切らない)。

**通知の並び。** 通知は最近の4つまでを並べて出し、通知ごとに3秒で消す(SengenEgui の `一定時間で消える通知の並び`)。起動の途中の知らせ(設定を読めない・音声出力装置を開けない)と
動画を読み込んだことのように続けて出た通知が、前の通知を読む前に置き換えないためである。

### 判断15: 左右反転は出力の設定の1項目にし、出力の画面とシアターの映像だけを反転する

左右反転とは、出力の画面に映像を左右を入れ替えて鏡のように映すことである(ダンスの振りを鏡で見る形で練習する等)。
左右の向き(`state/output_settings.rs` の `左右の向き`)は、クリップの項目ではなく出力の設定(見る側の設定)の1項目にする。
同じスタックを、反転して見る人と反転せずに見る人がいるためである。スタックのファイル(ライブラリと v4.0 形式)には書かない。

- **切り替え。** 出力の帯(編集の構え)の「左右反転」のチェックボックスで切り替える。シアターには切り替えの部品を置かない
- **描き方。** SengenEgui の画像の `左右を反転する` で、描く部分(クロップ)の中で uv の左端と右端を入れ替えて描く。描く大きさと、押して次へ進める範囲は変わらない。
  編集の構えの出力とシアターは同じ出力の画面の材料(`view/output/screen.rs`)から描くため、両方で効く
- **プレビューとクロップ枠。** サイドバーのプレビューは反転しない。プレビューの見出しが示すとおり、元の動画のコマをそのまま出して、その上でクロップ枠を動かすためである。
  クロップ範囲は元の動画の座標で持ち、左右の向きによって値を変えない。反転したプレビューの上で枠を動かす形にすると、枠の移動量の左右を逆にして元の座標へ戻す変換が
  要り、クロップの値の意味が見る側の設定に左右されることになる。反転しているときも、出力には、プレビューの枠の中身が左右を入れ替えて映る

### 判断16: 全画面は F11 で出入りし、ウインドウへの指示は1フレームに並びで送る

全画面とは、OS のウインドウが題名の帯と枠を消して画面全体を覆うことである。シアター(出力をウインドウ全体に広げる構え。判断12)とは別のものであり、組み合わせられる。
シアターで全画面にすると、動画が画面全体に出る。

- **出入り。** F11(どの構えでも、ダイアログを開いている間も効く)と出力の帯の「全画面」のボタンで出入りする。Escape は、全画面なら先に全画面だけを抜け(構えは変えない)、
  全画面でなくシアターなら編集の構えへ戻る。シアターで全画面にしたときは、Escape を2回押すと編集の構えの普通のウインドウへ戻る
- **様子と頼み。** 状態の `ウインドウの状態`(`state/window.rs`。語彙は `state/window_vocabulary.rs`)は、起動の部分が毎フレーム egui から読んで知らせる全画面の様子と、F11・Escape の操作が頼んだ全画面の様子を持つ。
  頼みは最後の1つだけを持ち、同じフレームで F11 を2回押したときは、2回目は1回目の頼みから切り替える。まだウインドウへ送っていない頼みがあれば、
  その頼んだ様子を今の様子とみなす。頼みは1フレームの終わりに配線が取り出してウインドウへ送るため、送った後は egui が知らせた様子を今の様子とする
- **ウインドウへの指示の並び。** 以前のウインドウへの指示は1フレームに1つの値だけを持ち、閉じる・前に出すの間で1つを選んでいた。全画面の出入りが加わると、閉じるのを取り消す・全画面・前に出すが
  同じフレームに重なりうるため、配線は指示の並び(`ウインドウへの指示::並びを決める`)を決め、起動の部分は並びを順に送る。順は、閉じるのを取り消す(取り消さないとウインドウが閉じる) →
  全画面の出入り → 大きさの変更(判断17の起動の後の確かめ) → 前に出す(全画面を変えた後のウインドウを前に出す)である。閉じると決めたフレームは、閉じる指示だけを送る

### 判断17: 見る側の設定を settings.json に覚え、変えてから1秒落ち着いたときと閉じるときに書く

見る側の設定とは、スタックに属さず見る人の好みで決まり、次に起動したときへ持ち越す値の組のことである(`viewer_settings/` の `見る側の設定`)。
形式と項目の名前は `ライブラリ.md` 6節が正本である。

**覚えるもの。** 覚えるのは次の7つである。

| 項目 | 覚える値 |
|---|---|
| ウインドウ | 最大化も全画面もしていないときのウインドウの中身の大きさ(`viewer_settings::ウインドウの大きさ`)と、最大化しているか。最大化して閉じても、最大化を戻したときの大きさを覚えておく |
| 音量 | つまみの値。音を消していても、消す前のつまみの値を覚える |
| 速度 | 速度の倍率 |
| 左右の向き | 出力を左右反転するか(判断15) |
| アスペクト比 | 出力のアスペクト比 |
| 表示サイズ | 出力の表示サイズ |
| キーの割り当て | 利用者が変えたキー(判断18)。既定と違う操作だけを書く |

出力の設定と再生の設定のうち、次のものは覚えない。

- 画面の構え(編集・シアター・ライブラリ): 起動したときは動画が無く、シアターやライブラリの構えで始めると最初の操作(動画を開く)の部品が見えないため
- 再生モード: スタックの見方(通して見るか・1つのクリップだけか・元の動画か)であり、開くスタックごとに選ぶため
- 全体ループ: シーケンス再生の末尾の振る舞いであり、スタックを作った人が並びに合わせて決めるもののため。スタックのファイルには無いが、見る人の好みではない
- 消音: 一時的に音を消す操作であり、覚えると次に起動したときに音が出ない理由が分からなくなるため
- 全画面: 起動したときに画面全体を覆うと、他のウインドウへ移る手段が見えにくいため。全画面の間はウインドウの大きさも覚え直さない

**読む時点と当て方。** 起動の手順がウインドウを作る前に読み(`app/launch_plan.rs`)、ウインドウの大きさと最大化はウインドウを作るときに eframe へ渡す。ほかの項目は組み立てで状態へ当てる
(`アプリの状態::見る側の設定を当てる`)。読めないときは既定の値で起動し、読めない理由は FFmpeg の置き場所を読むときの通知で1回だけ知らせる。

**ウインドウの大きさの確かめ。** ウインドウを作る前の eframe の口では画面の大きさが分からない。そのため、egui が最初に画面(モニタ)の大きさを知らせた回に、覚えていた大きさが
画面に収まり最小の大きさ(800×500)以上かを確かめ、外れていれば最初の大きさ(1200×620)へ戻す(`state/window.rs`)。大きな画面で広げたウインドウを、小さな画面で開いた等である。
最大化して起動したときは、最大化を解かないようウインドウへは大きさを頼まず、覚える大きさだけを最初の大きさにする。

**書く時点。** 配線の保存係(`app/viewer_settings_save.rs`)が毎フレーム今の設定を組み、最後に書いた設定と違う値が1秒変わらなかったら書く(`app/settings_watch.rs`)。
つまみやウインドウの縁をドラッグしている間にフレームごとに書かないためである。アプリを閉じるときは、書いた設定と違えば待たずに書く。書き方は今の原子的な書き方
(読み直して見る側の項目だけを変え、一時ファイルへ書き切ってから置き換える)である。書けなかったときは、最初の1回だけ通知で知らせ、次に値が変わって落ち着いたときに書き直す。
落ち着くのを待っている間は、入力が無くても保存する時刻に画面を進める。保存係が残り時間を状態(`アプリの状態::見る側の設定を保存するまでの時間`)へ置き、
画面の描き直しの予約(`view/invisible.rs`)が使う。ライブラリの自動保存が `次に並びを見るまでの時間` で予約するのと同じ形である。
予約しないと、音量のつまみを放した後にマウスを動かさなければ、次の入力まで書かれない。
書く処理は画面のスレッドで行う。書くのは値が落ち着いたときだけであり、ファイルは1KB未満である。

**2つ目のアプリ。** ライブラリの錠を持たないアプリ(2つ目に起動して読み取り専用になったアプリと、置き場所の無いアプリ)は、見る側の設定を書かない。
settings.json は錠の外にあるため書くこと自体はできるが、一時的に開いた2つ目のウインドウの大きさや音量で、1つ目のウインドウの設定を上書きしないためである。
2つのアプリが交互に書き合って、閉じた順で設定が決まることも避けられる。2つ目のアプリも起動のときには読み、同じ設定で始める。

### 判断18: キーの割り当てを利用者が変えられるようにし、既定のキーに利用者の変更を重ねた今の割り当てからキー操作とダイアログを作る

オーナーの依頼(2026-10-03)は、キーの切り替えなどのショートカットの設定をする画面である。F1 のキーの一覧のダイアログを、操作ごとに今のキーと「変更」のボタンを持つ設定の画面にする。

**型。** キーの割り当ての値は見る側の設定の層(`viewer_settings/keys/`)に置く。

- `キーで行う操作` とは、キーを割り当てられる操作の閉じた列挙のことである(20個)。キーの組ではなく操作を単位にする。Space と K は「再生と停止」の2つのキーである。働きの文(`働き`)と既定のキー(`既定のキー`)もこの型が持つ
- `操作のキー` とは、1つの操作に割り当てたキーの組の、1つか2つの並びのことである。既定で2つのキーを持つ操作は、再生と停止(Space・K)と編集をやり直す(Ctrl+Y・Ctrl+Shift+Z)である。利用者がキーを変えると1つになる。0個を型で表せない
- `キーの割り当て` とは、すべての操作の操作のキーの組のことである。不変条件は、どの2つの操作も同じキーの組を持たないことである(SengenEgui のキー操作は最初に一致したものだけが押下を受け取るため、重なった後の操作は決して起きない)。キーを変える(`キーを変えた`)・既定に戻す(`既定に戻した`)は、重なりを確かめてから新しい割り当てを返し、重なれば `キーを変えられない理由` を返す。保存した変更から作る(`保存した変更から作る`)は、重なりを起こした変更のうち後に読んだものだけを捨て、ほかの変更を生かした割り当てを返す(`ライブラリ.md`「keyBindings の読み方」)
- `操作のキー` の並びは非公開であり、作る口は1つの組(`一つ`)・確かめて作る `組の並びから作る`(2つが同じ組なら作らない)・既定のキーだけが const で使う `既定の二つの組から作る` である。既定の2つの組が違うことは試験が確かめる
- キーの組は SengenEgui の `キーの組` で持ち、生の文字列で持たない。文字列にするのは settings.json の境界(`persistence/app_settings/v1_keys.rs`。SengenEgui の `キーの組::表記` と `キーの組::表記から読む`)だけである

**層と依存の向き。** 次の表の各行は、知る側が知られる側を知ってよいことを表す。

| 知る側 | 知られる側 | 何に使うか |
|---|---|---|
| `viewer_settings/keys`(キーの割り当ての値) | SengenEgui のキーの型(`キー`・`キーの組`・`修飾キー`) | 操作のキーをキーの組で持つ |
| `state`(今の割り当てと、ダイアログの待ちの様子) | `viewer_settings/keys` | 状態の `キーの割り当て` と `キーの一覧のダイアログ` が待つ操作 |
| `command`(キーの設定の操作の適用・Enter の知らせ) | `state` | 割り当てと待ちの様子を書き換える |
| `command` | `viewer_settings/keys` | 割り当てを変える・既定に戻す。働きの文と今のキーの表記を知らせに使う(`command/key_settings_ops.rs`・`command/next_clip.rs`) |
| `command` | SengenEgui のキーの型 | 押されたキーの組を受け取り、Escape のキーを含むかを見る(`command/key_settings_ops.rs`)。名指してよい理由は2節の起動の部分の行に書いた |
| `persistence`(settings.json の keyBindings) | `viewer_settings/keys`・SengenEgui の `キーの組` | 既定と違う操作を、キーの組の表記と相互に変換する |
| `view/keys`・`view/text`・`view/header`(効く範囲と応答の表・キー操作の部品・設定のダイアログ・札の案内とボタンの説明) | `state`・`command` の応答・`viewer_settings/keys` | 今の割り当てを状態から読む(読むだけで変えない)。変えるのは、発した応答を command が適用したときだけである |

`view/keys/table.rs` は、操作を網羅する match で効く範囲・発する応答・入力欄との関係を決める。操作を足すと、表の書き忘れはコンパイルエラーになる。働きの文を操作の型に置くのは、ダイアログ(view)と重なりの知らせ(command)の両方が使うためである。

**ダイアログ。** 格子の列は「働き」「今のキー」「効く構え」と「変更」「既定に戻す」のボタンであり、表の下に「すべて既定に戻す」と「閉じる」を置く。「既定に戻す」は既定と同じ操作では押せず、「すべて既定に戻す」は割り当てが既定と同じなら押せない。
ダイアログはウインドウの4辺から16論理画素を空けた範囲に収め(SengenEgui のモーダルの `画面に収める`)、収まらない行は縦にスクロールさせる。格子の列の幅の上限は200論理画素であり(格子の `列の最大幅`)、働きと効く構えの長い文は折り返す。最小のウインドウ(800×500)と最初のウインドウ(1200×620)の大きさで、日本語フォントとテーマを当てた egui にダイアログを描かせ、枠がウインドウに収まること・最後の列のボタンの文字が1行であること・最も長い働きの文が折り返すことを試験で確かめる(`view/keys/help_tests.rs`)。実機の画面では確かめていない。

- 「変更」を押すと、ダイアログはその操作の新しいキーを待つ(状態の `キーの一覧のダイアログ::キーを待っている`)。その行の今のキーの升目に「キーを押してください」、「変更」の代わりに「やめる」を出す
- 待っている間は、画面のキー操作の部品をすべて置かない(F1・F11 も効かない)。ダイアログの先頭に SengenEgui の `次に押されたキーの組を受け取る` を置き、押されたキーの組(修飾キーを含む)を受け取る。受け取りはモーダルが Escape で閉じる処理より先に押下を消費するため、待っている間の Escape はダイアログを閉じない
- 押した組をほかの操作が持つなら、キーを変えずに「<キー> は「<働き>」のキーなので、「<働き>」のキーを変えなかった」と知らせる。待っている操作が既に持つ組なら、その組1つにする(再生と停止で K を押すと Space が外れる)。どちらの場合も待ちを終える
- 「既定に戻す」で戻す既定のキーをほかの操作が持つなら、戻さずに同じ形で知らせる。「すべて既定に戻す」は既定の割り当てが重ならないため、常にできる
- ダイアログを閉じると(F1・外を押す・閉じる)、待ちも終わる

**Escape の扱い。** 待っている間に Escape を押すと、キーを変えずに待ちをやめる。Escape を新しいキーとして割り当てることはできない。Escape のキーを含む組(Shift+Escape・Ctrl+Escape 等)も同じく割り当てず、押せば待ちをやめる(`command/key_settings_ops.rs` は組全体でなくキーで比べる)。Escape は、このアプリ全体で「やめる・閉じる」のキーであり(ダイアログを閉じる・入力欄の編集をやめる)、待ちをやめる手段をキーボードに残すためである。Escape を既定のキーに持つ操作(全画面かシアターを抜ける)を別のキーへ変えても、「既定に戻す」で Escape に戻せる。

**閉じ込めの防止。** キーの一覧を開く操作のキー(既定は F1)が無くなると、利用者はダイアログを開けず、キーを戻せなくなる。これを防ぐ規則は次の3つである。

- どの操作も必ず1つ以上のキーを持つ。`操作のキー` は空の並びを表せず、「変更」は1つの組への置き換えであり、キーを外すだけの操作を置かない。キーの一覧を開く操作も、常に1つ以上のキーを持つ
- キーの一覧を開く操作の効く範囲は、割り当てで変わらない(ライブラリのダイアログを開いていない間はどの構えでも効く)
- キーに依らない入口として、ヘッダー(編集とライブラリの構え。シアターにはヘッダーが無い)に「キー設定」のボタンを置く(`view/header.rs`)。押すとキーの一覧のダイアログを開く(`出力の操作::キーの一覧を開く`。開いていれば何もしない)。キーの一覧を開く操作のキーを忘れても、このボタンで開いて「すべて既定に戻す」を押せる。ボタンの説明には、キーの一覧を開く操作の今のキーを出す

キーを覚えていないときは、「キー設定」から戻すほかに、settings.json の `keyBindings` の項目を消すと、次の起動ですべて既定のキーに戻る(`ライブラリ.md` 6節)。

**保存。** キーの割り当ては見る側の設定の1項目であり、判断17の規則(変えてから1秒落ち着いたときと閉じるときに書く。ライブラリの錠を持たないアプリは書かない)で保存する。形式は `ライブラリ.md` 6節である。

**作らないもの。** 1つの操作に2つ目のキーを足す口は置かない。既定で2つのキーを持つ操作は、「既定に戻す」で2つに戻る。

## 5. 正準の一仕事

利用者は ClipViewer を開き、動画をウインドウへ落とす。「Clip Mod 1」が出来て再生が始まる。カードの区間の帯の開始と終了のつまみを動かして
1秒ほどの短い区間にする(動かしている間はプレビューにつまみの位置のコマが出る)。「このクリップを再生」でその区間だけを繰り返して確かめ、無限ループにする。溜め具合の表示が「溜め終えた」になると、繰り返しの継ぎ目が途切れなくなる。
プレビューの枠をドラッグして顔のあたりへ寄せると、出力がその部分へ切り替わる。寄せすぎたら Ctrl+Z で戻す。トリガーを Enter 待ちにしたクリップを
もう1つ足し、Enter で次へ進むことを確かめる。JSON保存で書き出し、アプリを開き直して JSON読込で同じ並びが出る。

## 6. この段階でやらないこと

- **音の高さを保った速度の変更**: `アーキテクチャ.md` の「この段階でやらないこと」を参照する
- **ドラッグでのクリップの並べ替え**: 並べ替えはカードの ↑ と ↓ で行う(判断14)。SengenEgui のドラッグ元と落とし先は、落とし先が子を枠で囲んで常に地を塗るためカードの見た目が変わり、ドラッグ元はカードの中の区間の帯・数値入力・クロップ枠のドラッグと掴む範囲が重なる。見た目と操作を実画面で確かめずに入れないため、この段階では入れない
- **流し読みの先読み**: 溜められない区間の継ぎ目は開き直しを伴い詰まる(`アーキテクチャ.md` 判断1-8)。先に次の開始位置で開いておく工夫は、溜めたコマの再生が成立したことを確かめてから決める
- **表示倍率の設定**: テーマの既定のままにする
