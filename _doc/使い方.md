# ClipViewer の使い方

この文書は、ClipViewer 0.3.0 の使い方を説明する。

画面に出る文字(ボタンの名前・選択肢・知らせの文)は、この文書では「」で囲み、画面に出ているとおりに書く。

## 1. ClipViewer とは

ClipViewer は、1本の動画から短い区間をいくつも切り出して並べ、その区間を繰り返し再生する Windows のアプリである。
ClipViewer は、ダンスの振り付け・楽器の演奏・語学の聞き取りのように、動画の同じところを何度も見て練習したい人のためのアプリである。

この文書で使う言葉の意味は次のとおりである。

- **動画**とは、利用者のパソコンに保存してある動画のファイル(mp4 など)のことである。ClipViewer は動画のファイルを書き換えず、写しも作らない。
- **パス**とは、ファイルの置き場所を「C:\動画\練習.mp4」のように書き表した文字のことである。
- **コマ**とは、動画を形づくる1枚1枚の絵のことである。
- **クリップ**とは、動画の中の「何秒から何秒まで」の区間に、繰り返す回数・切り抜く範囲・次へ進む条件を付けたもののことである。ClipViewer は、クリップを作っても動画を切り分けず、区間の数値だけを覚える。
- **スタック**とは、クリップを上から順に並べたもののことである。画面の見出しでは「Modifier Stack」と表示される。1つのスタックは1本の動画に対して作る。画面の知らせやダイアログの文では、スタックを「並び」と呼ぶことがある(例: 「読み込んだ並びは…」)。この文書は、画面の文を写すとき以外は「スタック」と書く。
- **再生の位置**とは、今どこを再生しているかを示す時刻のことである。
- **ライブラリ**とは、名前を付けたスタックを ClipViewer の中に保存しておき、一覧から開き直せるようにしたもののことである(8節)。
- **トリガー**とは、クリップを再生し終えたときに次のクリップへ進むための条件のことである(5.9節)。
- **クロップ**とは、動画の絵の一部だけを四角く切り抜いて大きく映すことである(5.11節)。
- **シーケンス再生**とは、スタックのクリップを上から順に続けて再生することである(6.1節)。
- **FFmpeg**(エフエフエムペグ)とは、動画を読んで絵と音に直す無料の道具のことである。ClipViewer は動画を読むために FFmpeg を使う。FFmpeg は ClipViewer に含まれていないため、利用者が別に入れる(2.3節)。
- **アプリのウインドウ**とは、ClipViewer の画面全体を収めた Windows のウインドウのことである。**ダイアログ**とは、アプリのウインドウの中に重なって出る小さな画面(名前を付けるダイアログ・確かめるダイアログ・キーの一覧のダイアログ)のことである。動画や JSON のファイルを選ぶときに Windows が出す画面は、ファイルを選ぶダイアログと呼ぶ。
- **知らせ**とは、ClipViewer が操作の結果を伝える短い文のことである(3.5節)。
- **ドラッグ**とは、マウスのボタンを押したままマウスを動かすことである。
- **チェックボックス**とは、押すと印が付いたり消えたりする小さな四角のことである。

## 2. はじめる前に

### 2.1 動作環境

- ClipViewer が動くのは、Windows 10 または Windows 11 の 64ビット版(x64)である。インストーラーは、Windows 10 より前の Windows ではインストールを止める。
- ClipViewer は、日本語のフォント(游ゴシック・メイリオ・MS ゴシックのどれか)を使って文字を出す。日本語版の Windows には、これらのフォントが最初から入っている。どれも無いと、ClipViewer は起動のときに「…。日本語が表示されない場合は OS へ日本語フォントを導入する」という Windows のメッセージボックスを出し、日本語の文字が出ないまま起動する。そのときは、利用者が Windows の設定の「システム」→「オプション機能」から「日本語の補助フォント」(Japanese Supplemental Fonts)を追加する。
- ClipViewer を使うには FFmpeg が要る(2.3節)。

### 2.2 インストールする

1. 利用者は、https://github.com/megaDenryu/ClipViewer/releases から `ClipViewer-<版>-setup.exe` を取得して実行する。
2. インストーラーは最初に、自分だけのために入れるか、このパソコンのすべての利用者のために入れるかを問う。自分だけのために入れると、ClipViewer は管理者の権限なしに `%LOCALAPPDATA%\Programs\ClipViewer` へ入る。すべての利用者のために入れると、ClipViewer は `Program Files` の下へ入る。
3. インストーラーの途中の画面に、デスクトップにショートカットを作るかのチェックボックスがある。最初は印が付いておらず、インストーラーがデスクトップのショートカットを作るのは、利用者が印を付けたときだけである。スタートメニューの「ClipViewer」は、インストーラーが必ず作る。
4. インストールを終えると、利用者は ClipViewer をスタートメニューの「ClipViewer」から起動できる。利用者は、インストーラーの最後の画面で ClipViewer を起動することもできる。

インストールすると、次の12種類の動画のファイルを右クリックしたときの「プログラムから開く」に ClipViewer が出る: mp4・m4v・mkv・webm・mov・avi・wmv・flv・mpg・mpeg・m2ts・mts。
利用者は、Windows の設定の「既定のアプリ」で、ClipViewer をこれらの動画の既定のアプリに選ぶこともできる。インストーラーも ClipViewer も、既定のアプリを勝手には変えない。

インストーラーには電子署名が付いていない。そのため、利用者が初めてインストーラーを実行するときに、Windows の SmartScreen(発行元の分からないアプリを止める警告)が警告のメッセージボックスを出すことがある。そのときは、利用者が「詳細情報」を押してから「実行」を押すと、インストールが始まる。

### 2.3 FFmpeg を入れる

ClipViewer は、FFmpeg の `ffmpeg.exe` と `ffprobe.exe` の2つのファイルを使う。この2つが同じフォルダに無いと、ClipViewer は動画を開けない。FFmpeg の入れ方は次の2つのどちらかである。

- **winget で入れる。** 利用者は、コマンドプロンプトか PowerShell を開いて `winget install Gyan.FFmpeg` を実行する(どのフォルダで実行してもよい)。入れた後に利用者が ClipViewer を起動し直すと、ClipViewer は FFmpeg を自動で見つける。見つからなければ、利用者は Windows から一度サインアウトしてから ClipViewer を起動し直す。
- **自分で取得して展開する。** 利用者は、https://ffmpeg.org/download.html の「Windows builds from gyan.dev」から、release builds の `ffmpeg-release-essentials.zip` を取得し、好きなフォルダへ展開する。展開したフォルダの中の `bin` フォルダに `ffmpeg.exe` と `ffprobe.exe` がある。この場合は、利用者が次の「FFmpeg の場所を指定する」の手順で、ClipViewer に `bin` フォルダの場所を教える。

ClipViewer の動作を確かめた FFmpeg の版は、4.4.1 と 9.0.2 である。

**FFmpeg の場所を指定する。** ClipViewer は、FFmpeg が見つからないとき、画面の上部に次の欄を出す。

- 「FFmpeg が見つからないため動画を開けない。」に続けて、見つからない理由と、探した場所
- 「手順: ffmpeg.exe と ffprobe.exe が入ったフォルダ(例: C:\ffmpeg\bin)を下に入力し、「保存して探し直す」を押す。…」
- フォルダを入力する欄と、「保存して探し直す」のボタン

利用者がフォルダを入力して「保存して探し直す」を押すと、ClipViewer はそのフォルダで FFmpeg を探し直す。

- 見つかると、ClipViewer はそのフォルダをアプリの設定へ保存し、「FFmpeg が見つかり、置き場所を保存しました」と知らせ、上部の欄を消す。次の起動からも、ClipViewer はそのフォルダを使う(環境変数 `CLIPVIEWER_FFMPEG_DIR` を使っていないとき)。FFmpeg は見つかったが設定を書けなかったときは、ClipViewer は「FFmpeg は見つかったが、置き場所を保存できない: <理由>」と知らせる。
- 見つからないと、ClipViewer は何も保存せず、「入力したフォルダと PATH に ffmpeg と ffprobe がそろっていない」と知らせる。
- 利用者が欄を空のまま押すと、ClipViewer は「FFmpeg を置いたフォルダを入力してください」と知らせる。

**FFmpeg を探す順。** ClipViewer は、起動したときに次の順で FFmpeg を探す。

1. 環境変数 `CLIPVIEWER_FFMPEG_DIR` があれば、ClipViewer はそのフォルダを探す。この環境変数があるときは、ClipViewer は画面で保存したフォルダを探さない。
2. 環境変数が無ければ、ClipViewer は画面で保存したフォルダを探す。
3. 1か2で見つからなければ、ClipViewer は環境変数 PATH(Windows がプログラムを探すフォルダの一覧)を探す。

環境変数とは、Windows がプログラムへ渡す設定の値のことである。ふつうの利用者は環境変数を使わなくてよい。

## 3. 画面の見かた

### 3.1 3つの構え

構えとは、ClipViewer の画面の組み方のことである。ClipViewer には次の3つの構えがある。ClipViewer は、起動すると必ず編集の構えで始まる。

| 構え | 何をする構えか | 入り方 |
|---|---|---|
| 編集 | 動画を開き、クリップを作って直し、再生して確かめる | 画面の上の「編集」、シアターの「編集へ戻る」(動画があれば右上、無ければ中央の案内の中。7.1節)、シアターの構えで押す Escape キー(全画面のときは、1回目の Escape キーは全画面を抜けるだけである。7.2節)、シアターの構えで押す T キー。ライブラリの構えでは、Escape キーは編集の構えへ戻さない |
| シアター | 編集の部品を隠して、動画をアプリのウインドウいっぱいに映して見る | 画面の上の「シアター」、出力の帯の「シアターで見る」、編集の構えで押す T キー |
| ライブラリ | ライブラリに保存したスタックの一覧を見て、開き直す | 画面の上の「ライブラリ」 |

画面の上のボタンのうち、今の構えのボタンは、琥珀色(こはくいろ。黄色がかった茶色)の地で示される。
利用者が上の表のボタンか Escape キーか T キーで構えを変えると、ClipViewer は「編集」「シアター」「ライブラリ」のどれかを知らせる。知らせの語は、画面の上の構えのボタンの名前と同じである。動画を開いたときのように、ClipViewer が自分で構えを移したときは、ClipViewer はこの知らせを出さない。
ライブラリの構えへ移ると、ClipViewer は再生を止める。映像が見えないまま音が鳴り続けないためである。

### 3.2 編集の構えの区画

編集の構えの画面は、次の5つの区画に分かれる。

| 区画 | 場所 | 中身 |
|---|---|---|
| ヘッダー | 上の端 | 構えのボタン、「JSON読込」「JSON保存」、「キー設定」(キーの一覧のダイアログを開く。12節)、「取り消す」「やり直す」、ライブラリへの保存の様子。FFmpeg が見つからないときは、その下に FFmpeg の場所の欄(2.3節) |
| 左のサイドバー | 左の端 | 動画の欄、プレビュー、クリップのカード |
| 出力の帯 | 真ん中の区画の上 | 再生モード・シアター・全画面・アスペクト比・表示サイズ・左右反転 |
| 出力 | 真ん中 | 再生している動画。クロップを掛けた絵を大きく映す |
| 再生コントロール | 下の端 | 時刻、再生位置の帯、再生の操作、速度と音量、再生の様子 |

利用者は、左のサイドバーの右の縁をドラッグして、サイドバーの幅を決まった範囲の中で変えられる。利用者は、左のサイドバーを上下にスクロールできる。

**左のサイドバー**には、上から次のものが並ぶ。

1. 動画の欄(見出しは「Video Source File」)。開いている動画のファイル名と「解除」のボタン、「PC内絶対パス:」の欄、「動画を開く」のボタン、「ウインドウのどこかへ動画をドラッグ＆ドロップしても開ける」の文が並ぶ。動画を開いていないときは、ファイル名の代わりに「未ロード」と出る。
2. プレビュー(見出しは「オリジナル動画 (クロップ調整対象)」と、動画の縦横の画素数)。プレビューは、動画のコマを切り抜く前の全体の絵を出し、その上に選んでいるクリップのクロップの枠を重ねる。動画を開いていないときは「動画未ロード」と出る。
3. クリップのカード(見出しは「Modifier Stack」と「新規Clipを追加」のボタン)。クリップが1つも無いときは「クリップスタックが登録されていません」と出る。

**出力**は、動画を開いていないとき、「Smart Video Modifier Stack」と「左の「動画を開く」か、ウインドウへ動画をドラッグ＆ドロップして、シーケンス再生を開始します。」を出す(シアターの構えで出す文は7.1節)。ClipViewer がスタックを作った動画のファイル名を覚えているときは、出力はさらに「対応する元動画が見つかりません」と、その動画の「ファイル名:」と「保存時パス:」を出す。ClipViewer がファイル名を覚えているのは、動画のファイル名を持つ JSON(9節)を読み込んだ後と、利用者が動画を開いてから「解除」(4.3節)を押した後である。

### 3.3 シアターの構えの区画

シアターの構えでは、ClipViewer はヘッダー・サイドバー・出力の帯を出さず、出力だけをアプリのウインドウいっぱいに置く(7節)。

### 3.4 ライブラリの構えの区画

ライブラリの構えでは、ClipViewer はヘッダー(「取り消す」「やり直す」を除き、編集の構えと同じボタンが並ぶ)を出し、その下の全体をライブラリの一覧にする。ClipViewer は、サイドバー・出力・再生コントロールを出さない(8節)。

### 3.5 知らせ

ClipViewer は知らせを画面の下の中央に出し、1つの知らせを3秒で消す。ClipViewer は最近の知らせを4つまで縦に並べて出す。

### 3.6 ウインドウの題名

アプリのウインドウの題名には、「ClipViewer 0.3.0」のように版が出る。

## 4. 動画を開く

### 4.1 開き方

利用者は、次のどれかで動画を開ける。

- 利用者がサイドバーの「動画を開く」を押し、ファイルを選ぶダイアログで動画を選ぶ。ファイルを選ぶダイアログは、インストーラーが関連付ける12種類(2.2節)と同じ mp4・m4v・mkv・webm・mov・avi・wmv・flv・mpg・mpeg・m2ts・mts を動画として出す。
- 利用者が動画のファイルを、アプリのウインドウのどこかへドラッグして落とす(ドラッグ＆ドロップ)。ClipViewer は、拡張子が json 以外のファイルを動画として開こうとする。拡張子が json のファイルを落としたときは、ClipViewer は9.3節のとおりに扱う。
- 利用者がエクスプローラーで動画を右クリックし、「プログラムから開く」で ClipViewer を選ぶ。
- 利用者が、ClipViewer を既定のアプリにした動画を、エクスプローラーでダブルクリックする。

ダイアログ(ライブラリのダイアログ(8節・11節)と、キーの一覧のダイアログ(12節))を開いている間に利用者がファイルを落とすと、ClipViewer は落としたファイルを開かず、「開いているダイアログを閉じてから、もう一度ドラッグ＆ドロップしてください」と知らせる。拡張子が json のファイルも、ClipViewer は読み込まず、取り込まない。開いているダイアログで選ぶはずだった操作を消さないためである。

利用者が複数のファイルをまとめてアプリのウインドウへ落とすと、ClipViewer はファイルを1つずつ順に扱う。

- 確かめるダイアログ(11節)が要らなければ、ClipViewer は順に開き、最後のファイルが開いたまま残る。
- あるファイルで確かめるダイアログが出たとき、残りのファイルがあれば、ClipViewer はそれを開かず、「開いているダイアログを閉じてから、もう一度ドラッグ＆ドロップしてください」と知らせる。
- ClipViewer は、まとめて落としたファイルのうち開かなかったものが何個あっても、この知らせを1件だけ出す。

### 4.2 開いたときの振る舞い

利用者が動画を開くと、ClipViewer は次のことを行う。

- ClipViewer は「動画を読み込みました: <ファイル名>」と知らせ、再生を始める。
- ClipViewer は、「PC内絶対パス:」の欄に、開いた動画のパスを入れる。
- 利用者がライブラリの構えで動画を開くと、ClipViewer は編集の構えへ移る。利用者がシアターの構えで開いたときは、ClipViewer はシアターの構えのままにする。
- ClipViewer は、今のスタックを残すか、新しいスタックで始めるかを次の規則で決める。

**新しいスタックで始めるとき。** ClipViewer は、今のスタックを捨て、最初のクリップ「Clip Mod 1」だけのスタックで始める。「Clip Mod 1」の区間は、動画の先頭から10秒である(動画が10秒より短ければ、動画の長さである)。

**今のスタックを残すとき。** 次のどちらかに当たると、ClipViewer は今のスタックを捨てずに残し、先頭のクリップを選んで、再生の位置を先頭へ戻す。取り消しの履歴(10節)も残る。

- スタックが空でなく、スタックを作った動画(最後に開いた動画か、読み込んだ JSON が期待する動画)のファイル名が、開く動画のファイル名と同じとき。大文字と小文字は区別しない。
- スタックが空でなく、読み込んだ JSON が動画のファイル名を持っていなかったとき。

今のスタックを捨てる前には、ClipViewer は失われる変更が無いかを確かめる(11節)。

### 4.3 動画を解除する

利用者が動画の欄の「解除」を押すと、ClipViewer は動画を閉じ、スタックを空にし、再生を止めて「動画を解除しました」と知らせる。ClipViewer は「PC内絶対パス:」の欄と、動画のファイル名の記憶を消さない。そのため、出力には「対応する元動画が見つかりません」と、解除した動画のファイル名とパスが出る(3.2節)。スタックを捨てる前には、ClipViewer は失われる変更が無いかを確かめる(11節)。

### 4.4 ClipViewer が既に起動しているときに開く

利用者は ClipViewer を複数起動し、別々のウインドウで動画を見られる。利用者がエクスプローラーから動画を開くと、ClipViewer は新しいウインドウでその動画を開く。利用者がスタートメニューから ClipViewer を起動すると、ClipViewer は動画を開いていない新しいウインドウを出す。先に起動していた ClipViewer は、その動画と再生の状態を保つ。

- 各 ClipViewer は、動画・スタック・再生位置・音量を別々に持つ。利用者は、それぞれのウインドウで動画を開き、再生・停止・編集を行える。
- 同じライブラリへ書ける ClipViewer は、ライブラリの錠を持つ1つだけである。後から起動した ClipViewer はライブラリを読み取り専用で開く(8.9節)。利用者は、そのアプリでも動画の再生・編集と「JSON保存」を使える。
- 利用者がエクスプローラーで複数の動画を選んで開くと、Windows は動画ごとに ClipViewer を起動し、各 ClipViewer は自分のウインドウで動画を開く。1回の起動に複数の動画が渡されたときは、ClipViewer は最初の1つだけを開き、「複数の動画が渡されたため、最初の1つだけを開いた(ほかのN個は開いていない)」と知らせる。

以前の版の ClipViewer は、後から起動したときに動画を先のアプリへ渡す。現在の版でライブラリの錠を持つ ClipViewer は、この受け渡しを受け取る。利用者が以前の版を起動すると、錠を持つ ClipViewer はウインドウを前に出して動画を開き、失われる変更を4.2節の規則で確かめる。開いているダイアログがあれば、ClipViewer は動画を開かず、ダイアログを閉じてから開き直すよう知らせる。現在の版どうしでは、この受け渡しを行わない。

### 4.5 開けないとき

動画を開けないとき、ClipViewer は今の動画とスタックをそのまま残し、開けない理由を知らせる。

- FFmpeg が見つからないとき: 「FFmpeg が見つからないため動画を開けない。画面の上部で FFmpeg の置き場所を設定する」
- ffprobe(FFmpeg のうち、動画の長さや大きさを読む道具)が異常終了したとき: 「動画の情報を取れない: ffprobe が異常終了した(…)。…。ファイルがその場所にあり、動画のファイルであるかを確かめる」
- ffprobe の異常終了と30秒の時間切れ(次の項目)を除く理由で、ClipViewer が動画の情報を取れなかったとき: 「動画の情報を取れない: <理由>」。この知らせには、次にすることの案内が付かない。例えば、ファイルに映像が無いときは「動画の情報を取れない: ファイルに映像が無い」と出る。
- FFmpeg が30秒たっても動画の情報を返さなかったとき: 「動画の情報を取れない: …。動画のあるドライブかネットワークの応答が遅い。少し待ってからもう一度開く」。この知らせが出たときは、利用者は、動画のあるドライブ(外付けのドライブやネットワークのフォルダ)をエクスプローラーで開いて中身が出ることを確かめてから、もう一度動画を開く。

## 5. クリップを作る・直す

### 5.1 クリップのカード

クリップのカードとは、サイドバーに並ぶ、1つのクリップを表す四角のことである。カードには上から次の6つの行が並ぶ。

| 行 | 並ぶもの |
|---|---|
| 1行目 | 「有効」のチェックボックス、名前の欄、「このクリップを再生」、「先頭へ」、「削除」 |
| 2行目 | 「↑」「↓」「複製」「開始を今の位置に」「終了を今の位置に」 |
| 3行目 | 区間の帯(全体の帯と、拡大の帯) |
| 4行目 | 「開始:」、「-0.5s」「< F」、開始の秒の欄、「F >」「+0.5s」 |
| 5行目 | 「終了:」、「-0.5s」「< F」、終了の秒の欄、「F >」「+0.5s」 |
| 6行目 | 繰り返しの「-」、回数、「+」、「無限」のチェックボックス、「トリガー」の選択欄 |

1行目の名前の欄は、1行目のほかの部品を置いた残りの幅いっぱいに広がる。利用者がサイドバーの幅を広げると、名前の欄も広がる。サイドバーの幅が最も狭いときも、名前の欄の幅は、名前を打つための最低の幅(120論理画素。論理画素とは、Windows の表示の拡大率を掛ける前の画面の長さの単位のことである)より狭くならない。

利用者が Tab キーを押すと、1行目では、選ばれる部品が見えている並びのとおり左から右へ(「有効」、名前の欄、「このクリップを再生」、「先頭へ」、「削除」の順に)移る。

選んでいるクリップのカードは、ほかのカードと違う見た目で示される。

### 5.2 クリップを選ぶ

利用者がカードを押すと、ClipViewer はそのクリップを選ぶ。選んだクリップのクロップの枠が、プレビューに出る。選んだときに ClipViewer が再生の位置をどう動かすかは、再生モード(6.1節)ごとに次のようになる。

| 再生モード | 止めているとき | 再生しているとき |
|---|---|---|
| シーケンス再生 | 再生の位置をそのクリップの開始へ移す | 再生の位置を動かさない。ClipViewer は再生している間、映しているクリップを選び続けるため、選んだカードはすぐに映しているクリップへ戻る |
| 単独クリップ再生(選択中クリップのみループ) | そのクリップの開始へ移す | そのクリップの開始へ移す |
| 元動画再生 | 動かさない | 動かさない |

シーケンス再生で再生しているときに別のクリップへ移るには、利用者はそのカードの「先頭へ」を押す(5.14節)。

### 5.3 クリップを追加する

利用者が「新規Clipを追加」を押すと、ClipViewer は、今の位置から5秒の区間のクリップをスタックの末尾へ足し、そのクリップを選び、「クリップを追加しました(<開始の秒>秒から)」と知らせる。

- 今の位置とは、出力に今映しているコマの、動画の上での位置のことである。再生の位置にクリップが無いときは、今の位置は動画の先頭である。
- 区間の終わりが動画の終わりを越えるときは、ClipViewer は区間の終わりを動画の終わりで止める(区間は5秒より短くなる)。今の位置が動画の終わりから0.05秒以内のときは、ClipViewer は区間の長さを0.05秒にし、区間の終わりを動画の終わりに合わせる。
- 新しいクリップの名前は「Clip Mod <番号>」であり、番号はスタックのクリップの数に1を足したものである。
- 新しいクリップは、有効で、1回繰り返し、クロップ無し(動画の全体)、トリガーは「自動進行」である。
- 動画を開いていないときは、ClipViewer はクリップを足さず、「先に動画ファイルをロードしてください」と知らせる。

### 5.4 区間の帯で区間を決める

区間の帯とは、横に長い1本の帯の上に、クリップの区間を塗った部分と、開始と終了のつまみと、再生の位置の印を重ねた部品のことである。帯の左端から右端までが、帯の受け持つ時間の範囲である。

カードには次の2本の帯がある。

| 帯 | 帯の範囲 |
|---|---|
| 全体の帯 | 0秒から動画の終わりまで。動画の全体の中で、クリップがどこにあるかを見せる |
| 拡大の帯 | 区間の前後に余白(区間の長さの半分と2秒の大きい方)を足した範囲。0秒より前と動画の終わりより後ろは含めない。長い動画の短いクリップを細かく動かすための帯である |

- 拡大の帯の上には、帯の範囲の秒数が「拡大 12.30〜18.40秒」の形で出る。
- 拡大の帯の範囲が全体の帯の範囲と同じになるとき(短い動画のとき)は、拡大の帯は出ない。
- 区間を塗った部分は琥珀色、つまみは白に近い色、再生の位置の印は空色で描かれる。
- 再生の位置の印は、選んでいるカードの帯にだけ描かれる。拡大の帯には、再生の位置が帯の範囲の中にあるときだけ描かれる。

利用者が帯の上で行う操作と、その結果は次のとおりである。

| 利用者の操作 | 動かしている間 | 放したとき |
|---|---|---|
| 開始のつまみをドラッグする | 開始がつまみの位置へ動く。プレビューと出力に、新しい開始の位置のコマが映る | 区間が決まる |
| 終了のつまみをドラッグする | 終了がつまみの位置へ動く。プレビューと出力に、新しい区間の中の最後のコマが映る | 区間が決まる |
| 区間を塗った部分をドラッグする | 区間の長さを保ったまま、区間全体が動く。区間の終わりが動画の終わりに着くと、区間はそこで止まる。新しい開始の位置のコマが映る | 区間が決まる |
| 選んでいるカードで、位置の印をドラッグするか、区間の外を押す | 指した位置のコマが映る。シーケンス再生と単独クリップ再生では、ClipViewer は指した位置を区間の開始から区間の中の最後のコマまでの間に収めてから映す | 再生の位置がその位置へ移る |

- ドラッグの間、ClipViewer は再生を一時止め、音を出さない。ドラッグの前に再生していたなら、ClipViewer は利用者が放したときに再生を再開する。
- ClipViewer は、開始を終了より0.05秒以上前に、終了を開始より0.05秒以上後ろに保つ。ClipViewer は区間を0秒から動画の終わりの間に収める。
- つまみで決めた秒は、ClipViewer が0.01秒の倍数へ丸める。つまみで動かさなかった方の端は、ClipViewer は丸めない。区間を塗った部分をドラッグしたときは、ClipViewer は開始だけを0.01秒の倍数へ丸め、終了を開始に区間の長さを足した位置にする(終了は丸めない)。ただし、端が止まる位置(開始が終了の0.05秒前、区間の終わりが動画の終わり)で止まったときは、秒はその止まった位置になり、0.01秒の倍数とは限らない。
- 区間が変わったときは、ClipViewer は利用者が放したときに再生の位置をそのクリップの開始へ移す。区間が変わらなかったときは、ClipViewer は再生の位置を動かさない。
- 位置の印で再生の位置が移る先は、シーケンス再生では、そのクリップの1周目の中の指した位置である。単独クリップ再生では、区間の中の指した位置である。元動画再生では、ClipViewer は指した位置へそのまま移し、区間の中へ収めない。
- シーケンス再生で、有効でないか長さが0のクリップの帯の位置の印を利用者が放すと、ClipViewer は再生の位置を移さず、「無効か長さ0のクリップの中へは、シーケンス再生では移れない」と知らせる。
- 利用者が選んでいないカードの帯を押すと、ClipViewer はまずそのカードを選ぶ(5.2節の規則で再生の位置を合わせる)。利用者がつまみか区間を押したときは、そのまま区間のドラッグも始まる。利用者が区間の外を押したときは、ClipViewer はカードを選ぶだけである。
- 選んでいるカードでも、再生の位置が拡大の帯の範囲の外にあるときは、拡大の帯に位置の印が描かれない。このとき利用者が拡大の帯の区間の外を押しても、ClipViewer は再生の位置を動かさない。

別の動画の JSON を読み込んだときのように、区間の終わりが動画の終わりより後ろにあるときは、全体の帯の上に「区間(…〜…秒)が動画の終わり(…秒)より後ろまである。区間の帯の端の三角は範囲の外を指す。区間を動画の中へ収める」と出て、拡大の帯は出ない。

### 5.5 数値で区間を決める

カードの4行目(開始)と5行目(終了)で、利用者は区間の開始と終了を数値で決められる。2つの行は同じ並びであり、どちらの行のボタンも、その行の端だけを動かす。

- 開始の秒の欄と終了の秒の欄は、小数点以下2桁で秒を出す。
- 利用者が欄をドラッグすると、値が変わる。マウスを右か上へ動かすと値が増え、左か下へ動かすと値が減る。Shift キーを押さないときは、値は0.1秒の倍数に揃い、マウスをおよそ2画素(Windows の表示の拡大が100%のとき)動かすごとに0.1秒変わる。Shift キーを押しながらドラッグすると、値は0.01秒の倍数に揃い、およそ2画素ごとに0.01秒変わる。
- 利用者が欄を選んでいるときに ↑ キーか ↓ キーを押すと、値は0.05秒ずつ変わる。
- 利用者は、欄を押して数を打ち込むこともできる。
- 「-0.5s」はその行の端を0.5秒前へ、「< F」は1コマ前へ、「F >」は1コマ後ろへ、「+0.5s」は0.5秒後ろへ動かす。そのため、利用者は開始を後ろへ動かすか終了を前へ動かして、区間を縮められる。1コマの長さは、開いている動画の1秒あたりのコマ数で決まる。
- 利用者がボタンにマウスを乗せると、「開始を0.5秒前へ」のように、そのボタンが動かす端と量と向きが出る。
- どの操作でも、ClipViewer は開始を終了より0.05秒以上前に、終了を開始より0.05秒以上後ろに保ち、区間を0秒から動画の終わりの間に収める。利用者が開始を終了より後ろへ打ち込むと、開始は終了の0.05秒前で止まる。
- 欄のドラッグと ↑・↓ キーで決めた秒は、0.01秒の倍数になる(端が止まる位置で止まったときを除く)。打ち込んだ値と、「-0.5s」「< F」「F >」「+0.5s」で決めた秒は、ClipViewer は0.01秒の倍数へ丸めない。
- 数値の欄とボタンで区間を変えても、ClipViewer は再生の位置を動かさない。

### 5.6 今の位置を区間の端にする(I・O)

「開始を今の位置に」と「終了を今の位置に」は、区間の端を今の位置(5.3節)に合わせる。I キーと O キーは、選んでいるクリップに同じことを行う(編集の構えだけで効く)。

| 操作 | 結果 |
|---|---|
| 「開始を今の位置に」・I キー | 今の位置が終了より前なら、ClipViewer は開始だけを今の位置へ動かす。今の位置が終了以降なら、ClipViewer は区間の長さを保ったまま、開始を今の位置へ動かす。区間の終わりが動画の終わりに着くと、区間はそこで止まる |
| 「終了を今の位置に」・O キー | 今の位置が開始より後ろなら、ClipViewer は終了だけを今の位置へ動かす。今の位置が開始以前なら、ClipViewer は区間の長さを保ったまま、終了を今の位置へ動かす。区間の開始が0秒に着くと、区間はそこで止まる |

区間が変わると、ClipViewer はそのクリップを選び、再生の位置をそのクリップの開始へ移す。区間が変わらなかったときは、ClipViewer は何もしない。

### 5.7 名前を変える

利用者はカードの名前の欄に名前を打ち込める。ClipViewer は、利用者が Enter を押すか、欄の外を押したときに名前を決める。利用者が打ち込んでいる途中で Escape を押すと、欄は打ち込む前の名前に戻る。名前は空でもよい。

### 5.8 繰り返し(リピート)

- 6行目の回数は、クリップの区間を何回続けて再生するかを示す。「1x」は1回、「3x」は3回である。回数は1から100までである。
- 「+」は回数を1つ増やし、「-」は1つ減らす。回数は100より多く、1より少なくはならない。
- 利用者が「無限」のチェックボックスに印を付けると、クリップは回数を決めずに繰り返す(無限ループ)。このとき回数の所には「無限」と出る。利用者が印を外すと、回数は1回になる。無限ループのクリップで利用者が「+」を押すと回数は2回に、「-」を押すと1回になる。

### 5.9 トリガー

トリガーの選択欄には次の4つがある。

| 選択肢 | 次のクリップへ進む条件 |
|---|---|
| 自動進行 | 決めた回数を再生し終えたら、自動で次へ進む |
| Enter待ち | 利用者が Enter キーを押すと次へ進む |
| Space待ち(Enterで進む) | 利用者が Enter キーを押すと次へ進む。Space キーは再生と停止に使うため、Space キーでは進まない |
| Click待ち | 利用者が出力の映像を押すと次へ進む |

「Space待ち(Enterで進む)」は、ブラウザ版の ClipViewer の「Space待ち」のファイルを読み書きできるように残してある選択肢であり、ClipViewer の中では「Enter待ち」と同じに振る舞う。

Enter キーは、シーケンス再生のとき、トリガーに関わらず次のクリップへ進める(6.4節)。「Enter待ち」が「自動進行」と違うのは、ClipViewer が最後の1周でクリップの終わりに待つことである。

待つクリップとは、トリガーが「自動進行」以外のクリップと、無限ループのクリップのことである。シーケンス再生で待つクリップを再生すると、次のようになる。

- ClipViewer は、決めた回数の最後の1周に入ると、その1周を繰り返しながら待つ。無限ループのクリップでは、ClipViewer は1周目から待つ。
- 待っている間、出力に「トリガー待機中」の札が出る。札には、進め方の案内と「Next Clip」のボタンが並ぶ。札は、編集の構えでは出力の下に、シアターの構えでは出力の上に出る。
- 利用者が Enter キーを押すか、トリガーが「Click待ち」のクリップで出力を押すと、ClipViewer は次のクリップへ進む。これらの操作は、最後の1周より前の周でも次へ進める。
- 「自動進行」の無限ループのクリップは、利用者が「Next Clip」のボタンか、PageDown キーか、Enter キーを押したときだけ次へ進む。

札に出る案内の文は次のとおりである。

| トリガー | 案内 |
|---|---|
| 自動進行(無限ループのとき) | 「無限ループ中です。Nextボタンで進めてください」 |
| Enter待ち | 「Enterキーを押すか、Nextボタンで進めてください」 |
| Space待ち(Enterで進む) | 「Space待ちは Enterキーで進む(Space は再生と停止に使う)。Enterキーを押すか、Nextボタンで進めてください」 |
| Click待ち | 「出力映像をクリックするか、Nextボタンで進めてください」 |

### 5.10 有効と無効

カードの1行目の左端の「有効」のチェックボックスは、クリップが有効かを示す。印を外したクリップ(無効なクリップ)は、シーケンス再生で飛ばされ、再生の時間を占めない。無効なクリップも、スタックと保存するファイルには残る。

再生できるクリップとは、有効で、区間の長さが0でないクリップのことである。

### 5.11 クロップ(切り抜く範囲)

クロップの枠とは、プレビューの上に重なる四角の枠のことであり、動画の絵のどこを切り抜いて出力に映すかを示す。プレビューには、選んでいるクリップのクロップの枠が出る。

- 利用者が枠の内側をドラッグすると、枠は大きさを保ったまま動く。枠は動画の絵の外へは出ない。
- 利用者が枠の四隅のどれかをドラッグすると、枠の大きさが変わる。枠の幅と高さは、動画の幅と高さの5%より小さくならない。
- 出力には、枠の中の絵が大きく映る。
- 新しいクリップのクロップは、動画の全体である。
- プレビューは左右反転(6.8節)をしない。利用者は、クロップの枠を元の動画の向きのまま動かす。

### 5.12 並べ替えと複製

- 「↑」はクリップをスタックの1つ前へ、「↓」は1つ後ろへ動かす。先頭のクリップの「↑」と、末尾のクリップの「↓」は押せない。ClipViewer は、動かしたクリップを選ぶ。
- 利用者が「複製」を押すと、ClipViewer はクリップの写しを元のクリップのすぐ後ろへ差し込み、写しを選び、「クリップを複製しました」と知らせる。写しの名前は、元の名前の後ろに「のコピー」(空白は入らない)を足したものである。ライブラリのスタックを複製したとき(8.6節)と同じ足し方である。
- 利用者は、ドラッグでクリップを並べ替えることはできない。

### 5.13 クリップを削除する

利用者が「削除」を押すと、ClipViewer はそのクリップをスタックから消し、「クリップを削除しました」と知らせる。ClipViewer は確かめるダイアログを出さない。消したクリップを戻すには、利用者は取り消し(10節)を使う。
スタックに残る最後の1つのクリップは削除できず、ClipViewer は「最後の1つのクリップは削除できない」と知らせる。

### 5.14 1つのクリップだけを見る

- 利用者が「このクリップを再生」を押すと、ClipViewer は再生モードを単独クリップ再生(6.1節)に変え、そのクリップを選び、区間の開始から再生を始める。単独クリップ再生は、利用者が止めるまでクリップの区間を繰り返す。
- ClipViewer がそのクリップを単独クリップ再生で再生している間、ボタンは琥珀色の「単独再生を止める」になる。利用者がこのボタンを押すと、ClipViewer は再生を止める。ClipViewer は再生モードと再生の位置を変えない。
- 動画を開いていないときは、ClipViewer は再生せず、「先に動画ファイルをロードしてください」と知らせる。
- 単独クリップ再生からスタック全体を通して見るには、利用者は出力の帯の再生モードを「スタックシーケンス再生」に戻す。

利用者が「先頭へ」を押すと、ClipViewer はそのクリップを選び、今の再生モードのまま、再生の位置をそのクリップの始まりへ移す。移る先は、シーケンス再生ではスタックの中のそのクリップの始まり、単独クリップ再生では区間の先頭、元動画再生では動画の上の区間の開始である。

## 6. 再生する

### 6.1 再生モード

再生モードとは、何を再生するかの決め方のことである。利用者は出力の帯の「再生モード:」で選ぶ。ClipViewer は起動すると「スタックシーケンス再生」で始まる。

| 選択肢 | 再生するもの | 末尾に着いたとき |
|---|---|---|
| スタックシーケンス再生 | 有効なクリップを上から順に、それぞれの回数だけ続けて再生する(シーケンス再生) | 「全体ループ」に従う(6.3節) |
| 選択中クリップのみループ | 選んでいるクリップの区間だけを繰り返す(単独クリップ再生) | いつも区間の先頭へ戻る |
| 元動画のまま全体再生 | クリップを使わず、動画の全体を再生する(元動画再生)。クロップは掛からない | 「全体ループ」に従う(6.3節) |

利用者が再生モードを選ぶと、ClipViewer は再生の位置をそのモードの先頭へ移す。

### 6.2 再生コントロール

再生コントロールには、上から次の5つが並ぶ。

1. **時刻の行。** 「構成パス: 」に続けて今の再生の様子、「<今の時刻> / <全体の長さ>」、「元動画 <区間の開始> / <映しているコマの位置> / <区間の終わり>」が並ぶ。時刻は「分:秒.十分の一秒」(例 01:05.3)で出る。
   - シーケンス再生の様子は「<クリップの名前> (2/3) [Trigger: Enterキー待ち]」の形である。(2/3) は3回のうちの2周目を、無限ループなら (Loop) を示す。トリガーが自動進行なら [Trigger: …] は出ない。再生の位置にクリップが無いときは「待機中」と出る。
   - 単独クリップ再生の様子は「<クリップの名前> [Solo]」、元動画再生の様子は「元動画全体を再生中」である。
   - 全体の長さは、シーケンス再生ではスタックの全体の長さ、単独クリップ再生では選んでいるクリップの区間の長さ、元動画再生では動画の長さである。
2. **再生位置の帯。** 帯の左端から右端までが全体の長さである。利用者が帯をドラッグすると、再生の位置が動く。ドラッグの間、ClipViewer は音を出さない。
3. **再生の操作の行。** 次の表のボタンとつまみが並ぶ。
4. **映像の様子。** 今映しているコマを、ClipViewer がどこから取り出しているかを示す(6.9節)。
5. **音の様子。** 音が鳴っているか、鳴らせないかを示す(6.9節)。

| 部品 | 働き |
|---|---|
| 「-5s」 | 再生の位置を5秒戻す |
| 「< F」 | 再生の位置を1コマ戻す |
| 「再生」/「停止」 | 再生と停止を切り替える。再生している間は「停止」と書かれる。再生の位置が末尾にあるときは、先頭から再生する(6.3節)。動画を開いていないときは何もしない |
| 「F >」 | 再生の位置を1コマ進める |
| 「+5s」 | 再生の位置を5秒進める |
| 「速度」のつまみ | 再生の速さを0.25倍から2倍の間で0.05倍ずつ選ぶ |
| 「音量」のつまみ | 音の大きさを0から1の間で0.05ずつ選ぶ。0で音が出ない |
| 「消音」 | 印を付けると音を消す |
| 「全体ループ」 | 印を付けると、末尾に着いたときに先頭へ戻る(6.3節) |

利用者が「-5s」「< F」「再生」「F >」「+5s」「消音」にマウスを乗せると、同じ働きの今のキー(12節)が出る(例: 既定のキーなら、「再生」は「Space・K」)。利用者が速度のつまみにマウスを乗せると「[ と ] で0.25倍ごとに変える」(既定のキーのとき。12節でキーを変えると、文のキーも変わる)が、音量のつまみにマウスを乗せると「0で無音。速度を変えると音の高さも変わる」が出る。
再生の位置を動かす操作(-5s・+5s・コマ送り・帯)では、ClipViewer は再生の位置を0から全体の長さの間に収める。

### 6.3 末尾での振る舞いと全体ループ

「全体ループ」には、ClipViewer を起動したときに印が付いている。

- 印が付いているとき: シーケンス再生と元動画再生は、末尾に着くと先頭へ戻って再生を続ける。
- 印が無いとき: シーケンス再生と元動画再生は、末尾に着くと再生を止める。出力には最後のコマが残る。

シーケンス再生と元動画再生で、再生の位置が末尾にあるとき(末尾で止まった後や、利用者が再生位置の帯を右の端まで動かした後)に利用者が「再生」を押すと、ClipViewer は再生の位置をそのモードの先頭へ移してから再生を始める。Space キーと K キーも同じである。

単独クリップ再生は、「全体ループ」に関わらず、いつも区間の先頭へ戻って繰り返す。

### 6.4 次のクリップへ・前のクリップへ

シーケンス再生のときだけ、出力の右下に「前へ」と「Next Clip」のボタンが出る(シアターの構えでは、ボタンは操作の欄の右上に出る)。

- 利用者が「Next Clip」を押すと、ClipViewer はトリガーを待たずに、次の再生できるクリップ(5.10節)の始まりへ進み、そのクリップを選ぶ。PageDown キーと Enter キーも同じである。
- 利用者が最後のクリップで「Next Clip」を押すと、ClipViewer は、「全体ループ」に印が付いていれば最初の再生できるクリップへ進み、印が無ければ再生を止めて最後のコマを出す。
- 利用者が「前へ」を押すと、ClipViewer は1つ前の再生できるクリップの始まりへ戻り、そのクリップを選ぶ。先頭のクリップにいるときは、ClipViewer はそのクリップの始まりへ戻る。末尾で止まっているときは、ClipViewer は最後の再生できるクリップの1つ前へ戻る。PageUp キーも同じである。
- 「前へ」と「Next Clip」は、再生しているか止めているかを変えない。
- 再生の位置にクリップが無いとき(再生コントロールに「待機中」と出ているとき)は、利用者が「Next Clip」か PageDown キーか Enter キーを押しても、ClipViewer は何もしない。
- 単独クリップ再生と元動画再生では、2つのボタンは出ず、PageUp と PageDown は何もしない。利用者が Enter キーを押すと、ClipViewer は次へ進まずに「Enter で次へ進めるのはシーケンス再生のときだけです」と知らせる。

### 6.5 速度

- 速度のつまみは、0.25倍から2倍までを0.05倍刻みで選ぶ。
- [ キーは速度を1つ遅い選択肢へ、] キーは1つ速い選択肢へ変える。選択肢は 0.25・0.5・0.75・1・1.25・1.5・1.75・2 の8つである。利用者がつまみで選択肢の間の速さ(1.1倍など)を選んでいたときは、ClipViewer はキーを押した向きで一番近い選択肢へ移す。速度は0.25倍より遅く、2倍より速くはならない。
- 利用者が速度を変えると、音の高さも変わる。速くすると音は高くなり、遅くすると低くなる。

### 6.6 音量と消音

- 音量のつまみは0から1までを選ぶ。0では音が出ない。音量の最初の値は0.5である。ClipViewer は音量を次の起動に持ち越す(13節)ため、前の起動で保存した音量があるときは、ClipViewer はその値で始める。
- 利用者は、M キーか「消音」のチェックボックスで、音を消したり戻したりできる。音を消している間も、ClipViewer はつまみの音量を覚えていて、戻すとその音量で鳴らす。
- 音を消している間に利用者が音量のつまみを動かすと、ClipViewer は消音をやめる。

### 6.7 アスペクト比と表示サイズ

アスペクト比とは、出力の横と縦の長さの比のことである。利用者は出力の帯の「出力アスペクト比:」で選ぶ。最初の値は「クロップ枠に合わせる」である。ClipViewer はアスペクト比を次の起動に持ち越す(13節)ため、前の起動で保存したアスペクト比があるときは、ClipViewer はその値で始める。

| 選択肢 | 出力の形 |
|---|---|
| クロップ枠に合わせる | クロップの枠の形に合わせる |
| 16:9 | 横16・縦9の形 |
| 4:3 | 横4・縦3の形 |
| 1:1 | 正方形 |
| 9:16 | 横9・縦16の縦長の形 |

「クロップ枠に合わせる」では、出力の形はクロップの枠の形と同じであり、映像は伸びない。クロップをしていないクリップでは、出力の形は動画の形と同じである。利用者が「クロップ枠に合わせる」以外を選ぶと、ClipViewer はクロップの枠の中の絵を、選んだ形の出力いっぱいに引き伸ばして映す。クロップの枠の形が選んだ形と違うと、映像は横か縦へ伸びて映る。

表示サイズとは、出力の区画の中で出力をどの大きさに描くかの決め方のことである。利用者は出力の帯の「表示サイズ:」で選ぶ。最初の値は「大きめ」である。ClipViewer は表示サイズを次の起動に持ち越す(13節)ため、前の起動で保存した表示サイズがあるときは、ClipViewer はその値で始める。

ClipViewer は、出力の区画の縁に余白を空け、その内側に出力を描く。余白の内側の幅は出力の区画の幅から32論理画素を引いた長さであり、高さは区画の高さから32論理画素を引いた長さである。ただし、ClipViewer は余白の内側の幅を320論理画素より、高さを180論理画素より小さくしない。

| 選択肢 | 出力の大きさ |
|---|---|
| 標準 | 余白の内側の0.84倍の広さに、形を保って収める |
| 大きめ | 余白の内側いっぱいに、形を保って収める |
| 横幅優先 | 余白の内側の幅いっぱいにし、高さは形から決める |
| 余白なし | 余白の内側を覆いつくす大きさにし、形を保つ |

出力が出力の区画より大きくなるのは、次の2つのときである。

- 「横幅優先」と「余白なし」では、出力が余白の内側より大きくなることがあり、そのため出力の区画より大きくなることがある。
- 出力の区画の幅が320論理画素より小さいか、高さが180論理画素より小さいときは、余白の内側が出力の区画より大きくなる。そのため、「標準」と「大きめ」でも、出力が出力の区画より大きくなることがある。例えば、出力の区画が幅300・高さ600で、出力の形が16:9のとき、「大きめ」の出力は幅320・高さ180になり、区画より20論理画素広い。

出力が出力の区画より大きくなったとき、横にはみ出した分は、ClipViewer が出力を中央に寄せるため左右の端が切れる。縦にはみ出した分は、ClipViewer が出力を上の端に揃えるため下の端が切れる。

表示サイズは編集の構えでだけ効く。シアターの構えでは、ClipViewer は表示サイズに関わらず、出力をアプリのウインドウいっぱいに形を保って収める(7節)。

### 6.8 左右反転

利用者が出力の帯の「左右反転」に印を付けると、ClipViewer は出力の映像を鏡のように左右を入れ替えて映す。左右反転は、ダンスの振りを鏡に映したように見て練習するときに使う。

- 左右反転は、編集の構えの出力と、シアターの構えの映像の両方に効く。
- サイドバーのプレビューとクロップの枠は、左右反転しない。
- 左右反転はクリップごとの設定ではなく、見る人の好みの設定である。ClipViewer は左右反転をスタックのファイルに保存しない。ClipViewer は左右反転を次の起動に持ち越す(13節)。

### 6.9 映像と音の様子

溜めるとは、ClipViewer がクリップの区間のコマと音を、再生する前に FFmpeg で読んでパソコンのメモリに持っておくことである。流し読みとは、ClipViewer が動画を前から順に FFmpeg で読みながら再生することである。
ClipViewer は、再生するクリップの区間を溜める。溜め終えた区間は、繰り返しのつなぎ目で途切れずに再生される。溜め終えるまでの間は、ClipViewer は流し読みで再生する。流し読みでは、繰り返しのつなぎ目で映像が詰まることがある。
利用者が区間を変えると、ClipViewer は区間の変化が止まってから0.4秒待って溜め始める。

再生コントロールの映像の様子の行には、次のどれかが出る。

| 表示 | 意味 |
|---|---|
| 「溜めたコマで再生中(区間の継ぎ目で途切れない)」 | 今の区間を溜め終え、溜めたコマを映している |
| 「区間を溜めている N/Mコマ(流し読みで再生中)」と進み具合の棒 | 今の区間を溜めている途中であり、今は流し読みで映している |
| 「区間を溜める依頼を待っている(流し読みで再生中)」・「区間を溜める順番を待っている(流し読みで再生中)」 | 溜め始める前であり、今は流し読みで映している |
| 「区間を溜め終えた(流し読みで再生中)」 | 区間を溜め終えたが、このときは流し読みで映している |
| 「区間を溜められない: <理由>(流し読みで再生中)」 | 区間を溜められなかったので、流し読みで映している。区間が大きすぎるときは「区間が大きすぎる(約…MB。上限は約…MB)」が理由に出る |
| 「元動画を流し読みで再生中」 | 元動画再生で、流し読みで映している |
| 「映せない: <理由>」 | 映像を映せない |

再生コントロールの音の様子の行には、次のどれかが出る。動画を開いておらず、音を出す装置も使えるときは、何も出ない。

| 表示 | 意味 |
|---|---|
| 「音: 溜めた音で鳴らしている(区間の継ぎ目で途切れない)」 | 今の区間の音を溜め終え、溜めた音を鳴らしている |
| 「音: 流し読みで鳴らしている」 | 今の区間の音を、流し読みで鳴らしている |
| 「音: 流し読みで読めない(<理由>)」 | 音を読めない |
| 「音: この動画には音が無い」 | 動画に音が入っていない |
| 「音: 鳴らせない(<理由>)」 | 音を出す装置(スピーカーなど)が使えないか、動画の音を開けない。ClipViewer は映像だけで再生を続ける |

## 7. シアターの構えと全画面

### 7.1 シアターの構え

シアターの構えでは、ClipViewer は出力を、アスペクト比(6.7節)の形を保ったまま、アプリのウインドウいっぱいに収めて映す。ウインドウと出力の形が違うときは、映像の上下か左右に黒い地が残る。

シアターの構えの画面には、次のものが重なって出る。

| 部品 | 場所 | 出方 |
|---|---|---|
| 操作の欄 | 出力の下の端、幅いっぱい | マウスを操作したときだけ出る(下の規則)。半透明の黒の地に、編集の構えと同じ再生コントロールが並ぶ。シーケンス再生のときは、欄の右上に「前へ」と「Next Clip」も並ぶ |
| 「編集へ戻る」 | 右上 | 操作の欄と一緒に出たり隠れたりする。利用者が押すと、ClipViewer は編集の構えへ戻る |
| 「トリガー待機中」の札 | 上の端 | 待つクリップで待っている間、操作の欄が隠れていても出たままである |

操作の欄と「編集へ戻る」の出方の規則は次のとおりである。

- 利用者が出力の上でマウスを動かすか、出力を押すと、欄が出る。利用者が ← キーか → キーを押している間も、欄が出る。
- マウスが止まってから2.5秒たつと、欄は隠れる。一時停止している間も、マウスが欄の上にあっても、マウスが止まれば欄は隠れる。
- 利用者が欄の中で押し始めたドラッグ(再生位置の帯・速度と音量のつまみ)の間は、欄は隠れない。
- マウスがアプリのウインドウの外へ出ると、欄はすぐに隠れる。
- 欄が隠れている間は、出力の上のマウスの矢印も隠れる。利用者がマウスを動かすと、欄と矢印が一緒に戻る。
- 利用者が Space・Enter などのキーを押しても、← と → 以外では欄は出ない。

シアターの構えには、ヘッダーもサイドバーも出力の帯も無い。「JSON保存」や「ライブラリに保存」や「キー設定」を押すには、利用者は編集の構えへ戻る(ライブラリへの保存は Ctrl+S でも、キーの一覧は F1 キーでも開ける)。
利用者が編集の構えで T キーを押すと、ClipViewer はシアターの構えへ移る。シアターの構えから編集の構えへ戻るには、利用者は「編集へ戻る」を押すか、Escape キーか T キーを押す。T キーは、入力欄に文字を打っている間とライブラリの構えでは効かない(12節)。動画を開いていないときのシアターの構えでは、サイドバーが見えないため、ClipViewer は出力の案内(3.2節)の「左の「動画を開く」か、…」の文の代わりに、「ウインドウへ動画をドラッグ＆ドロップすると開けます。」の文を出す。その下に、ClipViewer は「「編集へ戻る」を押すか Escape キーを押すと、編集の構えへ戻ります。」の文と「編集へ戻る」のボタンを出す(「Escape」の所には、全画面かシアターを抜けるキーの今のキーが出る。12節)。このボタンは、マウスを止めても隠れない。

### 7.2 全画面

全画面とは、アプリのウインドウが題名の帯と枠を消して、画面全体を覆うことである。全画面はシアターの構えとは別のものであり、利用者は2つを組み合わせられる。利用者がシアターの構えで全画面にすると、動画が画面全体に出る。

- 利用者が F11 キーか、出力の帯の「全画面」を押すと、アプリのウインドウは全画面になる。利用者がもう一度押すと、元のウインドウに戻る。F11 キーは、どの構えでも、ダイアログを開いている間でも効く。ただし、利用者が名前の欄・数値の欄・パスの欄などの入力欄に文字を打っている間は、F11 キーは効かない。ClipViewer は、入力欄に文字を打っている間、Ctrl か Alt を含まないキーをその欄への入力として扱うためである(12節)。
- 利用者が Escape キーを押すと、ClipViewer は、全画面なら全画面だけを抜ける(構えは変えない)。全画面でなくシアターの構えなら、ClipViewer は編集の構えへ戻る。シアターの構えで全画面にしているときは、利用者が Escape キーを2回押すと、編集の構えの普通のウインドウへ戻る。

## 8. ライブラリ

### 8.1 ライブラリに登録する

ライブラリが保存するのは、動画のパスと、スタックのクリップ(各クリップの名前・有効か・区間・繰り返し・クロップ・トリガー)と、スタックの名前と、作った日時・更新した日時だけである。ClipViewer は動画を写さないため、クリップをいくつ作っても、保存するデータはほとんど増えない。ClipViewer は、選んでいるクリップ・再生の位置・出力の設定を保存しない。

登録とは、利用者がスタックに名前を付けて、初めてライブラリへ保存することである。未登録のスタックとは、ライブラリに登録していないスタックのことである。動画を開いてクリップを作っただけのスタックは未登録である。ClipViewer は、未登録のスタックを自動では保存しない。

未登録のスタックを登録する手順は次のとおりである。

1. 利用者が、ヘッダーの「ライブラリに保存」を押すか、Ctrl+S キーを押す。「ライブラリに保存」は、動画を開いていて、クリップが1つ以上あるときだけ押せる。
2. ClipViewer は「ライブラリに保存する名前」のダイアログを出す。名前の欄には、動画のファイル名から拡張子を除いたものが最初から入っている。
3. 利用者が名前を決めて「保存する」を押すと、ClipViewer はスタックを登録済みにして、ライブラリへの書き込みを始める。書き終えたら、ClipViewer は「ライブラリに保存しました: <名前>」と知らせる。利用者が「やめる」を押すか、ダイアログの外を押すか、Escape キーを押すと、ClipViewer は登録しない。

- 名前が空か空白だけのときは、ClipViewer は登録せず、「名前を入力してください」と知らせる。ClipViewer は名前の前後の空白を取り除く。
- 名前はほかのスタックと同じでもよい。
- 利用者は、同じ動画から、スタックをいくつ登録してもよい。
- 書き込みを頼めなかったときは、ClipViewer は登録せず、「ライブラリへ保存できない: <理由>」と知らせる。
- 書き込みを始めた後で書けなかったときは、ClipViewer は「ライブラリへ保存できない: <理由>」と知らせる。スタックは登録済みのままであり、ClipViewer は自動保存と同じく3秒ごとに書き込みをやり直し、ヘッダーに「保存に失敗: <理由>」を出す(8.2節)。後で書けても、ClipViewer は「ライブラリに保存しました」を知らせない。

### 8.2 自動保存

登録したスタックを開いている間、ClipViewer はクリップを変えるたびに自動でライブラリへ保存する。

- ClipViewer は、スタックが最後に保存を始めたときと違えば、変化が止まってから0.5秒後に保存を始める。利用者が選んでいるクリップを変えただけでは、ClipViewer は保存しない。利用者が区間の帯をドラッグしている間は、ClipViewer は保存しない。
- 保存に失敗すると、ClipViewer は3秒ごとに保存をやり直す。
- 取り消し(10節)でスタックが変わったときも、ClipViewer は自動で保存する。

ヘッダーには、今のスタックの保存の様子が次のどれかで出る。

| 表示 | 意味 |
|---|---|
| 「ライブラリ: 未登録」と「ライブラリに保存」のボタン | 未登録のスタックである |
| 「ライブラリ: <名前>」と「保存済み」 | 今のスタックをライブラリに書けている |
| 「ライブラリ: <名前>」と「変更を保存待ち」 | ClipViewer は、変わったスタックを保存する前の0.5秒の間待っている |
| 「ライブラリ: <名前>」と「保存中」 | ClipViewer が書き込んでいる途中である。保存に失敗した後のやり直しで書き込んでいる間も、「保存に失敗」でなく「保存中」が出る |
| 「ライブラリ: <名前>」と「保存に失敗: <理由>」 | 書けなかった。この表示は、次の保存が成功するまで出続ける(やり直しで書き込んでいる間を除く)。ClipViewer は、自動保存の失敗を知らせの文では繰り返さない |
| 「ライブラリ: 読み取り専用(別の ClipViewer が開いている等。一覧の画面に理由を出す)」 | ライブラリへ書けない(8.9節) |
| 「ライブラリ: 使えない(置き場所が無い)」 | ライブラリの置き場所が無い(15.10節) |

登録したスタックで利用者が Ctrl+S キーを押すと、ClipViewer は変化が止まるのを待たずに、すぐに保存を始める。保存を待っている変更が無ければ、ClipViewer は「保存済みである(登録済みのスタックは変えるたびに自動で保存している)」と知らせる。
登録したスタックを開いている間は、ヘッダーに「ライブラリに保存」は出ない。

### 8.3 一覧

ライブラリの構えの画面は、上から道具の帯、置き場所の文、一覧の順に並ぶ。

- 道具の帯には、「ライブラリ」、登録してあるスタックの件数(「12件」の形。読めないファイルも数える)、「名前で絞り込む」の欄、並べ替えの選択欄、「読み直す」、「v4.0 JSON を取り込む」が並ぶ。
- 置き場所の文は「置き場所: <ライブラリのフォルダ>」である。
- ClipViewer は、起動したときと、ライブラリの構えへ移ったときと、登録・取り込み・名前の変更・複製・削除・動画の場所の変更の後に、一覧を読み直す。利用者が「読み直す」を押したときも、ClipViewer は一覧を読み直す。
- ClipViewer が最初の一覧を読み終えるまでは、「一覧を読んでいる」と出る。2回目からの読み直しの間は、ClipViewer は前に読んだ一覧を出し続け、読み終えたら新しい一覧に替える。
- ライブラリのフォルダを読めなかったときは、「ライブラリのフォルダを読めない: <理由>」と出る。
- スタックが1つも無いときは「ライブラリにスタックがありません」と「編集の構えで動画を開いてクリップを作り、ヘッダーの「ライブラリに保存」で登録する」が出る。

一覧の1行には、左にサムネイル(8.4節)、右に次のものが並ぶ。

- スタックの名前。今開いているスタックの行には「開いている」が、動画がそのパスに無いスタックの行には「動画が見つからない」が並ぶ。
- 「<動画のファイル名> ・ <N>クリップ ・ 合計 <長さ> ・ 更新 <年-月-日 時:分>」。合計の長さとは、全クリップの区間の長さを足したもののことであり、繰り返しの回数は掛けない。更新の日時は、このパソコンの時間帯で出る。
- 「開く」「名前を変える」「複製する」「削除する」のボタン。動画が見つからないスタックには「動画の場所を指定し直す」も並ぶ。

**絞り込み。** 利用者が「名前で絞り込む」の欄に文字を打つと、一覧には名前にその文字を含むスタックだけが出る。大文字と小文字は区別しない。

**並べ替え。** 並べ替えの選択欄には「更新日時の新しい順」(最初の値)・「更新日時の古い順」・「名前順」・「作った日時の新しい順」がある。

**読めないファイル。** ライブラリのフォルダに読めないスタックのファイル(拡張子が json のファイル)があると、一覧の最後に「読めない: <ファイル名>」と理由の行が出る。読めない行は、絞り込みと並べ替えに関わらず最後に出る。ClipViewer は、読めないスタックのファイルを書き換えず、消しもしない。
より新しい版の ClipViewer が保存したスタックは、「このアプリより新しい ClipViewer で保存された。ClipViewer を更新すれば開ける」の意味の理由で読めない行になる。

ClipViewer は、一覧を作るたびに、ライブラリのフォルダの一部のファイルを消す(14.1節)。

### 8.4 サムネイル

サムネイルとは、一覧の各行の左に出す、スタックの中身を示す小さな画像のことである。ClipViewer は、スタックの中の最初の再生できるクリップ(5.10節)の開始のコマに、そのクリップのクロップを掛けた絵をサムネイルにする。

- ClipViewer は、ライブラリの構えを開いている間だけサムネイルを作る。ClipViewer は、画面に見えている行から先に作り、見えている行を終えたら残りの行も作っておく。
- ClipViewer は、一度作ったサムネイルを控えとしてとっておき(置き場所は14.1節)、次からはそれを出す。
- 最初の再生できるクリップの開始・クロップ・動画のパスのどれかが変わると、ClipViewer はサムネイルを作り直す。利用者が先頭のクリップを無効にしたときのように、最初の再生できるクリップが別のクリップに変わったときも、ClipViewer は作り直す。
- サムネイルの枠には、作る前と作る途中に「読んでいる」「撮る順番を待っている」「撮っている」のどれかが出る。
- ClipViewer がサムネイルを作らないときは、枠に理由が出る: 「動画が無い」(動画がそのパスに無い)、「再生できるクリップが無い」、「FFmpeg が無い」。
- ClipViewer がサムネイルを作れなかったときは、枠に「撮れない」と出る。利用者が枠にマウスを乗せると理由が出る。
- 動画がそのパスに無くても、前に作ったサムネイルがあれば、ClipViewer はそれを出す。

### 8.5 開く

利用者が一覧の「開く」を押すと、ClipViewer はそのスタックの動画を開き、スタックを今のスタックにし、先頭のクリップを選び、今の再生モードの先頭から再生を始め、編集の構えへ移る。ClipViewer は「ライブラリから開きました: <名前>」と知らせる。

- 今のスタックが未登録で、利用者がクリップを変えていたときは、ClipViewer は開く前に確かめるダイアログを出す(11節)。
- 今のスタックが登録済みで、保存を待っている変更があるときは、ClipViewer は先に保存してから開く。
- 動画を開けないときは、ClipViewer は今の画面を変えず、「動画を開けない(<動画のパス>): <理由>」と知らせる。ffprobe が異常終了したとき(4.5節)は、理由の後ろに「動画を移動したなら、一覧の「動画の場所を指定し直す」で指定する」が付く。ffprobe のほかの失敗(ファイルに映像が無いとき等)では、この案内は付かない。
- ClipViewer は、開いたスタックを登録済みのスタックとして扱い、以後は自動で保存する。

### 8.6 名前を変える・複製する・削除する

- 利用者が「名前を変える」を押すと、ClipViewer は「新しい名前」のダイアログを出す。利用者が名前を打ち込んでダイアログの「名前を変える」を押すと、ClipViewer は名前を変え、「名前を変えました」と知らせる。名前が空のときは、ClipViewer は「名前を入力してください」と知らせる。
- 利用者が「複製する」を押すと、ClipViewer はそのスタックの写しを、名前の後ろに「のコピー」(空白は入らない)を足した名前で登録し、「複製しました」と知らせる。
- 利用者が「削除する」を押すと、ClipViewer は「「<名前>」をライブラリから削除しますか。削除すると元に戻せない(動画は消えない)」のダイアログを出す。利用者がダイアログの「削除する」を押すと、ClipViewer はスタックのファイルを消し、「削除しました」と知らせる。ClipViewer はファイルをごみ箱へ送らないため、削除したスタックは戻せない。動画は消えない。
- 利用者が今開いているスタックを削除すると、今のスタックは未登録に戻る。削除した後のスタックはどこにも保存されていないため、ClipViewer はそのスタックを捨てる前に確かめるダイアログを出す(11節)。
- ライブラリのスタックを変えられなかったときは、ClipViewer は「ライブラリのスタック <識別子> を変えられない: <理由>」と知らせる。識別子とは、ClipViewer がスタックごとに自動で付ける英数字の名前のことである。

### 8.7 動画の場所を指定し直す

利用者が動画を別のフォルダへ移したり、動画のファイル名を変えたりすると、そのスタックの行には「動画が見つからない」が出る。利用者が「動画の場所を指定し直す」を押し、ファイルを選ぶダイアログで動画を選ぶと、ClipViewer はスタックの動画のパスを選んだ動画のパスに変え、「動画の場所を指定し直しました」と知らせる。

### 8.8 v4.0 JSON を取り込む

v4.0 JSON とは、ブラウザ版の ClipViewer が書き出すスタックのファイル(9節の JSON と同じ形式)のことである。

利用者が「v4.0 JSON を取り込む」を押してファイルを選ぶと、ClipViewer はそのファイルのスタックを新しいスタックとしてライブラリへ登録し、書き終えたら「ライブラリへ取り込みました: <名前>」と知らせる。ClipViewer は、取り込んだスタックを開きはしない。

- 取り込んだスタックの名前は、JSON のファイル名から拡張子を除いたものである。
- JSON が動画のパス(expectedVideoPath)を持っていないときは、ClipViewer は取り込まず、「取り込めない: 設定ファイルに動画のパス(expectedVideoPath)が無いため、どの動画のスタックか分からない」と知らせる。
- ライブラリの構えのときに利用者が拡張子が json のファイルをアプリのウインドウへ落としても、ClipViewer は同じく取り込む。
- ライブラリが読み取り専用のときは、「v4.0 JSON を取り込む」は押せない。読み取り専用のときに利用者がライブラリの構えで JSON を落とすと、ClipViewer は取り込もうとして、「ライブラリへ書き込めない: <理由>」と知らせる。

### 8.9 読み取り専用で開いたとき

錠とは、1つの ClipViewer だけがライブラリへ書けるようにするために、ClipViewer がライブラリのフォルダの錠のファイル(`ClipViewer.lock`)を開いて持ち続けることである。錠を持った ClipViewer が終わると、Windows が錠を外す。
ClipViewer は、同じライブラリへ書き込める ClipViewer を、錠を持った1つに限る。錠を持てない ClipViewer は、ライブラリを読み取り専用で開く。

ClipViewer がライブラリを読み取り専用で開くのは、次のときである。

- ほかの ClipViewer が錠を持っているとき。ClipViewer は起動したときに錠を1回だけ試し、取れなければ必ず読み取り専用で起動する。利用者が ClipViewer を複数起動すると、先に起動した ClipViewer が錠を持つため、後から起動した ClipViewer はふつうこれに当たる(4.4節)。ほかの ClipViewer が落ちた直後で、Windows がまだ錠を外していないときも、これに当たる。
- 錠のファイルを作れないか、読み書きできないとき(ライブラリのフォルダへ書く権限が無い等)。このとき、読み取り専用の理由は「ライブラリの錠を取れない: …」になる。

読み取り専用のとき、ClipViewer は次のように振る舞う。

- ヘッダーに「ライブラリ: 読み取り専用(別の ClipViewer が開いている等。一覧の画面に理由を出す)」が出る。一覧の画面の置き場所の文は「読み取り専用: <理由>。開くことはできるが、登録・保存・名前の変更・複製・削除・取り込みはできない(置き場所: …)」になる。
- 利用者は、一覧を読み直すことと、スタックを開くことができる。
- 「名前を変える」「複製する」「削除する」「動画の場所を指定し直す」「v4.0 JSON を取り込む」は押せない。
- ClipViewer は、読み取り専用で開いたスタックを、未登録のスタックとして開く。ClipViewer は「ライブラリから読み取り専用で開きました: <名前>。変更はライブラリへ保存しない」と知らせる。変えたスタックを残すには、利用者は「JSON保存」(9節)でファイルに書き出す。
- 読み取り専用の ClipViewer は、ウインドウの大きさや音量などの見る人の設定(13節)を保存しない。
- 読み取り専用で起動した ClipViewer も、自分を起動したときに渡された動画(エクスプローラーから開いた動画)は開く。読み取り専用の ClipViewer が受け取らないのは、以前の版の ClipViewer が起動したときに渡してくる動画(4.4節)だけである。

ほかの ClipViewer が落ちた直後に読み取り専用で開いたときは、利用者は、Windows のタスクマネージャーの「詳細」の一覧に `clip_viewer.exe` が今の1つのほかに残っていないかを確かめる。残っていなければ、利用者が今の ClipViewer を閉じて起動し直すと、ClipViewer はライブラリへ書けるようになる。

## 9. ファイルへの保存と読み込み(JSON)

JSON とは、データを文字で書き表すファイルの形式のことである。ClipViewer は、スタックを JSON のファイルへ書き出し、JSON のファイルから読み込める。このファイルの形式は、ブラウザ版の ClipViewer の設定ファイル(v4.0)と同じであり、利用者は2つのアプリの間でスタックをやり取りできる。
JSON のファイルに入るのは、スタックのクリップ(各クリップの名前・有効か・区間・繰り返し・クロップ・トリガー)と、動画のファイル名と、動画のパスと、書き出した日時である。再生モードや出力の設定は入らない。

### 9.1 JSON保存

利用者がヘッダーの「JSON保存」を押すと、ClipViewer は次のことを行う。

1. クリップが1つも無いときは、ClipViewer は「エクスポートする構成がありません」と知らせて止まる。
2. ClipViewer は「PC内絶対パス:」の欄の値を確かめる。確かめて合格しないときは、ClipViewer は理由を知らせて止まる。
3. ClipViewer は保存先を選ぶダイアログを出す。最初のファイル名は「<動画のファイル名の最初の点より前>_clip_stack_config.json」である。ここでの動画のファイル名とは、スタックを作った動画のファイル名(最後に開いた動画か、読み込んだ JSON が期待する動画のファイル名。4.2節)のことである。動画のファイル名を持たない JSON を読み込んでから次に動画を開くまでの間は、ClipViewer はスタックを作った動画のファイル名を知らないため(JSON を読み込む前から動画を開いていたときも同じである)、最初のファイル名は「stack_clip_stack_config.json」になる。
4. 利用者が保存先を選ぶと、ClipViewer はファイルを書き、「スタック構成をJSON保存しました」と知らせる。書けなかったときは、ClipViewer は「保存失敗: <理由>」と知らせる。

「PC内絶対パス:」の欄は、スタックを作った動画のパスを JSON に書くための欄である。ClipViewer は、動画を開くと、この欄に動画のパスを入れる。欄の値が次のどれかに当たると、ClipViewer は欄の下にその文を出し、JSON保存をしない。

| 文 | 当たるとき |
|---|---|
| 「動画のPC内絶対パスを入力してください」 | 欄が空である |
| 「パス前後の引用符を確認してください」 | パスの前後の引用符(")の片方だけがある |
| 「Windowsの絶対パスを入力してください」 | 「C:\…」のようにドライブから始まる形でも、「\\サーバー\共有\…」のように共有フォルダから始まる形でもない |
| 「動画ファイル名が一致しません: <ファイル名>」 | パスのファイル名が、スタックを作った動画のファイル名と違う |

### 9.2 JSON読込

利用者がヘッダーの「JSON読込」を押してファイルを選ぶと、ClipViewer は次のことを行う。

- ClipViewer は、今のスタックを、読み込んだスタックに置き換え、「設定を読み込みました (<N>クリップ)」と知らせる。置き換える前には、ClipViewer は失われる変更が無いかを確かめる(11節)。
- 動画を開いているときは、ClipViewer はその動画を開いたままにし、読み込んだクリップをその動画に当てる。
- ClipViewer は、JSON が持つ動画のファイル名とパスを覚え、「PC内絶対パス:」の欄に JSON の動画のパスを入れる。JSON が動画のファイル名を持ち、動画を開いていないときは、出力に「対応する元動画が見つかりません」と、期待する動画のファイル名とパスが出る。その後に利用者が同じファイル名の動画を開くと、ClipViewer は読み込んだスタックを残して開く(4.2節)。
- 利用者がライブラリの構えで読み込むと、ClipViewer は編集の構えへ移る。
- 読めないファイルのときは、ClipViewer は今のスタックを変えず、「読み込み失敗: <理由>」と知らせる。

### 9.3 JSON をアプリのウインドウへ落とす

利用者が拡張子が json のファイル(大文字と小文字は区別しない)をアプリのウインドウへ落とすと、ClipViewer は次のように扱う。

- 編集の構えとシアターの構えでは、ClipViewer は「JSON読込」と同じく読み込む。
- ライブラリの構えでは、ClipViewer は「v4.0 JSON を取り込む」と同じくライブラリへ取り込む。
- ダイアログを開いている間に落としたときは、ClipViewer は読み込まず、取り込まない(4.1節)。

利用者がエクスプローラーから ClipViewer で開いたファイルは、拡張子が json でも、ClipViewer は動画として扱う。

## 10. 取り消しとやり直し

**要点。** クリップを直して失敗したら、利用者は編集の構えで Ctrl+Z キーを押す(またはヘッダーの「取り消す」を押す)。取り消しすぎたら、利用者は Ctrl+Y キーを押す(またはヘッダーの「やり直す」を押す)。別の動画を開き直したり JSON を読み込んだりすると、それより前の変更は取り消せなくなる。

**詳しい条件。**

- 取り消すには、利用者は編集の構えのヘッダーの「取り消す」を押すか、Ctrl+Z キーを押す。やり直すには、利用者は「やり直す」を押すか、Ctrl+Y キーか Ctrl+Shift+Z キーを押す。取り消せる変更が無いときは「取り消す」が、やり直せる変更が無いときは「やり直す」が押せない。
- 取り消しとやり直しは、編集の構えでだけ効く。シアターの構えとライブラリの構えには、ボタンが出ず、キーも効かない。
- 利用者が名前の欄や数値の欄に文字を打っている間は、Ctrl+Z・Ctrl+Y・Ctrl+Shift+Z は、その欄の文字の取り消しとやり直しになる。
- ClipViewer は、最大100回分の変更を取り消せる。

**取り消しの対象になるもの。** クリップの追加・削除・複製・並べ替え、区間・名前・有効・繰り返し・トリガー・クロップの変更である。
**取り消しの対象にならないもの。** 選んでいるクリップを変えること、再生の位置・再生モード・速度・音量・アスペクト比・表示サイズ・左右反転・構えを変えることである。
取り消しとやり直しでスタックを戻したときも、ClipViewer は今選んでいるクリップを変えない(選んでいたクリップが戻したスタックに無いときは、ClipViewer は戻したスタックの選択を使う)。その後、ClipViewer は、利用者がカードを押したときと同じ規則(5.2節)で再生の位置を動かす。

**1回分になる変更。** 1回の取り消しで戻る変更の単位は次のとおりである。

- 利用者がボタンやキーを1回押した変更は、1回分である。
- クロップの枠のドラッグは、押してから放すまでが1回分である。
- 区間の帯のドラッグは、押してから放すまでが1回分である。
- 数値の欄のドラッグは、同じクリップの同じ端について、押してから放すまでが1回分である。
- 数値の欄に打ち込んだ値と、名前の欄の名前は、利用者が決めたとき(Enter か、欄の外を押したとき)に1回分になる。

**履歴が消えるとき。** 利用者が次の操作をすると、ClipViewer は取り消しとやり直しの履歴を空にする: 新しいスタックで始める動画の開き方(4.2節)、動画の解除、JSON読込(落とした JSON を含む)、ライブラリから開くこと。同じ名前の動画を開き直してスタックを残すときは、ClipViewer は履歴も残す。
利用者が取り消した後にスタックを変えると、やり直せる変更は消える。
利用者がドラッグをしている途中は、取り消しもやり直しもできない。

## 11. 変更を捨てる前の確かめ

**要点。** ライブラリに登録していないスタックは、自動では保存されない。そのため、ClipViewer は、スタックを捨てる操作(別の動画を開く・解除・JSON読込・一覧から開く・アプリを閉じる)の前に、確かめるダイアログを出すことがある。残したいときは、利用者は「ライブラリに保存する」を押して名前を付ける。要らないときは、利用者は「変更を捨てて続ける」(または「並びを捨てて続ける」)を押す。迷ったときは、利用者は「やめる」を押せば、何も失われない。

### 11.1 未登録のスタックを捨てるとき(詳しい条件)

ClipViewer は、未登録のスタックを捨てる次の操作の前に確かめる。

| 続ける操作 | スタックを捨てるか |
|---|---|
| 動画を開く(「動画を開く」・ウインドウへ落とす・以前の版の ClipViewer から渡された動画を開く(4.4節)) | 4.2節で今のスタックを残せないときだけ捨てる |
| 動画を解除する | 捨てる |
| JSON読込・JSON をウインドウへ落とす | 捨てる |
| ライブラリの一覧から開く | 捨てる |
| アプリを閉じる | 捨てる |

利用者がエクスプローラーから動画を開くと、ClipViewer は新しく起動した ClipViewer の空のスタックへ動画を開く(4.4節)。スタックが空のときは確かめるダイアログが出ないため、エクスプローラーから開いたときは確かめるダイアログが出ない。

ClipViewer が確かめるダイアログを出すのは、スタックが空でなく、次のどちらかに当たるときである。

- **変えているとき。** 今のスタックを始めたとき(動画を開いた・JSON を読み込んだ・ライブラリから開いたとき)から、利用者がクリップを変えている。利用者が選んでいるクリップを変えただけでは、ClipViewer は変えたことに数えない。ClipViewer は、動画を開いたときにできる「Clip Mod 1」も変えたことに数えない。そのため、利用者が動画を開いて何もせずに別の動画を開いても、ダイアログは出ない。
- **読み込んだスタックを別の名前の動画で捨てるとき。** 利用者が、JSON から読み込んだスタック(読み取り専用のライブラリから開いたスタックを含む)を、変えていなくても、名前の違う動画を開いて捨てる。

ダイアログの文とボタンは、2つの場合で次のように違う。

| 場合 | ダイアログの文 | ボタン |
|---|---|---|
| 変えているとき | 「ライブラリに保存していない変更がある。続けると失われる」 | 「ライブラリに保存する」「変更を捨てて続ける」「やめる」 |
| 読み込んだスタックを別の名前の動画で捨てるとき | 「読み込んだ並びは、名前の違う動画を開くと捨てて、最初のクリップだけの並びで始める。続けると今の並びは失われる」 | 「ライブラリに保存する」「並びを捨てて続ける」「やめる」 |

| 利用者が押したもの | 結果 |
|---|---|
| 「ライブラリに保存する」 | ClipViewer は「ライブラリに保存する名前」のダイアログを出す(8.1節)。利用者が登録すると、ClipViewer は書き込みを終えるのを待ってから、元の操作を続ける(アプリを閉じる操作なら、アプリを閉じる)。このボタンは、ライブラリへ書けないとき(読み取り専用のとき)と、動画を開いていないときは押せない |
| 「変更を捨てて続ける」・「並びを捨てて続ける」 | ClipViewer はスタックを捨てて、元の操作を続ける |
| 「やめる」(ダイアログの外を押すか、Escape キーを押したときも同じ) | ClipViewer は何もしない。スタックはそのまま残る |

**確かめる時点。**

- 動画を開く操作では、ClipViewer は、利用者がファイルを選んだ直後(動画を開く前)に確かめる。確かめた後で動画を開けなかったときは、今のスタックはそのまま残る。
- JSON読込では、ClipViewer は、選んだファイルを読んで解釈できた後に確かめる。
- 利用者がファイルを選ぶダイアログで取り消したときと、読めない JSON を選んだときは、確かめるダイアログは出ない。

### 11.2 登録したスタックを保存できないとき(詳しい条件)

登録したスタックを開いているとき、ClipViewer は、スタックとの関係を終える操作(別の動画を開く・動画を解除する・JSON読込・一覧から別のスタックを開く・アプリを閉じる)の前に、今のスタックをライブラリへ書けているかを確かめる。書けていなければ、ClipViewer は保存をやり直して書き終えるのを待つ。
それでも書けないときは、ClipViewer は「開いているスタックを保存できない(<理由>)。続けると、保存できていない変更が失われる」のダイアログを出す。

| 利用者が押したもの | 結果 |
|---|---|
| 「変更を捨てて続ける」 | ClipViewer は元の操作を続ける。保存できていない変更は失われる |
| 「やめる」(ダイアログの外を押すか、Escape キーを押したときも同じ) | ClipViewer は何もしない。スタックとの関係は残り、ClipViewer は保存をやり直し続ける |

利用者が、登録したスタックの動画と同じパスの動画を開き直したときは、ClipViewer はスタックとの関係を保ったまま開き、確かめない。利用者が、ファイル名が同じでもフォルダが違う動画を開いたときは、ClipViewer は確かめてから、スタックを残したまま関係を終える(以後、そのスタックは未登録になる)。

### 11.3 アプリを閉じるとき(詳しい条件)

利用者がアプリのウインドウを閉じると、ClipViewer は11.1節と11.2節と同じ規則で確かめる。確かめるダイアログが要るときは、ClipViewer は閉じるのをやめてダイアログを出す。利用者が「変更を捨てて続ける」を選ぶと、ClipViewer は閉じる。
登録したスタックに書き終えていない変更があるときは、ClipViewer は閉じる前に書き終えるのを待つ。

## 12. キー操作の一覧とキーの設定

### 12.1 キーの一覧

利用者が F1 キーを押すか、画面の上の「キー設定」を押すと、ClipViewer は「キーの一覧」のダイアログを出す。「キー設定」は編集の構えとライブラリの構えのヘッダーにある(シアターの構えにはヘッダーが無いため、T キーか Escape キーで編集の構えへ戻ってから押す)。「キー設定」にマウスを乗せると、キーの一覧を開くキー(既定は F1)が出る。このダイアログは、次の表の操作を同じ順に1行ずつ、「働き」「今のキー」「効く構え」の3列と、「変更」と「既定に戻す」のボタンで出す。今のキーとは、その操作に今割り当てているキーのことである。利用者がキーを変えていなければ(12.2節)、今のキーは表の「既定のキー」の列と同じである。キーを2つ持つ操作では、今のキーの列に2つのキーが「・」でつないで出る。

利用者がもう一度 F1 キーを押すか、Escape キーを押すか、ダイアログの外を押すか、「閉じる」を押すと、ダイアログは閉じる。この説明書のほかの節に書いたキーは、既定のキーである。

「効く構え」の列の「ダイアログ」は、1節で定義したダイアログを指す。

| 既定のキー | 働き | 効く構え |
|---|---|---|
| Space・K | 再生と停止 | 編集・シアター |
| Enter | 次のクリップへ進む(シーケンス再生のとき。トリガーを待たない。ほかのモードでは進めないことを知らせる) | 編集・シアター |
| PageUp | 前のクリップへ戻る(シーケンス再生のとき) | 編集・シアター |
| PageDown | 次のクリップへ進む(シーケンス再生のとき。トリガーを待たない) | 編集・シアター |
| ← | 1コマ戻す | 編集・シアター |
| → | 1コマ進める | 編集・シアター |
| Shift+← | 5秒戻す | 編集・シアター |
| Shift+→ | 5秒進める | 編集・シアター |
| [ | 速度を1段下げる(0.25倍ごと) | 編集・シアター |
| ] | 速度を1段上げる(0.25倍ごと) | 編集・シアター |
| M | 音を消す・戻す | 編集・シアター |
| T | 編集ならシアターへ、シアターなら編集へ切り替える | 編集・シアター |
| Escape | 全画面なら全画面を抜け、シアターなら編集へ戻る | どの構えでも(ダイアログを開いている間は効かない) |
| F11 | 全画面にする・抜ける | いつでも(ダイアログを開いている間も) |
| Ctrl+S | ライブラリへ保存する(未登録なら名前を付けて登録するダイアログを開く) | 編集・シアター |
| F1 | このキーの一覧を開く・閉じる | どの構えでも(キーの一覧のダイアログを開いている間も効く) |
| Ctrl+Z | 編集を取り消す | 編集 |
| Ctrl+Y・Ctrl+Shift+Z | 編集をやり直す | 編集 |
| I | 選択中のクリップの開始を今の位置に | 編集 |
| O | 選択中のクリップの終了を今の位置に | 編集 |

表の効く構えの意味は次のとおりである。

- 「編集・シアター」と「編集」のキーは、ダイアログを開いている間は効かない。
- 「どの構えでも(ダイアログを開いている間は効かない)」のキーは、ダイアログを開いている間は効かない。ダイアログを開いている間に Escape キーを押すと、ダイアログが Escape キーを受け取って閉じる。
- 「どの構えでも(キーの一覧のダイアログを開いている間も効く)」の「このキーの一覧を開く・閉じる」のキーは、ライブラリのダイアログ(名前を付けるダイアログ・確かめるダイアログ)を開いている間は効かない。キーの一覧のダイアログを開いている間は、このキーは効き、ダイアログを閉じる。

キーの一覧のダイアログの表の上には「「変更」を押してから、割り当てるキーを押す(Ctrl・Alt・Shift と一緒に押してもよい)。Escape を押すと変更をやめる」と出る。表の下には「入力欄に文字を打っている間は、Ctrl か Alt を含むキーだけが効く(取り消し・やり直し・選択中のクリップの開始と終了を今の位置にするキーは入力欄に任せる)」と出る。利用者が名前の欄・数値の欄・パスの欄などに文字を打っている間、ClipViewer は Ctrl か Alt を含まないキーを、その欄への入力として扱う。取り消し・やり直し・開始と終了を今の位置にするキーは、Ctrl を含んでいても、その欄の中の文字の取り消し・やり直しなどとして扱う。ライブラリへ保存するキー(既定は Ctrl+S)を押すと、ClipViewer は打っている途中の名前を決めてから保存する。

### 12.2 キーを変える

利用者は、キーの一覧のダイアログで、操作ごとにキーを変えられる。

1. 利用者が、変えたい操作の行の「変更」を押す。その行の今のキーの所に「キーを押してください」が出て、「変更」は「やめる」に変わる。
2. 利用者が、割り当てたいキーを押す。押したキーが、その操作のキーになる。利用者が Ctrl・Alt・Shift を押しながらキーを押すと、ClipViewer は修飾キーと一緒の組(例: Ctrl+Shift+T)をキーにする。

- キーを変えると、その操作のキーは1つになる。例えば、利用者が「再生と停止」を K に変えると、Space キーでは再生と停止をしなくなる。
- 「キーを押してください」が出ている間は、ほかのキー操作は効かない。F1 キーと F11 キーも、割り当てるキーとして受け取る。
- 「キーを押してください」が出ている間に、利用者が Escape キーを押すか「やめる」を押すと、ClipViewer はキーを変えずに待つのをやめる。このとき、Escape キーはダイアログを閉じない。
- 利用者は、Escape キーを新しいキーとして割り当てられない。Ctrl・Alt・Shift と一緒に押した Escape キー(例: Shift+Escape)も割り当てられず、押すと Escape キーだけを押したときと同じく、ClipViewer はキーを変えずに待つのをやめる。Escape キーは、ClipViewer のどこでも「やめる・閉じる」に使うためである。「全画面なら全画面を抜け、シアターなら編集へ戻る」のキーを別のキーへ変えても、利用者が「既定に戻す」を押すと Escape キーに戻る。
- 押したキーをほかの操作が使っているときは、ClipViewer はキーを変えずに「<キー> は「<ほかの操作の働き>」のキーなので、「<変える操作の働き>」のキーを変えなかった」と知らせる。利用者は、先にほかの操作のキーを別のキーへ変えてから、もう一度変える。
- 利用者が行の「既定に戻す」を押すと、その操作のキーは既定のキー(12.1節の表)に戻る。既定のキーをほかの操作が使っているときは、ClipViewer は戻さずに同じ形で知らせる。今のキーが既定のキーと同じ行では、「既定に戻す」は押せない。
- 利用者が表の下の「すべて既定に戻す」を押すと、すべての操作のキーが既定のキーに戻る。すべての操作が既定のキーのときは、「すべて既定に戻す」は押せない。
- 再生の操作の行のボタンとつまみ、ヘッダーの「取り消す」「やり直す」、出力の帯の「シアターで見る」「全画面」にマウスを乗せたときに出るキーは、今のキーである。トリガー待ちの札の案内(5.9節)と、シーケンス再生でないときに次のクリップへ進むキーを押したときの知らせ(6.4節)も、今のキーで出る。例えば、利用者が「次のクリップへ進む(シーケンス再生のとき。トリガーを待たない。ほかのモードでは進めないことを知らせる)」を F2 に変えると、札は「F2キーを押すか、Nextボタンで進めてください」と出す。「再生と停止」のキーに Space キーが無いときは、Space待ちの札は「(Space は再生と停止に使う)」を出さない。
- ClipViewer は、変えたキーを次の起動に持ち越す(13節)。

どの操作も、いつも1つ以上のキーを持つ。ClipViewer にはキーを外すだけの操作が無いため、キーの一覧を開くキーも無くならない。キーの一覧を開くキーを忘れたときは、利用者は画面の上の「キー設定」を押してダイアログを開き、「すべて既定に戻す」を押す。ClipViewer を閉じてから、settings.json(14.1節)の `keyBindings` の項目を消してもよい。次に起動すると、ClipViewer はすべての操作を既定のキーで始める。

## 13. 次の起動に持ち越す設定

ClipViewer は、見る人の好みの設定を覚え、次に起動したときにその設定で始める。

| 持ち越す設定 | 覚える値 |
|---|---|
| ウインドウの大きさ | 最大化も全画面もしていないときのウインドウの大きさと、最大化しているか |
| 音量 | 音量のつまみの値。音を消していても、消す前のつまみの値を覚える |
| 速度 | 速度の倍率 |
| 左右反転 | 左右反転しているか |
| アスペクト比 | 出力アスペクト比の選択 |
| 表示サイズ | 表示サイズの選択 |
| キーの割り当て | キーの一覧のダイアログで変えたキー(12.2節)。既定のキーと違う操作だけを覚える |

ClipViewer は、次の設定を持ち越さない。ClipViewer は、起動するといつも次の値で始まる。

| 持ち越さない設定 | 起動したときの値 |
|---|---|
| 構え | 編集の構え |
| 再生モード | スタックシーケンス再生 |
| 全体ループ | 印が付いている |
| 消音 | 音を消していない |
| 全画面 | 全画面でない |

- ClipViewer は、持ち越す設定が変わってから1秒の間それ以上変わらなかったときと、アプリを閉じるときに保存する。
- ClipViewer は、起動したとき、覚えていた大きさでアプリのウインドウを作る。その後、画面の大きさが分かった最初の回に、ClipViewer は覚えていた大きさが画面に収まるか、幅800・高さ500以上かを確かめる。外れていれば、ClipViewer はウインドウを最初の大きさ(幅1200・高さ620)に変える。最大化していたときは、ClipViewer はウインドウを最大化のままにし、覚えておく大きさだけを最初の大きさに戻す。
- 読み取り専用の ClipViewer(8.9節)は、持ち越す設定を保存しない。読み取り専用の ClipViewer も、起動のときには設定を読んで、同じ設定で始める。
- 保存できなかったときは、ClipViewer は1回だけ「ウインドウの大きさ・音量などの見る側の設定を保存できない(同じ起動の間は、この知らせを繰り返さない): <理由>」と知らせる。

## 14. データの置き場所とアンインストール

### 14.1 データの置き場所

ClipViewer が保存するデータの置き場所は次のとおりである。`%APPDATA%` は、利用者ごとのアプリのデータのフォルダ(ふつうは `C:\Users\<利用者名>\AppData\Roaming`)を指す。`%LOCALAPPDATA%` は、このパソコンだけで使うアプリのデータのフォルダ(ふつうは `C:\Users\<利用者名>\AppData\Local`)を指す。利用者がエクスプローラーの場所の欄にこの書き方のまま打ち込むと、そのフォルダが開く。

| 置き場所 | 中身 |
|---|---|
| `%APPDATA%\ClipViewer\library\` | ライブラリ。スタック1つにつき1つの、ClipViewer が自動で付ける英数字の名前の .json ファイルと、錠のファイル(`ClipViewer.lock`)を置く。動画は写さない |
| `%APPDATA%\ClipViewer\settings.json` | アプリの設定。FFmpeg の場所と、13節の持ち越す設定 |
| `%APPDATA%\ClipViewer\launch.json` | 以前の版の ClipViewer が、ライブラリの錠を持つ ClipViewer へ動画を渡すための案内。現在の版は、この案内を読んで動画を渡さない |
| `%LOCALAPPDATA%\ClipViewer\thumbnails\` | サムネイルの控え。消しても、ClipViewer が必要なときに作り直す。合計が50MBを超えると、ClipViewer は古く使ったものから消す |
| `%LOCALAPPDATA%\ClipViewer\logs\` | 落ちたときの記録(`crash-<日時>.log`)と、警告の記録(`warnings.log`。起動のたびに前の回の分を `warnings.previous.log` へ移す)。warnings.log を書くのは、ライブラリの錠を持つ ClipViewer だけである |

**ライブラリのフォルダで ClipViewer が消すファイル。** ライブラリへ書ける ClipViewer は、一覧を作るたびに(起動したとき・ライブラリの構えへ移ったとき等。8.3節)、ライブラリのフォルダ(`%APPDATA%\ClipViewer\library\`)から次のファイルを消す。

- 名前が `.jpg` か `.jpg.tmp` で終わるファイル(小文字の jpg。以前の版の ClipViewer がサムネイルをここに置いていたため)
- 名前が `.json.tmp` で終わるファイルのうち、同じ名前の `.json` ファイルが無く、最後に書き換えてから1日より古いもの(保存の途中で残った書きかけのファイル)

そのため、利用者がライブラリのフォルダに画像などのファイルを置くと、ClipViewer が消すことがある。利用者は、ライブラリのフォルダに自分のファイルを置かない。

ClipViewer は、利用者の動画のファイルを書き換えず、消さず、写しも作らない。ClipViewer は、JSON保存で書き出したファイルを、利用者が選んだ場所に置く。

ClipViewer は、ライブラリのファイルと settings.json を、書きかけのまま残さない書き方で保存する。保存の途中でアプリや電源が落ちても、前に保存したファイルは壊れない。

### 14.2 アンインストール

利用者は、Windows の設定の「アプリ」→「インストールされているアプリ」(Windows 10 では「アプリと機能」)で ClipViewer を選び、「アンインストール」を押す。

- アンインストーラーは最後に、「ClipViewer の利用者のデータも削除しますか?」と問う。問いには、ライブラリとアプリの設定の置き場所(`%APPDATA%\ClipViewer`)と、サムネイルの控えと記録の置き場所(`%LOCALAPPDATA%\ClipViewer`)が書かれる。
- 利用者が「いいえ」(最初に選ばれている答え)を選ぶと、アンインストーラーはデータを残す。利用者が入れ直したときに、ライブラリも設定もそのまま使える。
- 利用者が「はい」を選ぶと、アンインストーラーは上の2つのフォルダを消す。アンインストーラーが消すのは、アンインストールを実行したアカウントのデータだけである。すべての利用者のために入れた場合も、アンインストーラーはほかの利用者のアカウントのデータを消さない。
- 動画のファイルとの関連付け(「プログラムから開く」への登録)は、答えに関わらず消える。
- 利用者の動画は、どちらの答えでも消えない。

## 15. 困ったとき

### 15.1 FFmpeg が見つからない

画面の上部に「FFmpeg が見つからないため動画を開けない。」が出ているときは、利用者は2.3節の「FFmpeg の場所を指定する」の手順で、`ffmpeg.exe` と `ffprobe.exe` のあるフォルダを入力して「保存して探し直す」を押す。winget で入れた直後に見つからないときは、利用者は Windows から一度サインアウトしてから ClipViewer を起動し直す。

### 15.2 動画を開けない

利用者は、4.5節の知らせの文を読む。ライブラリの一覧から開けないときは、利用者は動画を移したりファイル名を変えたりしていないかを確かめ、移したなら「動画の場所を指定し直す」(8.7節)を使う。

### 15.3 サムネイルが出ない

- サムネイルの枠に「FFmpeg が無い」と出るときは、利用者は FFmpeg を見つけられるようにする(15.1節)。
- 「動画が無い」と出るときは、動画がそのパスに無い。利用者は「動画の場所を指定し直す」を使う。
- 「撮れない」と出るときは、利用者は枠にマウスを乗せて理由を読む。
- サムネイルの控えは `%LOCALAPPDATA%\ClipViewer\thumbnails\` にある。利用者がこのフォルダを消しても、ClipViewer は必要なときに作り直す。

### 15.4 音が出ない

利用者は、再生コントロールの音の様子の行(6.9節)を読む。「音: 鳴らせない(…)」のときは、音を出す装置が使えないか、動画の音を開けない。ClipViewer は、起動のときに音を出す装置を開けないと、「<理由>。音を鳴らさずに映像だけで再生する」と知らせる。再生の途中で装置が使えなくなったときは、ClipViewer は「<理由>。映像だけで再生を続ける」と知らせる。利用者は、「消音」に印が付いていないか、音量のつまみが0でないかも確かめる。

### 15.5 ライブラリが読み取り専用になった

利用者は8.9節を読む。ほかに ClipViewer を起動していないのに読み取り専用になったときは、利用者は8.9節の最後の手順(タスクマネージャーで `clip_viewer.exe` が残っていないかを確かめる)を行ってから、ClipViewer を起動し直す。一覧の画面の理由が「ライブラリの錠を取れない: …」のときは、ライブラリのフォルダを読み書きできない。利用者は、理由の文に出るパスのフォルダを、エクスプローラーで開けるかと、そのフォルダにファイルを作れるかを確かめる。

### 15.6 ライブラリに「読めない」行が出る

一覧の「読めない: <ファイル名>」の行は、ライブラリのフォルダにある読めないスタックのファイルを示す。利用者は理由の文を読む。より新しい版の ClipViewer で保存したスタックなら、利用者が ClipViewer を新しい版に更新すると開ける。ClipViewer が一覧を読んでいる途中にスタックの保存が重なると、壊れていないファイルが一時的に読めない行として出ることがある。そのときは、利用者が「読み直す」を押すと、元の行に戻る。

### 15.7 アプリの設定を読めない

settings.json を読めないとき、ClipViewer は既定の設定で起動し、「アプリの設定を読めない: <理由>」と知らせる。

- settings.json が壊れているときは、理由の文に「アプリの設定 <パス> が壊れていて読めない。このファイルを消すか直せば、次の起動から読める。FFmpeg の置き場所を保存するときには、このファイルを別の名前へ移して書き直す: …」が出る。利用者が「保存して探し直す」で FFmpeg の場所を保存すると、ClipViewer は壊れたファイルを `settings.json.broken-<日時>-<番号>` へ移してから、新しい settings.json を書く。
- より新しい版の ClipViewer が書いた settings.json のときは、理由の文に「このアプリより新しい ClipViewer で保存された(version が …)。ClipViewer を更新すれば読める」が出る。ClipViewer はこのファイルを書き換えない。

### 15.8 ClipViewer が落ちた

ClipViewer が想定しない失敗で落ちると、ClipViewer は「ClipViewer で想定しない失敗が起きた。続けて使えない場合は起動し直す。」で始まる Windows のメッセージボックスを出す。メッセージボックスには、落ちたときの記録を書いたファイルの場所が出る。ClipViewer は記録を `%LOCALAPPDATA%\ClipViewer\logs\crash-<日時>.log` に書く。
不具合を知らせるときは、利用者は https://github.com/megaDenryu/ClipViewer/issues に、落ちたときの記録と `warnings.log` を添える。

### 15.9 日本語の文字が出ない

利用者は、2.1節の日本語のフォントの手順を行う。

### 15.10 ライブラリを使えない

環境変数 APPDATA が無い Windows では、ClipViewer はライブラリを使えない。そのとき、ヘッダーに「ライブラリ: 使えない(置き場所が無い)」が、ライブラリの構えに「ライブラリの置き場所が無い(環境変数 APPDATA が無い)ため、保存も一覧もできない」が出る。ClipViewer は起動し、利用者は動画の再生と JSON保存をできる。
